# 隔离环境实测

目标：验证明确的行为及当前代码，保护用户正在使用的服务，以最小环境和可核对证据得出结论。独立进程、不同端口不等于完整隔离；隔离环境也不等于容器或独立 Account。

本文件中的链接相对于 Skill 目录；命令在仓库根目录执行。先读 [AGENTS.md](../../../AGENTS.md)、目标功能文档及相关实现，记录工作区状态；不修改、暂存或清理无关工作。

## 1. 选择最小环境

先用几行说明：要证明的行为、通过条件、需要的组件、真实与模拟边界，以及会产生的写入。能由已有聚焦测试可靠证明时，不额外启动实机环境。

| 验证目标                        | 最小环境                           | 结论边界                                             |
| ------------------------------- | ---------------------------------- | ---------------------------------------------------- |
| UI 布局、交互、客户端状态       | 独立 Web、独立浏览器、fixture Host | 证明 UI 与受控协议行为，不证明真实 Harness           |
| Host 路由、状态、配置、插件加载 | 独立 Host、测试客户端及必要插件    | 证明实际加载与调用路径；标明原生后端是否模拟         |
| Harness 原生能力                | Adapter 公共接口或独立原生进程     | 区分原生协议探针、Adapter 验证与完整 Host 集成       |
| 跨层业务流程                    | 独立 Web、Host、必要的真实 Harness | 以实际入口操作并核对服务端事实；未经过的界面不算验收 |
| Desktop、系统集成、平台特性     | 对应平台与获准使用的真实工具       | 浏览器模拟尺寸不是手机实机，协议客户端不是 GUI       |
| 打包、安装与升级行为            | 独立发行产物及测试数据             | 源码进程运行成功不证明安装包可用；不操作用户安装     |

允许部分真实、部分模拟，但必须逐组件标注。不要为一个局部变化铺开所有 Harness、Model、浏览器和操作系统的矩阵。与 [推送前检查](../codexhost-pre-push-checks/SKILL.md) 配合选检查；新增 Harness 或 Desktop 更新兼容问题分别沿用对应专门 Skill。

## 2. 确定影响与授权

- 测试前只读记录已有服务的可执行入口、PID、数据目录和监听端点，建立不得停止或改写的保护清单。不打印完整环境变量、认证描述文件或带 token 的 URL。
- 用户请求测试不等于允许重启现有服务、改用户设置或操作真实业务数据。确需这些影响时，先说明范围、任务中断及恢复方式并取得明确授权。CLI 的确认参数不能代替授权。
- 真实模型、付费服务或其他外部写入必须在用户授权范围内；范围不清楚先询问。使用新测试 Thread、合成输入、有限调用数和明确超时，不拿用户会话或截图内容当测试任务执行。
- 凭据默认不复制。需要现有认证时只采用获准的原生认证方式，确认是否共享账号状态、原生 home 或其他外部资源；不得宣称这部分已隔离。必要的临时凭据副本应最小化、限制权限，并列入清理清单；不以符号链接整个用户 home 代替隔离。
- GUI、浏览器、网络或权限工具拒绝访问时停止该路径并报告 blocked；不换工具绕过安全限制，也不把 API 调用冒充 GUI 实测。

## 3. 准备并核对构建

- 从当前 [根 package.json](../../../package.json)、目标包脚本及测试配置选择命令，检查 `pretest` 等隐式步骤。只构建所需部分；跨包依赖可能读取 `dist`，运行源码入口不代表其依赖也是新源码。
- 记录 commit、相关未提交修改、构建入口及关键产物指纹；适用时记录 Launcher、Host、Web、插件、原生 CLI 的实际路径和版本，Harness 与 Model 分开记录。
- 构建也可能影响现有服务：源码 Web 可监听工作树前端产物。必要时使用受支持的独立输出或独立 checkout，并确保包含待测修改；不能只复制 HEAD 而漏掉工作区补丁。
- 不让构建清空或改写产物的过程与读取同一产物的浏览器测试并行。脚本自带前置构建时，不能假定启动前已经稳定。
- 修改代码后仅重启自己拥有的相关测试进程，重新核对加载的版本。只重建 Web 不会更新已运行的 Host 或已加载的 Adapter。

## 4. 启动并证明隔离

用系统临时目录生成唯一运行根目录，只创建需要的部分：

```text
<run-root>/
  host/           Host 状态与客户端通道描述
  web/            Web 认证、设置和缓存
  native-home/    原生 Harness 配置与历史（按其实际支持方式指定）
  workspace/      测试文件与命令执行目录
  evidence/       脱敏记录
```

- 构造受控子进程环境；不要原样继承当前 Agent 的 `CODEXHOST_*`、`NODE_OPTIONS`、`NODE_PATH` 或委派控制通道。必要配置逐项显式传入，保留实际需要的 PATH、系统及认证条件。按平台检查 HOME、USERPROFILE、LOCALAPPDATA 等路径；只设 Host data 不能隔离所有 Harness 的用户目录。
- 默认绑定回环地址，支持时用端口 `0`，读取实际监听端点。不要抢占固定端口或结束占用者。源码 `--no-auth` 只适用于获准的本机受控测试，不对外暴露；认证测试使用真实认证路径。
- Host、Web、原生会话、浏览器 profile、工作区分别隔离。插件启用与启动设置也使用测试范围；不替换已安装插件，不改原生 CLI 的全局配置。
- 启动后核对实际 PID／进程树、入口、数据目录、服务 hello／epoch 及连接目标。发现连到保护清单中的服务就停止测试操作，不通过重启它“纠正”连接。
- 在进程创建时就登记清理动作，覆盖启动失败、断言失败、超时和取消；不要只在成功路径清理。限时等待就绪，不只靠固定 sleep，也不把进程存活当作功能正常。

### 仓库入口与参考

按所选环境阅读，不必全部执行：

- **独立 Host**：参考 [原生共享 Host 测试](../../../packages/host-runtime/test/native/shared-host.test.ts) 和 [Launcher 生命周期实现](../../../crates/launcher/src/host_service.rs)。原生 `host ensure` 显式指定 Node、当前 Host Runtime、独立 `--data`、测试插件目录及适用的 `--codex-home` / `--stock-codex`。路径从实际构建和发现结果取得，不硬编码个人安装路径。
- **独立源码 Web**：参考 [入口参数](../../../packages/web-server/src/main.ts) 和 [测试服务器辅助代码](../../../packages/web-server/test/support/server.ts)。`--data` 指 Web 数据；`--ch-data` 指 Host 数据。`--ch-control-directory` 应指向同一测试 Host 的 `client-hosts`，并核对按需启动所用的 Launcher、Runtime、插件与 Codex home，防止重连回落到用户默认目录。
- **浏览器**：优先复用 [Web 浏览器测试](../../../packages/web-server/test/browser) 的实际控件与隔离方式；单独创建浏览器上下文，不连接或关闭用户日常浏览器。fixture 的默认假 Host 不能不加说明地用于真实链路验收。
- **Harness**：优先公共 Adapter 接口及所属插件既有 Gate。直接调用 CLI 可定位原生语义，但不能据此宣布 Host／UI 集成通过。无法隔离的原生单实例或全局状态应报告限制，不自行修改原生程序。
- **普通开发启动**：见 [Web 构建与生命周期](../../../docs/product/standalone-web.md#代码与构建)。`npm start` / `npm start web` 会重启对应界面并可能重启共享 Host，换 Web 端口不代表隔离 Host。隔离实测使用上述显式测试入口；`npm stop` 是跨工作树停机命令，不用于测试清理。

## 5. 执行与取证

- 先证明请求经过预期组件，再执行少量有区分力的场景。UI 问题从真实控件进入；服务端问题可直接通过其公开接口验证。原生返回值、Host 快照、界面表现各自只证明对应层。
- 检查结果而非只检查“调用发生”：实际状态、持久化、顺序、身份、错误、可见性或资源释放，按目标选取。读取或观测可有界轮询，结果未知的写请求不得自动重发。
- 只保存需要的脱敏证据：测试对象标识、操作、版本、断言结果、必要截图与选定协议字段。不要整包转储用户历史、认证头、环境变量或响应；日志及截图也要检查敏感信息。
- 失败先保留首轮结果，再区分产品缺陷、测试假设和环境问题。修正选择器、时序或依赖后说明原因；重跑通过不抹去先前失败。基线比较必须说明替换了哪些组件，不能把单模块替换称为完整旧版验收。
- 不因调用成本或工具限制改用模拟数据后仍称“实机通过”。修复后补最小且稳定的回归即可，不将整套临时调查脚本、日志和场景矩阵永久收入仓库。

## 6. 清理与报告

1. 停止测试发送与自动重连，关闭自己创建的浏览器／客户端，再关闭测试 Web、watcher 等前台进程。
2. 检查测试队列、活动 Turn 与后台命令。Turn 已结束不证明进程已退出；只清理属于本次测试的对象，遵循原生取消语义。
3. 使用指向独立数据目录的原生 `host stop` 等所有者关闭路径，等待监管者回收子进程。若需要信号升级，重新验证进程归属并限制范围；禁止 `pkill node`、按端口杀进程或全局 `npm stop`。
4. 删除自己创建的临时凭据及可安全删除的数据，按约定保留最小脱敏证据。用户要求保留运行环境时明确列出剩余资源、关闭方式及凭据处理，不默认删除用户文件或认证。
5. 核对保护清单中的服务未被本次操作停止或替换；若确曾获准改用户设置，恢复并验证。清理失败、无法确认后台任务退出或设置恢复，都作为结果报告，不能写“全部清理完成”。

最终报告先给结论，保持简短：

- **目标与环境**：验证什么、当前代码／产物、实际连接，以及哪些组件真实、哪些模拟。
- **结果**：pass / fail / blocked / 未执行分开列，给关键证据位置；只对实际覆盖的范围下结论。
- **遗留与清理**：残留进程／任务、凭据处理、设置恢复和原服务保护情况。
- **部署状态**：隔离环境通过不代表用户正在使用的服务已升级；提交、推送、部署和重启不是本 Skill 的默认动作。

Skill 只保存选择规则与运行约束。可复用逻辑优先使用仓库现有工具；确有重复需求时才把小型编排放到所属工具或包中，不在 Skill 内建立通用测试框架或复制一次性探针。
