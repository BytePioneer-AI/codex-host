# CodexHost Web UI

Private browser workspaces imported from the MIT-licensed `deepseek-harness` 0.2.1-alpha.1 Web UI and the local `codexhost-web` fork. The import keeps the selected client plugins, their browser runtime and protocol dependencies, and local CodexHost/mobile changes. It does not include the upstream CLI, release machinery, independent agent execution, or a second Git repository.

The source roster and scoped upstream revisions are in `import-manifest.json`. The terminal controller source and tests are pinned to official DSH commit `ce7073d51254c26cd63b22a60835b8f948deb447`; its protocol codecs come from `@deepseek-ai/dsh-api-terminal-controller@0.2.2-alpha.2`. `packages/` and `vendor/` are npm workspaces of the parent CodexHost repository; install dependencies once at that repository root. `npm run build:web:ui` compiles plugin factories with the imported CSS/module-loader preset and builds `apps/web` with Vite. `lib/` and `dist/` are generated and ignored. All Harness execution belongs to the parent repository's Adapters and Web Server, not these browser packages.

The `generated/remote.js` and matching declarations in selected packages are pinned DSH protocol codecs from the imported fork's generated Host descriptors. They are protocol source snapshots, not copies of Harness SDKs or bundled applications. Keep them aligned with the Web Server's DSH protocol compatibility layer; do not generate them from the Desktop Host. For the terminal package, `npm run import:protocol --workspace=@deepseek-ai/dsh-api-terminal-controller -- /path/to/unpacked/package` converts the official package's generated method index into the embedded Gateway's descriptor-array format, preserving its Zod codecs. Format the generated files with the repository's Prettier configuration after importing. This does not require importing newer, unrelated Remote introspection APIs. The full upstream frontend type-check and test programs are not imported yet; the current integration uses source compilation and the Web Server's browser regression tests.

The right Sidebar also embeds upstream host services: `packages/fs/fs`, `packages/fs/fs-local`, `packages/util/timeout`, `packages/sandbox/sandbox-policy`, `packages/core/scope`, `packages/subprocess/*`, `packages/util/http-proxy`, `packages/util/lazy-require`, and `packages/document/office-to-pdf` are the imported local-filesystem, sandbox-policy, subprocess/PTY, and Office-conversion sources. `packages/host/dsh-web-backend` is the CodexHost adapter that mounts the Typert registry, local filesystem, Connection, gateway, workspace files, Office conversion, subprocess, and terminal services for `packages/web-server`; it supplies server-resolved local Session directories, the sandbox policy's workspace root, and the four Agent fields the terminal controller reads. The imported client plugins are the file tree, document preview, terminal, and sandboxed browser tabs; `packages/test-support/remote-mock` supports their client tests. The Gateway forwards the upstream `RemoteUplinkWindow` through Remote invocation and exports its bounded uplink inbox for the Web mux. Its `packages/api/gateway/src/index.ts` imports the runtime `OperatorPeer` from `src/operator-peer.ts` rather than the Connection plugin root so the embedded backend does not pull the upstream browser-auth and credentials chain; `subprocess-local/src/runner-launch.ts` additionally honors `CODEXHOST_SUBPROCESS_RUNNER` so a packed distribution can run its bundled runner. Dependency patches for FortuneSheet, ExcelJS, node-pty, Lexical keyboard-viewport coordinates, and Markdown autolink boundaries are kept in the repository `patches/` directory and applied by `scripts/apply-dependency-patches.mjs` after install. `tests/dsh` holds the imported workspace file and terminal-controller tests; they run under Vitest with the same standard-decorator pre-transform the upstream repository uses.

Terminal input and resize use the upstream duplex `terminal/attach` stream, with per-attachment sequence numbers, provider acknowledgements, encoded-frame windowing and bounded client queues. The Web mux forwards `item` frames, treats Client `end` as an input half-close, and cancels input reads on logical or socket closure. The backend's `workingDirectory` port uses server-resolved directories for known local drafts and Threads, defaulting to the Web service user's home only when no directory is set. It validates the directory before spawning; an invalid configured path fails instead of falling back. It does not mount DSH's directory picker, mutate Session directories, assign a project, or create a Thread. File access retains its separate saved-directory rules. xterm owns desktop keyboard input. On mobile, `MobileTerminalComposer.tsx` owns a visible native textarea while xterm's keyboard textarea is read-only. Its rounded, auto-growing editor has an icon send action; the compact mode switch stays beside a single horizontally scrolling strip containing all control keys, including backspace and Ctrl+D, without a More menu. Delivery warnings remain visible in the composer. IME composition and edits stay local until explicit insertion, Enter or Tab. A two-option switch selects whether soft-keyboard Enter inserts text only or inserts text followed by terminal Enter (the default). The choice is retained per terminal across tab remounts, but not page reloads; switching never sends input and the send arrow always inserts text followed by Enter. Soft-keyboard submission uses native `beforeinput` line-break events with composition/closing-key guards; Shift+Enter inserts a local newline. Text goes through xterm's public paste API without an incremental text mirror. Enter and Tab wait for preceding text acceptance. The local `TerminalView.whenInputAcknowledged()` API observes existing duplex acknowledgements without changing the wire protocol; drafts clear only on acceptance, remain in memory across tab remounts, and survive failed or uncertain submissions without automatic replay. Multiline input without bracketed paste and manual retries after uncertain delivery require confirmation. Drafts are not persisted across page reloads. Client and Web backend must be updated together; old pages using `terminal/follow`, `terminal/write` or `terminal/resize` must be reloaded.

Right Sidebar touch controls follow the scoped revision in `sidebarTouchUpstream`: blocked split controls are hidden on coarse pointers without removing their footprint, the mobile opener stays hidden and disabled while expanded to keep the header stable, and sidebar chrome hover styles apply only to hover-capable devices. Device detection reuses the existing Bowser/iPad policy without changing automatic input focus behavior. This does not import the newer file navigator; terminal input compatibility is separate from sidebar layout.

`packages/client/hmr` contains the browser half of `@deepseek-ai/dsh-client-hmr` and a byte-for-byte import of the official Node half and focused tests, pinned to [`bf1a2bf69c76af82eb583aad596f7e3eceb81d31`](https://github.com/deepseek-ai/deepseek-harness/tree/bf1a2bf69c76af82eb583aad596f7e3eceb81d31/packages/client/hmr). `clientHmrUpstream` in `import-manifest.json` records every copied path, SHA-256, dependency and baseline comparison. The package-local `LICENSE` is the unmodified upstream repository MIT license. The copied TypeScript files retain upstream formatting and are excluded from Prettier to preserve byte-level provenance.

The official Node entry runs in `dsh-web-backend` alongside a stable Loader and ClientModules registry, including when no external plugin is enabled. Its private route-registration port forwards `/plugins/events` through the authenticated Web carrier without exposing reserved paths to user packages. The existing management queue applies only changed installations and awaits their Cordis disposal before deleting files. Source and packed client compositions include the browser transport; recovery pages omit it and therefore cannot receive external graphs. No Node code-replacement HMR, profile manager or Worker transport is mounted.

`packages/web-server/src/web-hmr.ts` owns only the development shell watcher and `/plugins/shell-events`. The browser retains its local `shell` frame support and subscribes to that separate channel only when the source carrier enables `__CODEXHOST_DEV_WEB_UI__`. All plugin graph/rebuilt delivery uses the unmodified official server. Per-file adaptation reasons are recorded in the manifest; existing ClientModules snapshot/carrier adaptations remain in place.

The three unchanged upstream test files live beside `src/` and run with `npx vitest run --config tests/vitest.config.js apps/web-ui/packages/client/hmr/tests`. Real Loader/storage integration is covered by `packages/web-server/test/dsh-web-hot-loading.test.ts`; authenticated carrier behavior by `dsh-web-plugin-http.test.ts`; browser synchronization, reconnect and recovery isolation by `test/browser/web-plugin-hot-loading.test.ts`. These fixture tests are not third-party package or packed-distribution acceptance.

The upstream MIT license is retained in `LICENSE`, framework package licenses remain under `vendor/`, and upstream dependency notices are retained in `THIRD_PARTY_NOTICES.md`. Local import adaptations include private npm manifests, source exports, the selected source build, and removal of the upstream standalone Web Worker preview entry. The root LGPL license does not replace these notices.

The Web interface extension installer adapts the upstream `ui-plugin-manager` install dialog structure and styles, using the imported `ui-primitives` Modal and Button. Package/address input and npm registry selection call the CodexHost Web extension API; the upstream plugin-manager store, Host runtime and bundle configuration are not mounted. The source revision is recorded under `extensionInstallUpstream` in `import-manifest.json`.

See [the Web feature document](../../docs/product/standalone-web.md) for runtime isolation, commands and supported behavior.

Workspace mention search adapts DSH `file-reference-local/src/search.ts` in
`packages/web-server/src/workspace-file-search.ts`; the Web gateway binds the existing
`fileReferences/list` contract to server-owned Thread/draft workspaces. This keeps
bounded recursive fuzzy search and path-only results without mounting DSH's Agent
runtime or its prompt injection. Web owns the bounded cache and periodic invalidation;
`tests/dsh/file-reference/search.spec.ts` retains the upstream search regressions.
