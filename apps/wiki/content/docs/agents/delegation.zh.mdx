用久了多个 AI 工具你会发现，每个 Agent 都有自己的看家本领：比如有的写大段业务代码最顺、有的查刁钻 Bug 快、有的搜最新社区动态准、有的审代码最严。

以前想让它们配合，只能你自己当“人肉传话筒”——从左边窗口复制报错，粘贴到右边窗口，等跑完再复制回来。在 CodexHost 里，**你可以直接让 Agent 之间自己分工和接力。**

---

## 玩法一：输入 `#`，把独立任务派给别的 Agent

在聊天输入框里敲一个 `#`，从弹出的菜单里选一个目标 Agent，直接把要干的活交代清楚：

```text
让 #claude-code 独立审查一下这次改动，看看有没有破坏兼容性的地方。

让 #pi 帮我查一下这个单元测试为什么偶发失败。

让 #omp 先把后端接口写出来，我在这边继续改前端页面。
```

你也可以在句子里顺口指定用什么模型或思考强度（不指定就默认用那个 Agent 自己的默认配置）。

### 派出去之后会发生什么？

1. **左边自动多出一个真会话**：目标 Agent 会在左侧会话列表里新建一个独立的真实对话，马上开始并行干活，不会打断你手头正在聊的会话。
2. **随时点进去看、随时插手**：它不是黑盒后台任务——你随时可以点开那个子会话，看它改了什么文件、调了什么命令，甚至直接在里面追问两句。
3. **干完自动回来报信**：等那边的子任务跑完，主会话会自动收到完成通知并拿到结果摘要，不用你一直盯着看。

## 玩法二：输入 `@`（或拖入会话），换个 Agent 接着干

这是很多人每天高频使用的救场功能——比如 **Claude Code 聊到一半额度用完了**，或者你刚用 **Grok 把技术方案调研清楚，现在想换 Pi 动手写代码**：

1. 新开一个你想用的 Agent 会话；
2. 在输入框敲 `@` 搜索刚才那个会话（或者更简单：**直接从左侧列表把刚才的会话鼠标拖进输入框**）；
3. 直接对它说：

```text
总结一下这个会话刚才做到哪了，理解它的背景，然后把剩下的部分接着做完。
```

当前 Agent 就能直接读取被引用会话的完整上下文，甚至直接给那个会话发消息继续指挥它，**一行内容都不用你自己复制粘贴**。

---

## 进阶：多 Agent 同时改代码怎么防冲突？

如果你打算让两三个 Agent **同时改同一个仓库的代码**，怕它们互相覆盖文件，可以通过命令行或 MCP 派活时加上 `--worktree <新分支名>` 参数——CodexHost 会自动为每个子任务拉出一个独立的 Git Worktree 目录，改完再合并，互不打架。

想从终端脚本、Claude Desktop 或自己的机器人里自动派活？请看 **[CLI / MCP / HTTP 接入总览](/zh/docs/platform/interfaces)**。
