CodexHost 坚持直接对接每个 Agent 官方自己的接口——**它原本有什么能力（比如调整思考深度、斜杠命令、压缩上下文）就原汁原味保留；原本没有的功能，绝不在界面上硬造一个假开关骗你。**

看不懂表头术语？先看这几个常用词的意思：

- **Edit Diff**：改完文件后能不能直接在右侧审查面板看代码对比；
- **工具审批 / 权限模式**：跑终端命令或改文件前，能不能弹窗让你点头同意，或者切换「只读 / 询问 / 自动执行」档位；
- **跨 Agent 协作**：能不能用 `#` 互相派活；
- **Fork**：能不能从对话中间某一条消息分叉出一个新的独立会话，换个思路重试。

> 图例：`✅` 完整支持 · `◐` 部分支持或有条件限制 · `—` 该工具暂不支持

## 各工具使用注意事项（避坑必看）

- **Pi**：为什么切到 Pi 时没有「权限模式」下拉框？因为 Pi 官方核心本来就没有“只读 / 询问 / 全自动”这种档位设计，CodexHost 不会造一个假开关糊弄你。它支持 Pi 自己的扩展确认，而且在用 Codex 模型时输入框会出现 **Fast 闪电加速开关**。
- **Cursor CLI**：你在 Cursor 会话里可以把任务派给别的 Agent；但反过来**不能在其他会话里用 `#cursor` 让它在后台自动接活**（因为团队安全策略可能会悄悄拦住自动执行权限，没法保证它在后台无人值守跑完）。另外，Fork 分叉和修改上一条消息目前支持 macOS 与 Linux，Windows 暂不支持。
- **Antigravity (AGY)**：需要本机安装的 `agy` 版本达到 `1.5.8` 及以上；支持 `default`（默认询问）、`accept-edits`（自动允许改文件）、`auto`、`plan` 等权限模式、工具审批及提问卡片；需要等当前回复停下（空闲状态）才能点 Fork 分叉对话。
- **Kimi Code**：切换不同模型时，可选的思考深度（Thinking）会自动跟着当前模型动态变化；支持退出计划时的确认卡片，也支持接收 `#` 派活。
- **Hermes**：统一通过官方 Gateway 连接；只要那段聊天记录还没有执行过“上下文压缩”，就可以正常 Fork 分叉或修改上一条消息。
- **WorkBuddy 与 ZCode**：这两个工具需要先在电脑上装好对应的桌面端应用（**WorkBuddy Desktop** / **ZCode Desktop**）并在里面登录好账号，CodexHost 会直接调用它们内置的 CLI，不需要重复配密钥。
