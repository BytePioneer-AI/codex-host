## Why No Token Setup Is Needed

Whenever CodexHost is running on your machine (via Codex Desktop or `codexhost web`), the background Host automatically writes short-lived credentials with private `0600` permissions to `~/.codexhost/cli-credentials.json`.

Any terminal window or local script running under your OS user can run `codexhost` commands right away—**no client registration or environment variables required**.

> Make sure Codex Desktop or `codexhost web` is already running first; the CLI won't auto-launch the Host for you.

## 4 Everyday Command Recipes

### 1. See Available Agents & Local Projects

```bash
codexhost harness list --format text
codexhost project list --format text
```

> **Choosing `--format`**:
>
> - `text`: Clean, human- and LLM-friendly output without JSON escaping;
> - `compact`: Concise JSON with task links—great for shell scripts;
> - `json` (default): Full structured JSON payload.

### 2. Delegate a Task (into an Isolated Git Worktree)

For example, ask Claude Code to audit a module inside a brand-new Git worktree so it never touches your current working tree:

```bash
codexhost delegate start \
  --harness claude-code \
  --task-name "Audit auth boundaries" \
  --worktree review/auth \
  --watch true \
  --format text \
  --task "Review permission boundaries in packages/host-runtime and suggest concrete fixes."
```

Useful flags:

- `--worktree review/auth`: Creates branch `review/auth` under `.worktrees/` and runs the Agent there;
- `--watch true`: Registers a completion notification for the parent session or event log;
- `--task-file -`: Pipe or heredoc (`<<'EOF'`) multi-line prompts cleanly over stdin.

The command returns the new `<thread-id>` immediately, and the session pops right into your Desktop / Web sidebar.

### 3. Wait for Completion & Read Replies

```bash
# Wait until the turn finishes (defaults to 30s; if still running, returns a live checkpoint without stopping it)
codexhost thread wait <thread-id> --format text

# Read clean per-turn user prompts and final Agent replies
codexhost thread read <thread-id> --view messages --format text
```

For long conversations, `--view messages` supports `--from <n> --to <m>` turn pagination.

### 4. Follow Up, Steer Mid-Run, or Interrupt

```bash
# 1. Send a normal follow-up once the session is idle
codexhost thread send <thread-id> --message "Please add unit tests for those cases too"

# 2. Nudge a running session mid-turn without starting over
codexhost thread send <thread-id> --steer true --message "Focus only on host-runtime for now"

# 3. Wrong direction? Cancel the active turn, wait for it to stop, then send new instructions
codexhost thread send <thread-id> --interrupt --message "Stop that—let's trace the startup flow instead"

# 4. Just stop the current turn (keeps the session and history intact)
codexhost thread cancel <thread-id>
```
