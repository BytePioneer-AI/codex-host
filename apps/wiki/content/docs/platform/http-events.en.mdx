title: HTTP API & Completion Events
description: Building a Slack / Discord / Telegram bot or custom orchestrator? Call localhost port 4398 over HTTP and stream durable completion events.
---

Building an always-on **Slack, Telegram, Discord, or Feishu bot**, a webhook listener, or a custom backend service? You can talk directly to CodexHost over localhost HTTP without shelling out to the CLI.

Whenever Codex Desktop or `codexhost web` is running, CodexHost listens on **`http://127.0.0.1:4398`** by default.

---

## Step 1: Issue a Token for Your Bot

Register a dedicated client identity (lowercase letters, digits, and `-`):

```bash
codexhost client add my-bot
```

Copy the `chc_...` token printed to your terminal (shown once; revoke anytime with `codexhost client remove my-bot`). Include it on every HTTP request:

```http
Authorization: Bearer chc_your_token_here
Content-Type: application/json
```

---

## Step 2: Start Tasks, Steer & Read Replies

All action endpoints accept `POST` requests with a JSON body:

| Endpoint                  | What It Does                            | Common Fields                                                                              |
| :------------------------ | :-------------------------------------- | :----------------------------------------------------------------------------------------- |
| `POST /v1/harness/list`   | List ready Agents                       | `{}`                                                                                       |
| `POST /v1/project/list`   | Search discovered local Git repos       | Optional `query`, `limit`, `offset`                                                        |
| `POST /v1/delegate/start` | Spawn a new session and submit a task   | `harness`, `task`, `cwd` (absolute path), optional `taskName`, `worktree`, `base`, `watch` |
| `POST /v1/thread/send`    | Follow up, steer mid-turn, or interrupt | `threadId`, `message`, optional `steer`, `interrupt`, `watch`                              |
| `POST /v1/thread/read`    | Read the latest result or turn history  | `threadId`, optional `view` (`"result"` or `"messages"`), `from`, `to`                     |
| `POST /v1/thread/wait`    | Wait up to `timeoutMs` for completion   | `threadId`, optional `timeoutMs`, `view`                                                   |
| `POST /v1/thread/cancel`  | Cancel the active turn                  | `threadId`                                                                                 |
| `POST /v1/thread/watches` | List pending completion watches         | `{}`                                                                                       |

### Example: Start a Task in a Fresh Worktree with a Watch

```bash
curl -X POST http://127.0.0.1:4398/v1/delegate/start \
  -H "Authorization: Bearer chc_your_token_here" \
  -H "Content-Type: application/json" \
  -d '{
    "harness": "pi",
    "cwd": "/Users/me/projects/my-app",
    "taskName": "Investigate login timeout",
    "worktree": "fix/login-timeout",
    "watch": true,
    "task": "Track down why the login endpoint occasionally times out and summarize the root cause."
  }'
```

> Two quick gotchas to avoid:
>
> 1. External HTTP callers don't have an implicit working directory—always pass an **explicit absolute path for `cwd`** on `/v1/delegate/start` (especially with `worktree`).
> 2. On `/v1/thread/send`, `steer: true` and `interrupt: true` are mutually exclusive—don't set both at once.

## Step 3: Get Notified When Tasks Finish (Without Tight Polling)

Coding tasks can take minutes—you don't need to hammer `/v1/thread/read` in a loop.

Whenever you pass `"watch": true` on `start` or `send`, CodexHost appends a completion notice to your client's **7-day persistent event log** the moment that session stops (completed, failed, or interrupted)—so even if your bot restarts mid-run, it can catch right back up:

Pick whichever consumption pattern fits your stack:

1. **Server-Sent Events (Recommended for bots)**:
   Open `GET http://127.0.0.1:4398/v1/events`. On reconnect, pass header `Last-Event-ID: <cursor>` (or `?after=<cursor>`) to replay anything missed while offline.
2. **HTTP Long-Polling**:
   Call `POST http://127.0.0.1:4398/v1/events/poll` with `{"after": "<cursor>"}` (waits up to 60 seconds when idle).
3. **CLI Event Reader**:
   ```bash
   CODEXHOST_CLIENT_TOKEN=chc_your_token_here codexhost events --after <cursor>
   CODEXHOST_CLIENT_TOKEN=chc_your_token_here codexhost events --follow true
   ```

> Events intentionally carry lightweight metadata (`threadId`, outcome, turn info, deep link) rather than full message text—once an event arrives, call `POST /v1/thread/read` to fetch the Agent's final reply.
