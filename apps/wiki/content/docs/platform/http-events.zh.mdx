title: HTTP 接口与完成事件推送
description: 写飞书 / Slack / Telegram 机器人或自研工作流？直接调本机 4398 端口的 HTTP 接口派活，并通过事件流收完成通知。
---

如果你在自己写 **飞书 / Telegram / Slack 聊天机器人、Webhook 服务或者自定义后端工作流**，不想在代码里拼命令行参数，可以直接通过本机 HTTP 接口跟 CodexHost 通信。

只要桌面端或 `codexhost web` 正在运行，CodexHost 默认会在本机 **`http://127.0.0.1:4398`** 开启外部监听。

---

## 第 1 步：给你的机器人领一把令牌

在终端为你的程序登记一个名字（只能用小写字母、数字和 `-`）：

```bash
codexhost client add my-bot
```

复制输出的 `chc_...` 令牌（只显示一次；随时可用 `codexhost client remove my-bot` 吊销）。之后每次发 HTTP 请求，都在请求头里带上：

```http
Authorization: Bearer chc_你的令牌
Content-Type: application/json
```

---

## 第 2 步：发请求派活、追问、读结果

所有业务接口都是 **`POST`** 请求，传 JSON 对象即可：

| 接口路径                  | 干什么用的                 | 常用请求字段                                                                                         |
| :------------------------ | :------------------------- | :--------------------------------------------------------------------------------------------------- |
| `POST /v1/harness/list`   | 查看当前可用的 Agent 列表  | `{}`                                                                                                 |
| `POST /v1/project/list`   | 搜索本机已配置的 Git 仓库  | 可选 `query`、`limit`、`offset`                                                                      |
| `POST /v1/delegate/start` | 新建会话并派发任务         | `harnessId`（或 `harness`）、`task`、`cwd`（绝对路径），可选 `taskName`、`worktree`、`base`、`watch` |
| `POST /v1/thread/send`    | 继续发消息、插话或打断重发 | `threadId`、`message`，可选 `steer`、`interrupt`、`watch`                                            |
| `POST /v1/thread/read`    | 立刻读取最新结果或多轮对话 | `threadId`，可选 `view`（`"result"` 或 `"messages"`，默认 `"result"`）、`from`、`to`                 |
| `POST /v1/thread/wait`    | 等待本轮跑完再返回结果     | `threadId`，可选 `timeoutMs`（默认 30000）、`view`                                                   |
| `POST /v1/thread/cancel`  | 停掉当前正在跑的这一轮     | `threadId`                                                                                           |
| `POST /v1/thread/watches` | 查看还在等待完成的监听列表 | `{}`                                                                                                 |

### 调用示例：派活并开启完成通知

```bash
curl -X POST http://127.0.0.1:4398/v1/delegate/start \
  -H "Authorization: Bearer chc_你的令牌" \
  -H "Content-Type: application/json" \
  -d '{
    "harnessId": "pi",
    "cwd": "/Users/me/projects/my-app",
    "taskName": "排查登录超时",
    "worktree": "fix/login-timeout",
    "watch": true,
    "task": "排查登录接口偶发超时原因，先给出根因分析。"
  }'
```

> 两个防踩坑提醒：
>
> 1. 外部客户端没有“当前所在目录”，所以调 `/v1/delegate/start`（尤其是开启 `worktree`）时，**`cwd` 必须传完整的绝对路径**。
> 2. 调 `/v1/thread/send` 时，`steer: true`（顺着插话）和 `interrupt: true`（停掉重来）互斥，不能同时传 `true`。

---

## 第 3 步：任务跑完了怎么通知我的机器人？

Agent 改代码往往要跑几分钟，你不需要傻傻写死循环去高频轮询 `/v1/thread/read`。

只要你在 `start` 或 `send` 时传了 `"watch": true`，一旦那个会话停下来（完成、报错或被中断），CodexHost 就会往你这个客户端专属的**本地事件本**里写入一条通知（默认保留 7 天，哪怕你的机器人中途崩溃重启了也不会丢）：

你可以任选最顺手的一种方式收通知：

1. **SSE 实时推送（最推荐常驻 Bot 使用）**：
   保持长连接请求 `GET http://127.0.0.1:4398/v1/events`（断线重连时带上请求头 `Last-Event-ID: <上次收到的事件ID>` 或查询参数 `?after=<事件ID>`，会自动补发断线期间漏掉的通知）。
2. **HTTP 长轮询**：
   请求 `POST http://127.0.0.1:4398/v1/events/poll`，传入 `{"after": "<上次游标>"}`（没有新事件时最多挂起等待 60 秒）。
3. **命令行直接拉取或跟随**：
   ```bash
   CODEXHOST_CLIENT_TOKEN=chc_你的令牌 codexhost events --after <上次游标>
   CODEXHOST_CLIENT_TOKEN=chc_你的令牌 codexhost events --follow true
   ```

> 注意：事件通知只告诉你“哪个 `threadId` 停下来了、最终状态是成功还是失败”，不包含大段聊天正文——收到通知后，再调一次 `POST /v1/thread/read` 就能拿到完整的回复内容。
