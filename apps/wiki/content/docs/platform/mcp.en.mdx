title: MCP Integration (Claude Desktop, Cursor & More)
description: Connect CodexHost as a local MCP server so Claude Desktop, Claude Code, or Cursor can delegate tasks to any Agent on your machine.
---

With **MCP (Model Context Protocol)**, apps like **Claude Desktop, Claude Code, or Cursor** can call right into CodexHost—letting you sit inside Claude Desktop and ask **Pi, Grok, or OpenCode** to run tests, research an issue, or edit a branch in parallel.

---

## Step 1: Create a Named Client Token

Unlike same-user terminal commands, MCP connections require an explicit client token (names may use lowercase letters, digits, and hyphens):

```bash
codexhost client add claude-desktop
```

This prints a `chc_...` token **once**—copy it right away.

> Manage tokens anytime with `codexhost client list` and `codexhost client remove <name>`.

---

## Step 2: Add CodexHost to Your MCP Client

Whenever Codex Desktop or `codexhost web` is running, CodexHost serves Streamable HTTP MCP at `http://127.0.0.1:4398/mcp`. Replace `<your-token>` below with your `chc_...` token:

### Claude Code (One Command)

```bash
claude mcp add --transport http codexhost http://127.0.0.1:4398/mcp \
  --header "Authorization: Bearer <your-token>"
```

### Claude Desktop

Don't add `127.0.0.1` under Claude's cloud Custom Connectors (Anthropic's servers can't reach your localhost). Instead, add it to your local `claude_desktop_config.json` via `mcp-remote`:

```json
{
  "mcpServers": {
    "codexhost": {
      "command": "npx",
      "args": [
        "-y",
        "mcp-remote",
        "http://127.0.0.1:4398/mcp",
        "--header",
        "Authorization:${CODEXHOST_AUTH}"
      ],
      "env": {
        "CODEXHOST_AUTH": "Bearer <your-token>"
      }
    }
  }
}
```

Save the file and restart Claude Desktop.

### Cursor & Other Streamable HTTP MCP Clients

Point the client at `http://127.0.0.1:4398/mcp` with header `Authorization: Bearer <your-token>`.

## Tools Exposed Over MCP

Once connected, your MCP host gets the full CodexHost orchestration toolkit:

- **Discover what's on this machine**: `host_info`, `project_list`, `harness_list`, and `harness_inspect`;
- **Spawn delegated tasks**: `delegate_start` (supports `worktree`, `base`, `watch`, and `watchTimeoutMs`);
- **Follow up, steer, or cancel**: `thread_send` (with `steer`, `interrupt`, and `watch`) and `thread_cancel`;
- **Read results & workspace artifacts**: `thread_wait`, `thread_read` (`result` or paginated `messages`), `thread_file_read`, and `thread_watches`.
