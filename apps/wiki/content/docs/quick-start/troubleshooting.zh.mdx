## 遇到问题先开「本地控制台」

如果遇到 **Codex Desktop 打不开**，或者 **打开了但界面还是原版、看不到其他 Agent**，最直接的办法是在终端运行：

```bash
codexhost console
```

> Windows 用户也可以直接在「开始菜单」里找到 **`codexhost console`** 点击打开；如果桌面端能进设置，也可以在「codexhost 设置 → 关于」里点「打开控制台」。

它会在浏览器打开 `http://127.0.0.1:4399/`（仅你本机可访问，无需登录）。**哪怕 Codex Desktop 彻底启动失败，这个控制台也能独立打开**，帮你做四件事：

1. **看清到底卡在哪一步**：在「总览」页直接显示当前的 CodexHost 版本、Codex Desktop 版本，以及最近一次启动失败或功能未加载的具体原因和报错原文。
2. **一键导出诊断包**：提 Issue 或加群求助时，点一下「导出诊断包（含日志）」，就能打包好运行日志（会自动把你的个人主目录路径脱敏成 `~`）。
3. **检测和安装 Agent**：在「设置 → 连接」里查看哪些 Agent 已经就绪、哪些还没装命令行工具，支持直接在页面上一键安装或升级。
4. **管理更新与远程连接**：在 Codex 没打开的时候直接更新 CodexHost、配置手机远程访问或管理 SSH 连接。

> 小提示：`4399` 端口是**体检和设置控制台**，不是用来聊天的；想在浏览器里跟 Agent 聊天，请用 `codexhost web`（默认 `4400` 端口）。

## 常见问题速查

### 1. macOS 第一次打开提示「无法验证开发者」或「应用已损坏」

这是因为系统拦截了未经过 Apple 公证的应用包。在终端执行下面这行命令去掉隔离标记，再重新打开即可：

```bash
xattr -dr com.apple.quarantine /Applications/codexhost.app
```

### 2. 打开了界面，但输入框右下角看不到我想用的某个 Agent

先打开「codexhost 设置 → 连接」（或运行 `codexhost console` 看连接页）：

- CodexHost 本身不包含第三方 Agent 的本体程序；你需要先在本机装好对应的工具（例如 `claude`、`pi`、`agy` 等）并完成登录。
- 连接页会直接告诉你哪个工具没找到、怎么安装，或者当前卡在什么配置上。

### 3. Windows 用的是绿色免安装（解压版）Codex Desktop，提示找不到程序

如果 Codex Desktop 是你自己解压到某个文件夹的，需要告诉 CodexHost 它放在哪：

1. 打开 PowerShell，把下面的路径换成你实际的解压目录：
   ```powershell
   [Environment]::SetEnvironmentVariable("CODEXHOST_INSTALL_ROOT", "D:\CodexPortable", "User")
   ```
2. **彻底退出**正在运行的 Codex Desktop，关掉当前终端重新打开一个新终端窗口，再运行 `codexhost`。

### 4. 想看看后台服务现在到底有没有在跑

```bash
codexhost status
```

这条命令只做检查，不会启动或重启任何服务，会清楚列出后台 Host、Web 的运行状态、版本号和开机自启状态。

### 5. 卸载前怎么清理干净？

- **Windows 安装包**：直接运行系统卸载程序即可，它会自动帮你停掉后台服务并关闭开机自启。
- **macOS 或 npm 安装**：在把应用拖进废纸篓或运行 `npm uninstall -g @codexhost/cli` 之前，请先执行下面两条命令停掉后台进程和登录自启：
  ```bash
  codexhost stop
  codexhost autostart off
  ```

## 本地数据存在哪里？

CodexHost 的本地会话映射、日志和配置默认都存在你个人目录下的 `~/.codexhost` 中，不会上传你的代码或对话内容。详细的本地存储说明、凭据隔离规则与数据清理方式，可查阅仓库中的 [隐私与数据说明（PRIVACY.md）](https://github.com/BytePioneer-AI/codex-host/blob/main/docs/PRIVACY.md)。
