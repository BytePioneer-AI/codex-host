# 多 Agent 委派

CodexHost 支持在对话中直接跨 Agent 分配任务和传递上下文。原生子 Agent 只能调用同一个工具自己的模型，而 CodexHost 的委派可以跨不同 Agent 和账号运行。

```text
Claude Code ──▶ #pi (排查单测失败)
Codex       ──▶ #claude-code (独立审查 Diff)
Grok        ──▶ @引用会话 ──▶ Pi (接力编写实现代码)
```

## 用 `#` 委派并行子任务

在输入框中输入 `#`，选择目标 Agent，直接描述要执行的子任务：

```text
让 #claude-code 独立审查这次改动，检查是否有破坏向后兼容性的地方。

让 #pi 排查这个单元测试为什么偶发失败。

让 #omp 先实现后端接口，我在这边继续改前端表单。
```

默认使用目标 Agent 的默认模型，也可以在提示词里直接指定模型或思考深度。

### 子会话如何运行

- **独立真实会话**：每个委派任务都会在目标 Agent 下新建一个真实会话，出现在左侧会话列表中（Web 端会自动折叠在父会话下方），并行运行且不阻塞当前对话。
- **随时查看或介入**：点击左侧的子会话即可实时查看工具调用、审查 Diff，或直接在子会话里追加指令。
- **完成后自动回报**：子会话跑完当前轮次后，主会话会自动收到完成通知并读取结果。

## 用 `@` 引用会话接力

当某个 Agent 聊到一半额度用完，或者先用 Grok 做完调研、想换 Pi 或 Claude Code 写代码时，可以用 `@` 让新会话直接读取旧会话：

1. 新开一个目标 Agent 的会话。
2. 在输入框输入 `@` 搜索刚才的会话（或者直接**从左侧列表把那个会话拖进输入框**）。
3. 发送指令：

```text
先看下这个会话做到了哪一步，接着把剩下的部分写完。
```

新 Agent 会按需读取被引用会话的历史记录，甚至直接向那个会话发消息，不需要手动复制粘贴上下文。

## 用 Worktree 隔离并行改动

如果多个 Agent 需要同时修改同一个 Git 仓库，通过 CLI 或 MCP 发起委派时可以加上 `--worktree <分支名>`。CodexHost 会在 `.worktrees/` 下为每个子任务创建独立的分支与工作目录，互不覆盖文件。

详见 [CLI 参考](/docs/platform/cli) 与 [MCP 服务](/docs/platform/mcp)。
