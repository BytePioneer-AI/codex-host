# 外部 Thread 的本地图片显示

外部 Harness 的消息由 codexhost 投影成 Codex Desktop 原生条目后显示。本地图片能否显示，取决于投影出的条目是否满足 Desktop 的加载规则。本文记录当前做法和边界，依据 Codex Desktop 26.1021.3705.0 的渲染代码核对；Desktop 更新后需重新核实。

## Desktop 的加载规则

Agent 消息中的 Markdown 图片（`![alt](目标)`）只有在目标是绝对路径（`/…`、`C:\…`、`C:/…`、UNC）或 `file:` URL 时，才会被当作本地文件，经 app-server 读取后显示。其他目标按 Desktop 页面自身地址解析，加载失败后显示“Image unavailable”占位框。只有预览 `.md` 文件时，Desktop 才会按该文件所在目录补全相对路径；对话消息没有这个基准目录。

Harness 常按工作目录写相对路径，因此需要由 Adapter 改写。

用户消息气泡中的缩略图只来自消息 `content` 里的 `image` / `localImage` 条目。Desktop 同时把附件清单（`# Files mentioned by the user:`）解析成文件标签；只有消息带图片条目时，才把对应图片从标签中移除。消息没有图片条目时，所贴图片只显示为文件名标签。

## Agent 消息：改写本地媒体路径

`@codexhost/harness-adapter/local-media-markdown` 提供共用的改写：

- 改写图片目标中的本地媒体路径，以及只包含一个媒体路径的行内代码（转成图片）。相对路径按 Adapter 给出的根目录依次查找，只有找到实际存在的文件才改写。
- 远程 URL、`data:` 等地址、找不到的文件、无法解析的写法和围栏代码块中的内容保持原样，不改动一个字节。围栏按 CommonMark 识别：开头是行首（最多缩进三个空格）三个或更多的 `` ` `` 或 `~`；结尾行用同一种字符，长度不短于开头，后面只能有空白（CRLF 换行留下的 `\r` 也算行尾）。行中间出现的 ```` ``` ```` 不算围栏。
- Windows 盘符路径写成正斜杠（`C:/…`）。CommonMark 会把反斜杠加标点当作转义，原样输出会让 `C:\Users\me\.codex\…` 丢掉分隔符。
- 目标是本地媒体文件的普通链接（`[文字](images/1.jpg)`，没有 `!`）同样转成图片，链接文字作为图片说明；Desktop 对这种链接只显示文件标签，不显示图片。指向网页、其他文件或找不到的文件的链接保持原样；链接文字里嵌有方括号（如套着图片的徽章链接）时也不改。
- 行内代码或链接转成的图片单独成段，与 Agent 自己写 Markdown 图片时的排版一致：前后各空一行，紧跟其后的句末标点（`。.!！?？;；,，`）移到图片之前，并替换引出图片的冒号，例如 `` …鱼：`images/1.jpg`。 `` 显示为“…鱼。”，下一段是图片。同一行没有文字时，标点留在图片后面。表格行和标题行无法放入独立段落，其中的图片保持行内。实时输出会多等一个字符，用来判断其后是否有标点，结尾的冒号和空格同样暂缓发出。
- 路径中含有 `%` 时另行处理。Desktop 读取文件前会对目标做两次 `decodeURI`，任何一次性的转义都无法保住字面 `%`；Grok 的会话目录名是用 `encodeURIComponent` 编码的工作目录，总会包含 `%`。改写时为这类文件在 `<数据目录>/media-links/<路径哈希>/` 下建一个不含 `%` 的硬链接（失败则复制），消息中链接这个别名；硬链接和复制都失败时，把 `%` 转义成 `%2525`，正好经受两次解码。不含 `%` 的路径不受影响，也不创建别名。别名目录可以随时删除，下次改写时重新生成。
- 支持的扩展名：图片 `png`、`jpg`、`jpeg`、`gif`、`webp`、`svg`，音视频 `mp4`、`m4v`、`mov`、`webm`、`mp3`、`m4a`、`aac`、`ogg`、`wav`。

实时输出只能追加，Host 要求条目完成时的全文等于此前所有增量之和。`LocalMediaMarkdownStream` 因此只暂缓结尾仍可能被后续文本改变的写法（未闭合的图片、未闭合的行内代码），写错的图片或单个反引号不会扣住后面的文字；Item 结束前再补发暂缓部分。同一条消息内，每个路径只检查一次文件，保证前后改写一致。

接入的 Harness：

| Harness | 根目录 | 范围 |
| --- | --- | --- |
| Grok | 工作目录、Grok 会话目录及其 `videos/`、`images/`、用户 `Downloads/` | 实时输出与历史 |
| DeepSeek Harness | 消息产生时 Agent 的工作目录（按事件顺序随 `working-directory/change` 更新，恢复未完成的 Turn 时也一样），再到 Session 工作目录 | 实时输出与历史（`readSnapshot`）；用量刷新不做改写 |

其他 Harness 的 Agent 文本仍原样转发；它们输出相对路径时，图片仍显示为占位框。

## 用户消息：还原图片附件

Desktop 发送带图片的消息时，请求里既有 `localImage` 条目，也在文字的附件清单中写下每张图片的绝对路径，并标注 `Image attachment: true`。公共 Harness 输入只有文字，Host 转发时只保留文字，Harness 按路径读取图片；Native Session 历史同样只有文字。

`protocol-core` 投影用户消息时，从文字中 `## My request:` 之前的附件清单读出这些路径，补回 `localImage` 条目，放在文字之后。开始 Turn、运行中插入和历史回放三处投影一致，因此新旧会话都显示缩略图，`imageCount` 也与 Desktop 的乐观消息一致。解析规则在 `@codexhost/shared-contracts` 的 `desktopImageAttachmentPaths`，Renderer 的远程附件补存使用同一规则。

边界：

- 只认附件清单中的绝对路径；用户在请求正文里写的路径不算附件。附件清单必须位于消息开头（前面只允许空行），并以单独成行的 `## My request:` 结束；缺少结尾标题或前面还有其他文字时，视为用户自己输入或粘贴的文字，不读取附件。
- 不读取、不复制图片。剪贴板截图通常保存在系统临时目录，文件被清理后缩略图无法加载。
- 远程外部会话的图片路径位于远程主机，其缩略图显示尚未单独验证。
