# Pi 可见进度与流式内容

Pi Adapter 将原生公开的进度映射到 Codex 的 `agentMessage`，并设置
`phase: "commentary"`。这些消息标明 Pi 来源，不作为模型的最终回答。助手正文保留原生文本签名中的 phase；旧事件根据原生完成原因区分工具前进度与最终答复，通知跟在正文之后也不会覆盖答复语义。

## 通知与状态

- `display: true` 的原生 custom 消息在活动回合内即时展示；历史恢复也保留这些通知。
- `display: false` 的消息保持隐藏。通知身份取自当前原生分支中的类型、完整内容及同文出现序号，避免恢复时重复显示，也不合并两次真实发生的同文通知。
- 原生重试开始和结束、扩展 `notify` 与非空 `setStatus` 转为可读进度。只展示原生报告的尝试次数、等待时间和结果，不从经过时间推测工作进展。
- 原生状态事件本身不持久化在 Pi 历史中，因此重新打开会话时不会补造重试或扩展状态。持久化的 custom 通知可以恢复。
- 没有活动回合时，实时通知暂存于有界队列，随下一个真实回合展示；不会为了通知启动模型或伪造成功回合。一个从未产生用户或助手回合、只有通知的原生会话，暂时没有可投影的历史回合。

历史工具结果保留原生有效耗时；命令只有在原生明确提供退出码时才显示该值，不从成功状态推造退出码。

进度转换不更改 Pi 的重试策略，也不增加模型请求。压缩、审批和子代理仍走各自已有的公共事件。

## 自动续跑与新输入

后台进程或子代理通知可能让 Pi 在上一个用户回合结束后自动继续。原生 `agent_start` 一到，Adapter 就公布自主回合开始，后续工具和正文实时转发；不会等执行结束后才一次性回放。原生身份仍在稳定结束后核对，取消、重试及紧接旧回合的新执行保留各自顺序。

新用户输入在接纳前检查原生忙状态，并在异步启动或历史读取后重新检查。若自动续跑在这段间隙开始，返回可重试的 `sessionBusy`，不先宣称接纳、再失败，也不替用户自动重发。运行中的回合使用已有停止或调整方向入口。

## 流式完成态

Pi 的增量与完成消息按内容块核对。完整消息包含尚未展示的合法后缀时补齐；已经展示的内容不重复追加。不同消息和内容块的状态独立，兼容没有内容块索引的旧 RPC 事件。

Pi Provider 可能在流式摘要末尾加入段落换行，再在内容块完成时规范化文本；这种正常格式变化不应造成重复内容或错误。已经展示的正文若与最终快照发生无法通过追加修复的冲突，会明确报告协议错误，不把不完整内容静默当成成功结果。

## 验证与应用边界

回归覆盖可见/隐藏通知、重复帧与同文独立通知、历史身份、重试状态、逐块完成态、缺失后缀，以及真实 Pi 1.4 精简流事件。自动续跑还覆盖开始到首条消息之间的输入、历史读取期间的竞争、旧回合结束后立即续跑和取消。构建后的插件还需通过公共 Loader 或隔离回放核对实际投影。

Host 会缓存已加载的插件，替换磁盘上的 `plugin.mjs` 不会更新已有进程。应用时需确认其他任务已停止运行，保留当前安装文件作为回滚副本，再重启受控 Desktop；重启后核对新的 Host 进程和插件内容。构建或文件复制成功不等于已应用到运行环境。
