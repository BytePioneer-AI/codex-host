# Trae CLI experimental integration

The `trae` plugin connects to the official **Trae CLI 2.0** using its native `traecli app-server --stdio` interface. It does not automate the TRAE IDE, attach to SOLO, use the Python `TRAE-agent` project, or send Trae traffic to Codex's app-server. The native wire shapes were checked against the TypeScript bindings exported by public CLI **0.213.1** with `app-server generate-ts` on Windows on 2026-10-31. The interface is experimental; other CLI versions require compatibility verification.

## Setup

Install from the [official Trae CLI guide](https://docs.trae.cn/cli_get-started-with-trae-cli-2), then run `traecli login` with an account entitled to use the CLI. An existing IDE login does not prove CLI access. The plugin never starts login, copies credentials from another application, or installs/updates the CLI automatically.

The plugin discovers `traecli` on PATH and in supported per-user installation directories. Use `CODEXHOST_TRAE_COMMAND` for an explicit executable location; it is passed through the shared executable-discovery and command-invocation helpers, including Windows `.cmd` launchers. An explicit missing path is an error, not permission to select another installation. CLI version checks use that same executable. The connection page links to native manual updates (`traecli update check`, then `traecli update`); it does not claim to know the latest version.

The repository's normal TypeScript/plugin build includes this plugin through `scripts/release/harness-plugins.json`. A separately built plugin consists of the generated ESM entry, manifest and SVG resource; enable `trae` in the containing plugin root's `enabled.json`. No extra Host registration or Renderer patch is required. See [Harness plugin runtime](../../architecture/harness-plugin-runtime.md) for the public installation layout.

## Ownership and configuration

Each Session owns one child app-server and its stdin/stdout transport. JSON-RPC handling, native configuration, history projection and interactions remain inside `packages/adapters/trae`. Factory environment is the base; `open().environment` overrides it on create, resume, Fork and rollback paths. Closing a Session terminates only its own process tree, with a bounded fallback, and ends its output stream. The adapter also closes pending inspection/open transports.

Inspection initializes a temporary transport, checks `account/read`, and reads all pages of `model/list`. It creates no native Thread or model request. Hidden Models are omitted; Provider and Model identity are encoded together in opaque public Model Refs. Successful catalogs are cached per cwd and environment without a TTL; explicit refresh bypasses the cache. Open performs a fresh authentication/catalog check in the Session environment. Authentication and empty-catalog failures are distinct from installation and protocol failures. Native error text and stderr are not forwarded because they can contain prompts or credentials.

New Sessions are lazy: opening or selecting draft configuration does not create an empty native Thread. A draft selection is validated against the native catalog and stored as requested configuration. It is **not** published as effective state. On the first valid `turn.start`, `thread/start` must confirm the selected settings before the prompt is submitted. Unspecified Model/Thinking are omitted so Trae chooses its own defaults. This adapter's permission default is workspace-write with on-request approval; the other explicit modes are read-only/on-request and danger-full-access/never. Unattended full access must be confirmed by the native acknowledgment before any prompt; conflicting explicit permission intent is rejected.

On an established Session, Model, Thinking and permission changes use `thread/resume` overrides and publish the native response, including the Model's current Thinking options. Model/Thinking changes can be attempted while a Turn runs; Trae controls admission and when they take effect. Permissions cannot change during an active Turn. Resume treats native state as authoritative and does not replay persisted Host hints. A requested configuration that is not confirmed returns an error and retains the actually observed state.

## Turns, output and interactions

Only one ordinary Turn is admitted at a time. Notifications arriving before the `turn/start` response are buffered and replayed after acceptance. Rejected Turns do not emit Turn events. A Turn that is accepted emits one start and one terminal event; duplicate/late native completions are ignored. `turn/interrupt` acknowledges a cancellation request; only the later native interrupted completion settles the Turn. An exited process faults the Session and settles any accepted Turn once. There is no automatic retry of an operation with an uncertain receipt.

Native agent messages, public reasoning summaries, commands and command output, file patches, tools and context-compaction Items map to the public Item lifecycle. Raw private reasoning content is not projected. Final native Items replace streamed previews. Native command/file-change approval requests map to explicit allow-once, allow-for-session and deny choices; user-input requests map to validated text, single-choice and multi-choice answers. Wrong, duplicate and late Host responses are rejected. Pending interactions close when their Turn ends or the Session closes. Unsupported native client requests receive an explicit method error rather than hanging or receiving a fabricated approval.

Native autonomous `turn/started` notifications for this exact Thread are observed through the public autonomous-Turn event. Aggregate native token usage is exposed without invented prices or request-level attribution. Structured Subagent transcripts, request-level usage, native slash-command catalogs, imports, credits and global usage are not advertised. Same-Turn steer is explicitly unsupported in this initial plugin; the Host's generic cancel-and-replace flow remains available.

Detached native commands (`commandExecution.status: backgrounded`) cannot be tracked to their eventual exit through this implementation. Encountering one faults and stops the Session with an explicit unsupported error instead of reporting successful command completion. Foreground commands and their final exit codes/output are supported; background command execution remains a separate acceptance gap.

## History and derivation

Native identities are published after the native Thread is created and retained on resume. `thread/read` with `includeTurns` provides a read-only snapshot; responses with partial (`itemsView` other than `full`) history are rejected rather than presented as complete. The CLI itself may omit interactions it never persisted; the plugin cannot reconstruct those from Host metadata.

Fork validates that the checkpoint belongs to the source and names an actual terminal Turn, then invokes native `thread/fork` with its inclusive `lastTurnId` and target cwd. It verifies the retained Turn keys, inputs, Items and outcomes. Rollback creates a native Fork first and rolls back one Turn **on the copy**. The source history is re-read to detect concurrent changes. Neither operation rewrites native files or reverts workspace file changes. Derived identities must differ from their source. If native derivation succeeds but verification fails, the unverified copy is retained for diagnosis; no mapping is published and no unknown native data is deleted.

## Verification and limits

The automated suite launches an independent stdio fixture with the observed 0.213.1 wire shapes. It checks catalog caching/failures, lazy creation, Unicode streaming, configuration confirmation, busy/rejection/crash paths, cancellation, approvals, questions, environment precedence, exact restore/derivation and idempotent teardown. A public Host Coordinator test loads the built plugin after copying it outside the workspace, receives an unattended delegated task, reads actual projected response text, restarts the Host and continues the same native Session. This is a hermetic protocol/packaging test, not authenticated Trae inference.

On the actual Windows CLI 0.213.1, version/help, protocol generation and initialize/account/read/model/list were executed. The current account was not logged in and the actual Model catalog was empty. Authenticated inference, native tools/permissions, native history behavior, real delegation, Desktop UI and macOS/Linux process behavior remain live acceptance work. Do not call this a fully certified Trae or IDE integration. The [capability inventory](../../../packages/adapters/trae/CAPABILITIES.md) records each implemented and limited surface.

Native references: [CLI command reference](https://docs.trae.cn/cli_command-line-parameters), [ACP reference](https://docs.trae.cn/cli_agent-client-protocol). ACP is available in the CLI, but this plugin uses the richer native app-server history/configuration interfaces; it does not assume ACP and app-server have identical semantics.
