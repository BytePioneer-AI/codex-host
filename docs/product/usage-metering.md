# 会话用量计量

外部 Harness 会话的用量浮窗中，Host 统一计算请求级费用、平均缓存命中、首 token（TTFT）和输出速度（TPS）；保留原生计费的 Harness 可通过既有用量字段上报同口径速度。规范见 `openspec/changes/add-host-usage-metering/`。

## 显示的指标

| 指标 | 含义 | 来源 |
| --- | --- | --- |
| 会话费用估算 | 本会话全部请求的 Token 按公开 API 价格折算的金额 | Host 按请求记录与价格表计算 |
| 平均缓存命中 | 累计缓存读取 ÷ 累计输入 | Host 按请求记录或完整原生 `sessionCacheUsage` 计算，独立于计费模式 |
| 最近缓存命中（CH） | 最近一次请求的缓存命中率 | Adapter 根据最近请求的原生数据上报 |
| 输出速度 | 当前（或最近）一轮至今的平均产出速度：Σ 输出 Token（含思考）÷ Σ 各请求生成时长（从首个思考、正文或工具调用 Token 到请求结束，不含预填充和工具执行，与 DeepSeek dsh 口径一致），每完成一次请求更新 | Host 按请求计时计算 |
| 首 token（TTFT） | 最近一轮从开始到首个推理或正文输出的时间 | Host 观测，所有 Harness 都有 |

Token 累计、上下文、套餐等字段仍由 Adapter 原生上报，Host 不覆盖。所有 Harness 的用量浮窗均不单独展示推理／思考 Token 数；内部仍保留原生推理用量，计费和输出速度的计算口径不变。

Host 观测到首个输出或计入新请求后，通过用量通知触发界面重新读取指标，不必等待整轮结束，也不依赖原生上下文数据。Renderer 按 Host 隔离监听 Desktop 窗口中的原始通知，避免自定义通知被 Desktop 分发器过滤；没有增加轮询。原生尚未提供的数据仍需等待，不能靠刷新补造。

输入框下方的用量按钮显示“最近缓存命中（CH）· 输出速度 · 费用”，例如 `CH 99.6% · 232 tok/s · $12.23`。按钮用最近值反映缓存失效；有可靠数据时显示，包括明确的 0%，未知或输入为零时省略。平均缓存命中只在浮窗中显示。速度 100 以上取整；费用 1 美元以上保留两位小数，以下保留三位。缓存写入为 0 或未知时，浮窗只显示缓存读取。

## 已接入的 Harness

Pi、OMP、OpenCode v2、Claude Code、DeepSeek Harness（dsh）、CodeBuddy、WorkBuddy、ZCode。其余 Harness 继续显示原生费用，后续分批接入；OpenCode v1 不接入。

接入的 Adapter 在每次打开会话时回放原生历史中的全部请求，再声明历史是否完整；运行中每完成一次模型请求发布一条请求记录。Host 只在内存中计量，不持久化，重启后重新回放即可得到相同结果。

## 什么时候不显示

宁可不显示，也不显示错的数字。以下任一情况会省略整个会话的费用：

- 某次请求的模型或缓存数据未知；
- 原生历史读取失败或不完整，或运行中某次请求的用量缺失；
- 会话中没有任何一次请求能计价。

某些请求的模型在价格表中查不到（如 `auto`、`gpt-5.3-codex-spark`），或缺少需要的缓存单价时，这些请求不计入，费用显示为下限，例如 `≥$12.23`，浮窗中注明“未计价：模型 ID”。在 `pricing.json` 中补上价格后即恢复完整费用。

缓存数据未知或历史不完整时，平均缓存命中也不显示。首 token 与输出速度只依赖本次观测，不受影响。

## 计费口径

- 每次请求按它实际使用的模型单价计算，会话中途换模型也能算对。
- 费用 = 未命中输入 × 输入单价 + 缓存读 × 缓存读单价 + 缓存写 × 缓存写单价 + 输出（含思考）× 输出单价。
- 缓存写入分两档：默认（5 分钟）按价格表的缓存写入单价；1 小时档按输入单价 × 2，与 Claude Code 内置价格一致（models.dev 只提供 5 分钟档），可在 `pricing.json` 用 `cacheWrite1h` 覆盖。
- Claude Code：费用与其 `costUSD` 的差额来自它在流与转录之外发出的后台请求；不计网页搜索按次费用（$0.01/次）与美国地域推理 1.1 倍系数。历史文件缺失，或请求因取消/失败缺少最终用量时，标记不完整，不显示漏计的会话总费用。
- OpenCode v2：速度从首个输出事件计至原生 `time.streamed`（流结束），不使用可能包含工具执行的 `time.completed`；没有流结束时间时不计速度，用量仍计入。最近 CH 从最新已记录用量的 assistant 消息计算，输入分母包含缓存读取和写入；历史恢复和实时刷新使用同一口径。
- Grok：新建、恢复及切换模型时，对原生 `contextWindows` 明确包含 500,000 的模型，默认通过 `session/set_model` 的 `_meta.contextWindow` 选择 500K；原生配置成功后同步上下文上限，不改全局配置，不对其他模型强制设置。尚未取得上下文已用量时不伪造零占用。保留原生 `costUsdTicks` 费用，不使用公开价格重算。每次模型响应完成后异步查询 `_x.ai/session/usage` 刷新费用，不轮询、不阻塞工具或轮末结算。查询值是本次原生进程附着后的累计，按“打开时历史费用基线 + 当前原生累计”计算，不累加各次快照；忽略乱序、已结束轮次的迟到响应及缺失/不完整费用。查询失败保留上一有效值，仍由轮末原生历史核对。接收 `_x.ai/session_notification` 的 `response_completed`，每完成一次模型请求即更新本轮 TPS、最近请求缓存命中及累计 Token，无需等工具或整轮结束。该事件的输入是未缓存部分，须加缓存读/写后归一；输出已含推理，不重复加算。首个非空思考、正文或工具参数增量至该次响应完成构成客户端观测时窗；只累计有输出用量且时长为正的请求，排除工具、审批和结算 I/O。取消/失败不丢弃此前已完成请求的有效计时，无有效计时的新轮结束时清除旧速度。隐藏推理开始不可见时从首个实际输出起算，不宣称服务端完整生成速率，也不使用 API 耗时。完整原生历史和实时请求提供 `sessionCacheUsage` 事实，由 Host 独立计算平均缓存命中；不完整则省略。轮末历史用于校准累计 Token 和原生费用，不覆盖实时最近请求缓存率。历史不重建 TPS，也不把整轮缓存率伪装成最近请求缓存率；冷恢复只有整轮记录时省略最近值。TTFT 继续由 Host 观测。
- CodeBuddy / WorkBuddy：ACP 不上报逐次请求用量，打开会话、收到原生用量通知、浮窗请求刷新和每轮结束时，从原生历史的全部分支读取已落盘请求并按请求 ID 去重，不必等待工具执行或权限审批结束。读取失败不影响对话，由下次刷新重试；没有可靠的逐请求计时，因此不显示输出速度。WorkBuddy 自动路由的 `default-model` 不是具体模型，无法计价。最近 CH 按当前原生历史分支最后一次已记录请求的缓存读取除以输入总数（已含缓存）计算，不使用会话累计平均值。
- ZCode：恢复时从原生 `session/resume` 快照回放每条 assistant 消息；实时按主请求边界关联 `assistantMessageId`，轮末用 `session/read` 快照补齐并核对。输入已含缓存，输出已含思考；`v4/conversation/usage` 的输入是上下文增量累计，不能作为费用或平均缓存的分母，原生 Token 展示仍保留该口径。流事件缓存字段不全时延迟到轮末计量；未知口径或矛盾记录使会话级指标失效。失败/取消只有零占位、没有 Provider 用量时不计入。协议没有思考开始事件，明确带思考 Token 的请求暂不计速度；其他请求使用原生流事件时间，不拿包含工具执行的消息落盘时间作终点。Host 已计入的请求会触发界面刷新；流中缺缓存明细的请求仍需等轮末补齐。
- 不计入：子代理、原生不给出模型的后台请求（如 OpenCode v2 的标题生成与压缩）、按次收费项目和长上下文分档价格。
- 分叉会话按原生历史计算，包含从父会话复制来的轮次；撤销上一轮后，被撤销轮次不再计入。

## 价格表

- 默认价格来自 [models.dev](https://models.dev)（MIT），随版本打包快照。
- Host 启动时和运行期间每小时检查一次本地价格表，超过 24 小时即在后台请求 `https://models.dev/api.json`；查询中出现无价格的模型时，若价格表和上次尝试都已超过 6 小时，则提前重新请求（新模型可能刚被收录）。同一时间只有一个请求，失败时静默沿用现有价格。结果缓存到 `<数据目录>/pricing/models-dev.json`。用户价格保存在单独的 `<数据目录>/pricing.json`，优先于 models.dev；自动更新只改写缓存文件，不会覆盖或删除用户修改或新增的价格。
- 查找不做模糊或前缀匹配：先按“服务商/模型”，再按模型 ID。未命中明确的服务商价格时，带 `canonical_model_id` 的条目即使只有一个，也沿该链确定官方厂商，不能直接采用另一服务商的套餐零价；厂商自己列出该 ID 时用厂商价格，无法确定则视为未匹配。明确指定服务商的价格（包括零价）和用户自定义价格仍优先。仅大小写不同的 ID（如 `Deepseek-v4-flash`）也能匹配，前提是各写法的价格一致。所有报价都没有 `canonical_model_id` 标记时，只采用厂商自己的报价（厂商指在价格表中被标为官方条目、或被其他条目的官方 ID 指向的服务商，如 `openai`），多个厂商价格一致才采用；只有转售平台或厂商价格不一致时视为未匹配。原名未命中时，依次尝试去掉日期后缀（`-20250929`）、去掉推理强度后缀（`-high` 等）、版本号点号与短横线互换（`4.6` / `4-6`）的写法；用户为原名设置的价格始终优先。
- 更新打包快照：`npm run build:typescript && node packages/host-runtime/scripts/update-model-prices.mjs`。

数据目录默认是 `~/.codexhost`，可用 `CODEXHOST_DATA_DIR` 修改。

### 自定义价格

价格弹窗提供“相似模型价格”：按当前模型 ID 的名称片段、大小写及分隔符在 Host 已加载的本地价格目录中检索，最多展示 6 个候选，标明模型、Provider 和各项单价。对 `-free`、`:free` 后缀同时检索去掉后缀的基础模型，并将基础模型排在免费变体前；不去掉版本号或 `flash`、`pro` 等能力标识。名称检索忽略模型 ID 中的 Provider 路径前缀；对完整名称或去掉 `free` 后命中的条目，沿目录的 `canonical_model_id` 链扩展关联别名，展示“目录关联模型”。不同模型 ID 即使同价也独立保留，各自使用该目录条目的价格，不按价格合并或相互覆盖。只有目录明确标为官方，或 canonical 链最终指向当前 Provider 自己的模型，才显示“官方”；循环或缺少依据时不标记。同等相关度下优先用户指定的 Provider，再优先官方条目；同一完整模型 ID 最多保留两条普通供应商记录，官方条目不受此限制，最终仍最多展示 6 条。没有候选时不展示。此检索不发起网络请求，也不改变自动计价的精确匹配规则。候选可能来自不同版本、免费档或不同 Provider，仅供用户核对；点击“填入此价格”只替换四个可见价格输入，缺失缓存价格清空为未知、明确零价保留为 0，不修改模型 ID。可继续编辑，保存才写入当前模型覆盖价格；取消不保存，迟到的推荐不覆盖草稿，保存期间不能填入推荐。

在数据目录创建 `pricing.json`，单位为美元 / 百万 Token，优先于默认价格：

```json
{
  "models": {
    "my-local-model": { "input": 0.5, "output": 1.5 },
    "anthropic/claude-sonnet-4-5": { "input": 3, "output": 15, "cacheRead": 0.3, "cacheWrite": 3.75 }
  }
}
```

键可以是模型 ID，也可以是 `服务商/模型 ID`。文件修改后下次刷新用量时生效；格式无效时整个文件被忽略，并在 Host 诊断日志中记录原因。

也可以在本地控制台（`codexhost console`）的“用量统计”模型行点击“设置价格／编辑价格”，通过弹窗编辑该模型的价格，无需手写 JSON。页头无价格入口，不提供常驻价格区域或独立价格页面。弹窗经运行中的本机 Host 读写其数据目录中的 `pricing.json`；远程 Host 使用自己数据目录中的文件，不受影响。页面不展示作用范围、配置文件路径或远程 Host 说明。模型 ID 固定为所选行；可为该模型添加或修改自定义价格、填入默认价格，或确认移除已有条目以恢复默认查价。保存或移除成功后关闭弹窗，自动刷新统计并保留筛选；取消或 Esc 不保存，写入失败保留草稿。未出现在统计中的模型仍可通过 `pricing.json` 配置。

- 每个条目整体替代默认价格，不逐项继承：控制台仅编辑 `input`、`output`（必填）与 `cacheRead`、`cacheWrite`（留空表示未知，需要它的请求不计价），填 0 表示免费。不展示“1 小时缓存写入”字段或说明；底层仍支持 `cacheWrite1h`，编辑已有条目时保留该值，未配置时沿用原有计价规则。
- 每次保存只改一个键，保留其他条目和其他顶层字段；新增或改名为已存在的键会被拒绝。
- 模型键是任意字符串，`constructor`、`__proto__` 等也按普通键读写。
- 现有文件无效时，页面显示原因并拒绝保存，避免覆盖用户内容，需先修复或删除该文件。
- 自定义价格只影响用量估算，不添加模型或服务商，也不改变账号、套餐或实际扣费。
