# 全局用量统计

本地控制台（`codexhost console`）的“用量统计”页汇总本机全部原生会话的 Token、缓存命中与按官方公开价估算的 API 等价费用。设计与决策见 `openspec/changes/add-global-usage-statistics/`。

## 范围

- 统计本机原生会话，不论是否经 CodexHost 创建或导入；只统计所在 Host 的机器，远程 Host 各自统计。
- 已接线的读取器：Claude Code（含子代理与 workflows 转录）、Pi、OMP（含子代理会话）、CodeBuddy、WorkBuddy、OpenCode、ZCode、DeepSeek Harness、Grok、Qoder、Qoder CN。Qoder 两个发行版目前仅完成隔离测试与原生 SDK 分叉验证，尚缺真实会话对账；不代表运行中的 Desktop 已更新插件。
- 官方 Codex 通过独立预装统计插件 `codex-usage` 接入，显示名 Codex；不接管原生会话操作。Hermes 尚未接入。Kimi Code、Antigravity、Kiro CLI、Cursor CLI 的本地数据限制见下文。
- 只统计已启用的 Harness 插件；插件未实现读取能力时不出现，某个 Harness 读取失败只缺这一部分，页面会提示。
- 页面：今天 / 7 天 / 30 天 / 90 天 / 全部，可按 Harness（分段按钮）、模型、项目（可搜索下拉框）和某一天筛选；Host 按筛选条件聚合，前端只渲染结果。
  - 卡片：费用（未计价次数可点击，直达模型表的“只看未计价”）、Token、缓存读取（命中率与写入）、请求、项目数（最大项目占比）、会话数（每会话 Token 的中位数与 p90）。费用、Token、缓存读取和请求显示与上一周期的变化；以今天结尾的周期与上一周期的同一时刻比较，悬停显示上一周期的日期和数值。
  - 趋势：费用 / Token / 缓存读取 / 请求，按日 / 周 / 月（超过 120 天默认按周，超过 730 天按月）。多个 Harness 时按 Harness 堆叠（前四个加“其他”），图例可点击筛选该 Harness；点击某天或用方向键 + 回车只看当天，Esc 取消。“今天”不显示趋势。
  - 按时段：单日显示 24 小时柱状图，否则显示星期 × 小时热力图，标注本机时区。
  - 按 Harness / 模型 / 项目：占比条按当前度量计算，按费用时全部未计价的行显示“未计价”而不是 0%；列头可排序，默认显示前 6 行，其余折叠；点击行名筛选，再点一次取消。项目以文件夹名显示，同名文件夹带上父目录。
  - 最耗会话：按费用和按 Token 各取前 50 合并，默认显示前 10 个；可复制原生会话 ID，点击项目名筛选该项目。
  - 页头显示更新时间，可手动刷新、选择自动刷新间隔、导出当前筛选下按日 × Harness 的 CSV。时间范围、度量、粒度、筛选和自动刷新间隔保存在本浏览器；刷新时保持键盘焦点和图表悬停。

## 口径

- 每条记录是一次原生模型请求，沿用单会话计量的统一口径（输入含缓存，输出含思考），由各 Adapter 解析其原生用量。能够复用时沿用现有解析函数；Host 不理解 Harness 私有格式。
- 页面上的 Token **不含缓存读取与写入**：Token = 输入（扣除缓存读取和缓存写入）+ 输出，缓存读取单独成卡。缓存情况未知的请求无法拆分，其输入整体计入“输入”，Token 卡会注明这部分的数量。命中率 = 缓存读取 ÷ 缓存情况已知的全部输入（含缓存读写）。
- 每条记录可带原生会话 ID 和会话工作目录（项目），由 Adapter 从原生存储读出：Claude Code、CodeBuddy / WorkBuddy、Qoder 取自每行的 `sessionId`、`cwd`；Pi、OMP、DeepSeek Harness 取自会话头；Codex 取自线程 ID 和首个 `session_meta`；Grok 取自会话目录及其 URL 编码的上级目录；OpenCode、ZCode 关联会话表的 `directory`。缺失时请求照常计入，只是不出现在会话列表并归入“未知项目”。分叉复制的历史请求按 ID 去重，归属于先读到的那份会话文件。
- 按原生记录自带的时间归入本地日期。
- 去重：分叉、恢复会复制历史，Host 按（Harness, 请求 ID）只计一次。保留原始 ID 和时间的副本可在父会话文件删除后继续计入；Grok 等改写副本时间的 Harness 需要读取器先排除复制历史。Qoder 的处理见下文。
- 费用按模型 ID 在读取时计价（与会话浮窗相同的价格目录与公式）；缺价格或缺所需缓存单价、缓存数据未知的请求不计入，费用显示为下限 `≥$`，完全无法计价显示 `—`。价格入口仅出现在有模型 ID 的模型行：有未计价请求时显示“设置价格”，已计价时显示“编辑价格”。点击打开当前模型的价格弹窗，模型 ID 只读；可保存自定义价格、填入默认价或确认移除已有覆盖值。页头无价格入口，页面无常驻价格区域或独立价格导航；未知模型不提供价格操作。保存或移除成功后关闭弹窗并自动重新读取统计，保留时间范围、Harness、模型筛选与趋势指标。取消或 Esc 关闭且不保存，写入期间禁止关闭和重复提交；失败保留草稿。后台统计轮询不会替换弹窗或清除草稿。

## 读取与性能

- 只读原生会话文件或数据库，不启动原生进程，不另起进程，不修改原生存储。
- 解析结果按文件指纹（inode、大小、修改时间）缓存在 `<数据目录>/usage-statistics/v2/<harness>.json`，可随时删除，下次从原生数据重建。只重新解析变化的文件；正在写入的会话文件变化时整文件重读。
- 本机 Launcher 启动的 Host 在启动约 3 秒后后台预读；页面立即返回已有结果，结果超过 10 秒在后台更新；首次读取时显示“正在读取本地会话 已读/总数”和已读部分的结果。实测本机 Pi 2.7 GB 约 5.5 秒、Claude Code 551 MB 约 1 秒完成首次读取。

## Codex 统计插件

- 插件位于 `packages/adapters/codex-usage`，Manifest 使用 `kind: "usage"`，只提供 `createUsageStatisticsAdapter` 工厂与可选统计契约，不需要 `inspect/open`，不启动 Codex 或 app-server。Host 不包含 rollout 解析或按 Codex 名称分支。
- 只读配置的 `CODEX_HOME`（默认 `~/.codex`）下 `sessions/` 和 `archived_sessions/`；包括该目录内未经 CodexHost 创建的会话。不扫描其他账户目录或任意项目，不跟随目录内部符号链接。
- 新版 `token_usage_record` 以原生 Session ID + Response ID 去重；旧版 `token_count` 以累计差额还原，处理重复检查点和计数器重置。相邻请求记录与检查点按模型请求配对，不把两种观测重复计入。
- 压缩的明确 Response ID 只计一次，识别 `compacted` 内嵌记录；不能直接比较包含压缩用量的 Thread 累计值与不含压缩的旧计数器。分页子代理的恢复快照作为边界处理，不把已继承的整段累计值当成一次新请求。
- 子代理的新请求计入 Codex 总量。复制历史按原生 `thread_id` 归属与旧格式分叉时间排除；原始父文件删除后不能保证还原这些历史请求，不将复制时间或文件修改时间当作原始发生时间。
- 同一 Thread 的多段 rollout 合并读取，兼容双 UUID（含下划线）的续写文件名。相同文件名的归档或压缩副本只有逐字节解压比对证明是前缀时才整份去重；不因 Thread ID 相同就丢弃分段或分歧文件。
- `.jsonl.zst` 按帧异步解压，支持拼接帧；损坏/残缺压缩文件报告失败。逐行读取并定期让出事件循环；超大帧有内存安全上限。
- 返回的输入 **包含缓存**、输出 **包含思考**，由公共层计价时扣除输入里已含的缓存，不在插件重复扣减。模型来自原生 Turn 上下文；缺模型或缓存字段时不猜测，也不替换成当前配置模型。
- 缓存单元为 Thread 的文件集合，指纹包含路径、inode、大小、mtime、ctime；集合未变时沿用 Host 缓存。变化时整组重读，尚非按字节续读；读取期间有改写/追加会报告失败，下一次刷新重试。

### 验证边界

- 三份公开的原生脱敏样本与预期的请求数、输入/输出/缓存合计一致；另有配对顺序、模型切换、重置、分叉、归档前缀、拼接压缩帧和关闭取消的合成测试。
- 本机只读扫描 795 个 rollout，归并为 792 个 Thread 源，得到 34,289 条请求。独立 Python 核对：明确 Response ID 的 9,929 条请求与 584 个仅旧计数器 Thread 的 24,360 条请求，两部分的输入、输出、缓存读与思考 Token 合计分别一致；一次首次扫描约 4.6 秒。这是数据快照，不是持续不变的账户账单。
- 搬移后的独立插件通过真实 Loader 加载、隔离实例和关闭测试；Host 路由与公共计价、补价后重算有集成测试。没有重启正在运行的 Desktop，也未做其可见页面验收；生效需后续构建产物安装并重启 Host。

## Qoder / Qoder CN

- 两个发行版复用 Qoder Adapter 内的 `qoder-usage-statistics.ts`，各自暴露 `usageStatistics`；不增加 Host 分支、契约或页面。
- 分别读取 `QODER_CONFIG_DIR/projects`、`QODERCN_CONFIG_DIR/projects`；没有显式配置时，使用对应 `QODER_CLI_HOME` / `QODERCN_CLI_HOME` 下的 `.qoder` / `.qoder-cn`，再回退用户主目录。这与两套原生 SDK 的历史目录规则一致。
- 扫描主会话及子代理 JSONL。一次模型回复的多个内容块共享 `message.id`，取首个有效原生时间和最后一份有效用量；保留已撤回分支中的实际请求，不把当前会话视图当成全部消耗。
- 输入为 `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`，输出包含思考。缺必要 Token 桶、请求 ID 或时间的记录不猜测；模型缺失时保留 Token，交给公共层显示未计价。跳过原生 API 错误占位与 `<synthetic>` 消息。
- 原生 SDK 的分叉会重建行 UUID，并可能把最后一条复制记录改为分叉时间。读取器跳过带 `forkedFrom` 的复制行，只计原始文件中的请求；如果原始文件已删除，不能从这些副本可靠恢复历史归日。这是当前限制，不以文件修改时间替代请求时间。
- 用已安装的两套 SDK 在隔离目录实际执行 `forkSession` 验证复制规则，不启动 CLI。当前机器两个默认存储目录都没有会话文件，真实请求总量与原生统计的对账尚未完成。

## 暂未接入的四个 Harness

| Harness | 已确认的本地依据 | 当前缺口 |
| --- | --- | --- |
| Kimi Code | 既有 Adapter 读取 `usage.record` 的 `inputOther`、`inputCacheRead`、`inputCacheCreation`、`output`；存在 `agent.switched` 分支记录 | 本机 `.kimi-code` 没有会话日志。尚未验证每请求的时间、稳定身份、模型与跨会话分叉规则；不能只拿单会话累计值接入全局统计 |
| Antigravity | 现有用量来自运行时事件；Host 历史镜像不是完整原生用量存储 | 本机 `.gemini/antigravity-cli/conversations` 为空，未验证可离线读取的原生请求用量；不为统计启动进程或调用运行时接口 |
| Kiro CLI | 本机 23 份 `messages.jsonl` 的 `usage_summary` 提供 credits；`session_metadata` 有上下文占用比例 | 没有确认输入、输出与缓存 Token；credits 和上下文百分比不换算为 Token |
| Cursor CLI | 本机 21 个 `store.db` 的 JSON 消息没有用量字段 | 尚无经验证的离线 Token 来源；不猜测 protobuf 字段含义，也不拿账户额度替代逐请求用量 |

这些 Harness 继续不暴露全局用量能力，不添加返回空数据的占位读取器。这里的限制是当前数据证据不足，不是架构禁止接入。

## 已知限制

- 增量按文件粒度：活跃会话文件每次变化都整文件重读，尚未从上次位置续读。
- 读取器语义变化时需提升缓存版本号（`CACHE_VERSION`，当前为 2：加入会话归属），否则未变化的文件沿用旧解析结果。升级后首次启动会整体重读一次（本机约 13 秒，后台进行）；之后按筛选聚合一次约 70 毫秒。
- 单会话计量（`UsageMeter`）与全局统计各自实现了同一计价公式（`usageEntryCostUsd`），修改公式时两处需同步。
