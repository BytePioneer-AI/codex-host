# 全局用量统计

本地控制台（`codexhost console`）与 Codex Desktop 内置 CodexHost 设置中的“用量统计”页汇总本机全部原生会话的 Token、缓存命中与按官方公开价估算的 API 等价费用。两个入口复用同一页面、交互和样式；内置设置直接通过 Desktop 的本机 Host 连接请求统计及模型价格，不依赖控制台 HTTP 服务或当前 Composer 所在的远程 Host。设计与决策见 `openspec/changes/add-global-usage-statistics/`。

## 范围

- 统计本机原生会话，不论是否经 CodexHost 创建或导入；只统计所在 Host 的机器，远程 Host 各自统计。
- 已接线的读取器：Claude Code（含子代理与 workflows 转录）、Pi、OMP（含子代理会话）、CodeBuddy、WorkBuddy、OpenCode、ZCode、DeepSeek Harness、Grok、Qoder、Qoder CN。Qoder 两个发行版已用本机真实会话核对：请求与原生消息一一对应，但本地记录的 Token 均为 0、只有积分，因此只计请求数，Token 与费用显示为未记录；模型以 Qoder 本地界面文字显示名称（如 `qfmodel` 显示为 Qwen3.8-Flash）。
- 官方 Codex 通过独立预装统计插件 `codex-usage` 接入，显示名 Codex；不接管原生会话操作。Hermes 尚未接入。Kimi Code、Antigravity、Kiro CLI、Cursor CLI 的本地数据限制见下文。
- 只统计已启用的 Harness 插件；插件未实现读取能力时不出现，某个 Harness 读取失败只缺这一部分，页面会提示。
- 页面：今天 / 7 天 / 30 天 / 90 天 / 全部，可按 Harness（分段按钮）、模型、项目（可搜索下拉框）和某一天筛选；Host 按筛选条件聚合，前端只渲染结果。
  - 卡片：费用、总 Token、缓存命中率。总 Token 主数字包含缓存，下方以三个等宽、无边框的小列显示“输入 / 输出 / 缓存”三个互斥分项，每列标签在上、数量在下，不显示斜杠分隔；缓存合并读取与写入。概览卡数量仅作展示，不设置帮助光标或悬停提示。保留三卡布局，不加口径开关、第二个总量、日均或环比。中文 Token 总量显示带千位分隔符的完整数字，达到一万时在数字后以弱化文字补充约数（如 `116,222,990 ≈ 1.16 亿`）；不足一万不附约数。中文分项、表格、Token 图表刻度和悬浮提示采用“万 / 亿”，保留最多两位小数；英文继续使用 K / M / B。分项固定三列，不把缓存项挤到下一行；极窄列中的长数值可折行，避免裁切或重叠。费用、命中率、筛选、排序及 CSV 原始分项不变。
  - 趋势：费用 / Token，按日 / 周 / 月（超过 120 天默认按周，超过 730 天按月）。多个 Harness 时按 Harness 堆叠（前四个加“其他”），图例可点击筛选该 Harness；点击某天或用方向键 + 回车只看当天，Esc 取消。“今天”不显示趋势。
  - 按时段：单日显示 24 小时柱状图，否则显示星期 × 小时热力图，标注本机时区。
  - 按 Harness / 模型 / 项目：占比条按当前度量计算，按费用时全部未计价的行显示“未计价”而不是 0%；列头可排序，默认显示前 6 行，其余折叠；点击行名筛选，再点一次取消。项目以文件夹名显示，同名文件夹带上父目录。
  - 最耗会话：按费用和按 Token 各取前 50 合并，默认显示前 10 个；第一行显示会话名：有 codexhost 映射记录时优先使用 Desktop 持久化标题，否则使用原生名称（用户命名、Agent 生成或首条提示），没有名字时显示“未命名”；第二行以灰色小字显示项目名。长文本单行省略，悬停会话名查看完整标题及原生 ID，点击复制 ID；点击项目名筛选该项目，悬停可查看工作目录。
  - 最近会话：按最后活跃时间取前 50，默认显示前 10 个，列与最耗会话相同。
  - 页头显示更新时间，可手动刷新、选择自动刷新间隔、导出当前筛选下按日 × Harness 的 CSV。时间范围、度量、粒度、筛选和自动刷新间隔保存在各入口自己的本地存储中，不在 Web 与 Desktop 之间同步；刷新时保持键盘焦点和图表悬停。

## 口径

- 每条记录是一次原生模型请求，沿用单会话计量的统一口径（输入含缓存，输出含思考），由各 Adapter 解析其原生用量。能够复用时沿用现有解析函数；Host 不理解 Harness 私有格式。
- 原生记录给出了请求但 Token 桶全为 0 时（目前为 Qoder：本地会话与日志只记积分），视为“Token 未记录”：计入请求数，不计 Token 与费用，也不算未计价；整行均为此类请求时，Token 各列与费用显示 `—`，不提供价格入口。
- 概览“总 Token”**包含缓存读取与写入**：总量 = 规范化输入 + 输出，不能再次加上缓存或思考。下方“输入”= 规范化输入 − 缓存读取 − 缓存写入，“输出”沿用包含思考的输出桶，“缓存”= 缓存读取 + 缓存写入；已记录的三个分项之和等于总量。缓存情况未知的请求无法拆分，其输入整体保留在“输入”；全部输入均无缓存拆分时，缓存项显示 `—` 而非假定为 0。全部请求未记录 Token 时，总量与三个分项均显示 `—`。本次仅调整概览卡：趋势、按 Token 的占比与会话排名仍使用非缓存 Token（输入扣除缓存读写 + 输出），与“总 Token”不是同一度量。命中率仍为缓存读取 ÷ 缓存情况已知的全部输入（含缓存读写），计费公式不变。
- 每条记录可带原生会话 ID、会话名和会话工作目录（项目），由 Adapter 从原生存储读出：Claude Code、CodeBuddy / WorkBuddy、Qoder 取自每行的 `sessionId`、`cwd` 以及 `custom-title` / 首条用户提示；Pi 取自会话头与 `session_info` 名称；OMP 取自文件开头的 title 行；DeepSeek Harness 取自会话头；Codex 取自线程 ID、`session_index.jsonl` 的 `thread_name`，否则取首条用户键入的提示（跳过 AGENTS.md 与环境注入）；Grok 取自会话目录及其 URL 编码的上级目录，以及 `summary.json` 的生成标题；OpenCode、ZCode 关联会话表的 `directory` 与 `title`。缺失时请求照常计入，只是不出现在会话列表并归入“未知项目”。分叉复制的历史请求按 ID 去重，归属于先读到的那份会话文件。
- 会话列表展示标题时，Host 按（Harness、原生 Session ID）精确关联本机 mapping-store 的 ready Thread，优先复用其非空 `title`（Desktop 已保存的自动标题或用户重命名），不按项目名或首条提示模糊匹配。相同原生身份有多条映射时，取最近更新的非空标题；导入会话也适用。每次统计查询读取当前映射，改名无需重读原生用量；映射缺失、标题为空或读取失败时回退原生名称，再回退“未命名”。只装饰展示结果，不改变原生 Session、请求归属或统计缓存，也不额外调用 Codex 标题生成服务。标题生成策略不变，已有标题不代表所有外部会话都经过 Codex 转写。
- Pi / OMP 全局统计优先使用原生 responseId；缺失时用原生日志条目 ID 加消息时间，避免跨会话同毫秒碰撞，并保留分叉副本的身份。两种原生身份均缺失时跳过该条，不凭时间猜测。统计缓存版本升级后会从原生记录重建。
- 按原生记录自带的时间归入本地日期。
- 去重：分叉、恢复会复制历史，Host 按（Harness, 请求 ID）只计一次。保留原始 ID 和时间的副本可在父会话文件删除后继续计入；Grok 等改写副本时间的 Harness 需要读取器先排除复制历史。Qoder 的处理见下文。
- 费用在读取时计算，顺序为：用户在价格弹窗中为该模型设置的价格 → Harness 自己记录的请求费用（目前为 Grok：每轮的 `costUsdTicks`，1 tick = 10⁻¹⁰ 美元；Grok Build 的定价与公开 API 不同，不按公开价换算；Grok 标为 `usageIsIncomplete` 而没有费用的轮次按 0 计）→ 按模型 ID 查价格目录（与会话浮窗相同的价格目录与公式）；缺价格或缺所需缓存单价、缓存数据未知的请求不计入费用；金额只显示已计价部分，不加 `≥` 等标记，完全无法计价显示 `—`。未计价请求在模型表中以“N 次未计价”标出，可用“只看未计价”筛选并补价。按 Harness 记录的费用计价的模型行不显示价格入口（设置价格会覆盖全部记录的费用）。其余价格入口仅出现在有模型 ID 的模型行：有未计价请求时显示“设置价格”，已计价时显示“编辑价格”。点击打开当前模型的价格弹窗，模型 ID 只读；可保存自定义价格、填入默认价或确认移除已有覆盖值。页头无价格入口，页面无常驻价格区域或独立价格导航；未知模型不提供价格操作。保存或移除成功后关闭弹窗并自动重新读取统计，保留时间范围、Harness、模型筛选与趋势指标。取消或 Esc 关闭且不保存，写入期间禁止关闭和重复提交；失败保留草稿。后台统计轮询不会替换弹窗或清除草稿。

价格弹窗下方可展示本地目录检索出的“相似模型价格”（最多 6 项，含模型、Provider 及单价）。用户可点击“填入此价格”复用并修改，模型 ID 保持不变，保存才生效；推荐不自动参与计价。未查询到候选或旧 Host 未返回候选时维持原有表单。详情见 [会话用量计量：自定义价格](usage-metering.md#自定义价格)。

## 原生 Credits

- 不设置独立 Credits 区域。按 Harness、按模型表的费用列采用主金额＋明细：美元在第一行，credits 在下方以较小字号和弱颜色显示，每个 Harness 独立一行；没有美元时，credits 使用正常字号与颜色作为主显示。明确为零显示 `0 credits`，两者均未知显示“未计价”。Token 列不变，概览、趋势、占比和费用排序仍采用美元口径，项目和会话表不借用其他范围的 credits。
- Credits 沿用时间、Harness、模型、项目及日期筛选和请求去重；同一 Harness 可汇总不同模型，不跨 Harness 合计。汇总视图始终标注 Harness 名称（只有一个 credits 来源也标注）；选定单个 Harness 后省略其名称。数字与 `credits` 单位不拆行，过长来源名称省略并可悬停查看，不换算美元。
- CodeBuddy / WorkBuddy 读取每请求 `providerData.rawUsage.credit`；Qoder / Qoder CN 读取每请求 `message.usage.credits`，不使用折扣前的 `original_credits` 或累计会话快照。小数和明确的 0 均保留；缺失或无效值为未知，不补零、不丢弃有效 Token。
- 费用单元格悬停提示“已记录 / 请求数”，说明 credits 覆盖范围；缺失 credits 不补零。原生记录为 0 只表示文件记为零，不额外推断账户实际扣费。美元未计价提示和补价功能保留，不将 credits 误当成美元已计价。
- Kiro CLI 的单会话读取支持原生 credits，但尚未接入全局统计。

## 读取与性能

- 只读原生会话文件或数据库，不启动原生进程，不另起进程，不修改原生存储。
- 解析结果按文件指纹（inode、大小、修改时间）缓存在 `<数据目录>/usage-statistics/v5/<harness>.json`，可随时删除，下次从原生数据重建。只重新解析变化的文件；正在写入的会话文件变化时整文件重读。
- 本机 Launcher 启动的 Host 在启动约 3 秒后后台预读；页面立即返回已有结果，结果超过 10 秒在后台更新；首次读取时显示“正在读取本地会话 已读/总数”和已读部分的结果。实测本机 Pi 2.7 GB 约 5.5 秒、Claude Code 551 MB 约 1 秒完成首次读取。

## Codex 统计插件

- 插件位于 `packages/adapters/codex-usage`，Manifest 使用 `kind: "usage"`，只提供 `createUsageStatisticsAdapter` 工厂与可选统计契约，不需要 `inspect/open`，不启动 Codex 或 app-server。Host 不包含 rollout 解析或按 Codex 名称分支。
- 只读配置的 `CODEX_HOME`（默认 `~/.codex`）下 `sessions/` 和 `archived_sessions/`；包括该目录内未经 CodexHost 创建的会话。不扫描其他账户目录或任意项目，不跟随目录内部符号链接。
- 新版 `token_usage_record` 以原生 Session ID + Response ID 去重；旧版 `token_count` 以累计差额还原，处理重复检查点和计数器重置。相邻请求记录与检查点按模型请求配对，不把两种观测重复计入。
- 压缩的明确 Response ID 只计一次，识别 `compacted` 内嵌记录；不能直接比较包含压缩用量的 Thread 累计值与不含压缩的旧计数器。分页子代理的恢复快照作为边界处理，不把已继承的整段累计值当成一次新请求。
- 子代理的新请求计入 Codex 总量。复制历史按原生 `thread_id` 归属与旧格式分叉时间排除；原始父文件删除后不能保证还原这些历史请求，不将复制时间或文件修改时间当作原始发生时间。
- 同一 Thread 的多段 rollout 合并读取，兼容双 UUID（含下划线）的续写文件名。相同文件名的归档或压缩副本只有逐字节解压比对证明是前缀时才整份去重；不因 Thread ID 相同就丢弃分段或分歧文件。
- `.jsonl.zst` 按帧异步解压，支持拼接帧；损坏/残缺压缩文件报告失败。逐行读取并定期让出事件循环；超大帧有内存安全上限。
- 返回的输入 **包含缓存**、输出 **包含思考**，由公共层计价时扣除输入里已含的缓存，不在插件重复扣减。模型来自原生 Turn 上下文；缺模型或缓存字段时不猜测，也不替换成当前配置模型。
- 缓存单元为 Thread 的文件集合，指纹包含路径、inode、大小、mtime、ctime；集合未变时沿用 Host 缓存。变化时整组重读，尚非按字节续读；读取期间有改写/追加会报告失败，下一次刷新重试。

### 验证边界

- 三份公开的原生脱敏样本与预期的请求数、输入/输出/缓存合计一致；另有配对顺序、模型切换、重置、分叉、归档前缀、拼接压缩帧和关闭取消的合成测试。
- 本机只读扫描 795 个 rollout，归并为 792 个 Thread 源，得到 34,289 条请求。独立 Python 核对：明确 Response ID 的 9,929 条请求与 584 个仅旧计数器 Thread 的 24,360 条请求，两部分的输入、输出、缓存读与思考 Token 合计分别一致；一次首次扫描约 4.6 秒。这是数据快照，不是持续不变的账户账单。
- 搬移后的独立插件通过真实 Loader 加载、隔离实例和关闭测试；Host 路由与公共计价、补价后重算有集成测试。没有重启正在运行的 Desktop，也未做其可见页面验收；生效需后续构建产物安装并重启 Host。

## Qoder / Qoder CN

- 两个发行版复用 Qoder Adapter 内的 `qoder-usage-statistics.ts`，各自暴露 `usageStatistics`；Host 不包含 Qoder 专用分支。
- 模型名称通过可选 `readModelLabels` 能力，从各自配置目录的 `.auth/dynamic-texts.json` 动态关联 `modelSelector.item.<原生 ID>`，优先英文名称、回退中文；没有逐模型硬编码，不读取凭据或启动进程。元数据随统计刷新独立重读，不重读未变化的会话；缺失或损坏时显示原始 ID，不影响 Token 统计。名称是当前原生展示文案，不是历史模型身份或计价别名；请求、筛选、价格编辑和计价仍使用原始 ID。页面模型筛选、模型表及会话表使用名称，模型表悬停可见原始 ID；跨 Harness 同 ID 的名称有冲突时，合并视图保留原始 ID，选定 Harness 后显示其名称。
- 分别读取 `QODER_CONFIG_DIR/projects`、`QODERCN_CONFIG_DIR/projects`；没有显式配置时，使用对应 `QODER_CLI_HOME` / `QODERCN_CLI_HOME` 下的 `.qoder` / `.qoder-cn`，再回退用户主目录。这与两套原生 SDK 的历史目录规则一致。
- 扫描主会话及子代理 JSONL。一次模型回复的多个内容块共享 `message.id`，取首个有效原生时间和最后一份有效用量；保留已撤回分支中的实际请求，不把当前会话视图当成全部消耗。
- 输入为 `input_tokens + cache_read_input_tokens + cache_creation_input_tokens`，输出包含思考。缺必要 Token 桶、请求 ID 或时间的记录不猜测；模型缺失时保留 Token，交给公共层显示未计价。跳过原生 API 错误占位与 `<synthetic>` 消息。
- 原生 SDK 的分叉会重建行 UUID，并可能把最后一条复制记录改为分叉时间。读取器跳过带 `forkedFrom` 的复制行，只计原始文件中的请求；如果原始文件已删除，不能从这些副本可靠恢复历史归日。这是当前限制，不以文件修改时间替代请求时间。
- 用已安装的两套 SDK 在隔离目录实际执行 `forkSession` 验证复制规则，不启动 CLI。当前机器两个默认存储目录都没有会话文件，真实请求总量与原生统计的对账尚未完成。

| Antigravity | 现有用量来自运行时事件；Host 历史镜像不是完整原生用量存储 | 本机 `.gemini/antigravity-cli/conversations` 为空，未验证可离线读取的原生请求用量；不为统计启动进程或调用运行时接口 |
| Kiro CLI | 本机 23 份 `messages.jsonl` 的 `usage_summary` 提供 credits；`session_metadata` 有上下文占用比例 | 没有确认输入、输出与缓存 Token；credits 和上下文百分比不换算为 Token |
| Cursor CLI | 本机 21 个 `store.db` 的 JSON 消息没有用量字段 | 尚无经验证的离线 Token 来源；不猜测 protobuf 字段含义，也不拿账户额度替代逐请求用量 |

这些 Harness 继续不暴露全局用量能力，不添加返回空数据的占位读取器。这里的限制是当前数据证据不足，不是架构禁止接入。

## 已知限制

- 增量按文件粒度：活跃会话文件每次变化都整文件重读，尚未从上次位置续读。
- 读取器语义变化时需提升缓存版本号（`CACHE_VERSION`，当前为 7：v2 加入会话归属，v3 加入 Harness 记录的费用，v4 加入原生 credits，v5 加入“Token 未记录”标记，v6 已有缓存列扩展，v7 加入原生会话名），否则未变化的文件沿用旧解析结果。升级后首次启动会整体重读一次（本机约 13 秒，后台进行）；之后按筛选聚合一次约 70 毫秒。
- 单会话计量（`UsageMeter`）与全局统计各自实现了同一计价公式（`usageEntryCostUsd`），修改公式时两处需同步。
