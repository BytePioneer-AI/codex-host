# iOS Safari 软键盘下输入框与屏幕底部的贴合

状态：**待解决**。已定位原因，没有可靠的网页侧修法；当前保持未处理。

## 现象

手机 Safari（普通标签页，经 Tailscale 访问 Web）里，期望输入框始终贴着当前可见区域底部：没有键盘时贴屏幕底部，有键盘时贴键盘上沿。实际出现两种偏差：

1. 键盘打开后，输入框底边离键盘上沿有一段空白（实测约 190px 屏幕像素）。
2. 偶发：键盘收起后页面仍停在被滚上去的位置，输入框停在屏幕上部，下方全是空白，直到下一次触摸或重新聚焦才恢复。

空白会话（hero 阶段）的输入框居中显示是现有设计，不属于此问题。

## 已确认的事实

在手机上用临时诊断面板（已移除）实测：

| 状态 | `#root` 顶/底 | `scrollY` | `visualViewport` |
| --- | --- | --- | --- |
| 无键盘，正常 | 0…796 | 0 | 值不可信 |
| 键盘打开 | −431…365 / −543…252 | 431 / 543 | 高度停在 365 / 152，无 resize 事件 |
| 键盘收起后卡住 | −543…253 | 543 | 高度仍为 152 |

- 应用高度没有变小：`html/body/#root { height: 100% }` 一直是 796，Chromium 手机视口下输入框的 `sticky; bottom: 0` 正确贴底。
- 文档本身没有可滚内容（`scrollHeight` 等于视口高度），但 iOS 在聚焦时把页面向上滚了 431～543px，滚动量每次不同，并且会超出文档底部，所以输入框底边落在键盘上沿之上。
- `visualViewport` 在这台 Safari 里不可用：键盘打开期间一条 `vv.resize` 事件都没有，高度被钉在旧值。依赖它判断键盘或设置应用高度都不可行。
- 键盘上方还有 Safari 自带的表单辅助栏（上下箭头和 ✓）和浮动地址栏，页面无法改变它们，输入框不会落到它们下面。
- `interactive-widget=resizes-content` 在 iOS Safari 上不生效。

## 已试过、无效的做法

- 在 `focusout`、`visualViewport.resize/scroll` 后延时 300ms 且「键盘已走」时执行 `scrollTo(0, 0)`。键盘收起时没有任何事件，条件不成立，没有效果，已还原。
- 以 `visualViewport` 作为应用高度（Pi 评审建议的方向）：因上述陈旧值未实施。

## 备选方向（均未实施）

- 键盘期间用 `scrollY` 推算多滚的量并抵消：没有可靠数据，可能忽大忽小，需要真机反复调试。
- 聚焦后使用固定在可见区底部的独立输入层：改动大，会改变输入体验。
- 做成原生壳（Capacitor 等）：键盘高度由原生层提供，可从根本上解决。

## 可能的回归线索

用户反馈比前一两天体验更差。同一时间窗口合入、与键盘或视口滚动相关的提交：

- `04126cdd0`：iOS 上给 viewport 追加 `maximum-scale=1`（`web/src/ios-focus-zoom.ts`）。
- `f93e851c5`：Lexical 0.49.0 补丁，改变光标露出时的视口坐标。

建议的对照实验：临时关闭 `preventIosFocusZoom()`，在真机多次「点输入框、收起、再点」对比；无改善则恢复，再单独对照 Lexical 补丁。

## 验收

必须在 iOS Safari 真机、实际访问地址上验证：地址栏各状态、键盘反复开关（含不失焦的收起和下滑收起）、中文候选栏、附件选择返回、长草稿光标移动、横竖屏、后台恢复。
