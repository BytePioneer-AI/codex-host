# Design

## Context

未提供注册检查时，Relay 用公钥派生的 26 位 ID 作为地址。注册成功后返回 `{ hostname }`，电脑端使用该主机名申请证书。`createRelay` 的可选接口允许部署者在签名验证后分配地址名和额度。

## Decisions

- **协议：** 电脑在回复挑战时（与公钥、签名放在同一个响应里），可以多带两个头：`relay-name`（想要的地址名）和 `relay-invite`（邀请码），都可以省略。注册成功时，Relay 仍回复 `{ hostname }`。拒绝时不发正文，直接用四个新的关闭码关闭连接：邀请码无效 4410、名字已被占用 4411、已被停用 4412、容量已满 4413。只用关闭码，是为了和现有的 4401/4408/4409 保持同一种处理方式，不新增消息格式。
- **额度通知：** 某地址达到当日额度时，Relay 在控制连接上向电脑发一个 `POST /v1/notice` 流，正文是 `{"quota":"exhausted","until":"<下一个 UTC 日 ISO 时间>"}`。旧版电脑会拒绝这个流，不影响其他功能。
- **核心接口：** `createRelay` 提供以下可选项：
  - `check(request)`：传入 ID、IP、地址名和邀请码。返回 `{ name, rate?, dailyQuota?, usedToday? }`，表示允许注册；或返回 `{ reject: "invite" | "name-taken" | "banned" | "full" }`，表示拒绝。检查抛错或超出 10 秒注册时限时，按注册失败关闭连接，电脑会自动重试。
  - `onUsage(name, bytes)`：在计数时报告每个地址名转发的增量字节数，计数口径与每日额度相同。
  - `onRequest(request, response)`：控制地址上不属于协议的 HTTPS 请求交给它处理，路径与响应由部署者自行定义。不提供时返回 404。WebSocket 升级路径与按地址名的 SNI 转发不经过该回调。

  另外，返回值增加 `disconnect(name)`。不提供 `check` 时，地址名就是 ID，限额来自启动参数。
- **按地址名索引：** 在线电脑、用量和替换逻辑都改为以地址名为键。部署者的检查函数保证一个名字只对应一个身份。同一名字的新注册仍会替换旧连接。SNI 改为接受任何合法的 DNS 标签，不再只接受 26 位 ID。检查返回的名字不是合法的 DNS 标签时，Relay 拒绝这次注册。如果内存中已有该名字当天的用量，以内存为准；没有时用 `usedToday` 作为起点。
- **电脑端保存：**
  - `service.json` 新增 `relayName` 和 `relayInvite`：点击启用时保存，每次注册都提交，由中转决定是否忽略。
  - 新增 `relayHostname`：保存最近一次取得的主机名，用来决定是否还显示输入框；`--relay` 改变时清除。
- **电脑端被拒处理：**
  - 收到 4410、4411、4412 时，把 `relayEnabled` 设为关闭，并在内存中记下原因，页面在关闭状态下显示该原因，直到用户下次启用。
  - 收到 4413 时，按普通断线处理并重试，页面显示"中转已满"。
  - 收到额度通知后，在 `until` 之前显示"今日流量已用完"。
- **名字格式：** 页面只接受 4–20 位小写字母和数字。核心只要求检查返回合法的 DNS 标签。

## Compatibility

- 不认识 4410–4413 的旧客户端按普通失败退避重试。
- 未提供 `check` 时，注册、地址和启动参数的行为保持不变。
