# Proposal

## Why

部署者需要在公钥身份验证之外控制注册、分配地址名和设置额度。Relay 核心提供可选扩展接口，电脑端提供对应的填写和提示；不提供扩展时仍使用公钥派生的 ID。

## What Changes

- 核心增加可选的注册检查：签名验证通过后，交给部署者决定是否允许注册、使用哪个地址名、限速和每日额度多少，以及当天已用流量。不提供检查时行为不变，地址名仍是公钥派生的 ID。
- 拒绝注册时，中转告诉电脑原因：邀请码无效、名字已被占用、已被停用、容量已满。
- 核心按地址名转发，并把每个地址名的转发字节数报告给部署者；部署者可以立即断开某个地址，对应电脑重连时重新检查。
- 某地址当天额度用完时，中转通知电脑。
- 注册协议增加两个可选字段：想要的地址名和邀请码。
- 核心允许部署者处理控制地址上的其他 HTTPS 请求，路径与响应由部署者自行定义。
- 电脑端：在"codexhost 中转"启用前可填写地址名（可选）和邀请码。被拒时显示原因；名字被占用、邀请码无效、已被停用时自动关闭中转，用户修改后可重新启用。容量已满时自动重试。额度用完时显示"今日流量已用完"。

## Decisions

- **核心只提供扩展接口。** `check` 决定是否允许注册及使用哪个地址名；身份与名字的唯一对应由部署者保证。不提供检查时，忽略提交的名字和邀请码，沿用公钥派生的 ID。
- **限额修改靠断开重连生效。** 部署者修改限速或额度后断开该地址，电脑会在几秒内重连，这时取到新值。核心不提供运行中修改限额的接口。
- **名字留空时由部署者分配。** 核心只要求检查返回合法的 DNS 标签。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `remote-relay`：增加注册检查、拒绝原因、按地址名转发、用量报告、断开地址和额度用完通知。注册协议增加可选的地址名和邀请码。
- `web-relay-access`：增加启用前填写地址名和邀请码，以及各拒绝原因和额度用完的显示与处理。

## Impact

- `packages/remote-relay`：注册流程、转发路由、协议常量和导出的 `createRelay` 选项。
- `packages/web-server/src/remote-relay`：注册时发送地址名和邀请码，处理新的拒绝原因和额度通知，保存待用的名字和邀请码。
- `packages/shared-contracts`：中转状态增加新的停止原因和额度提示。
- `apps/web-ui` 的连接设备页：中转启用前的输入框和提示文案。
