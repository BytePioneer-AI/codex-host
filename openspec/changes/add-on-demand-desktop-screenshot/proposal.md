# Proposal

## Why

用户需要从手机或另一台设备确认执行电脑当前显示的真实桌面，而无需建立持续投屏或远程控制。按需返回一张图片可以控制流量和实现范围，并与已有浏览器页面预览明确区分。

## What Changes

- Web 聊天提供「桌面截图」入口，主动请求当前连接电脑主屏的一张截图，在输入框附近展示，可放大、重新截图和关闭。
- 实现 Windows、macOS 采集适配；权限不足、没有可用图形会话及系统限制必须给出真实错误，不承诺锁屏或休眠时取图。Linux 暂不支持截图，不引入相关图形依赖或改变原有 Host/CLI 行为。
- macOS 未授权时在用户点击取图后主动申请系统授权；若仍未获准，尝试打开运行 Web 那台 Mac 的录屏设置页并说明手动授权、重试，不自动开启权限或轮询取图。
- 每次成功截图标明拍摄时间；重新截图替换旧图，失败保留的旧图明确标识为过期。
- 不自动采集、不持续推流、不记录截图历史、不附到草稿或发送给 Agent，不增加鼠标键盘控制。

## Decisions

- 截取运行当前 Web 服务的电脑，不按 Thread 的执行目录或 SSH 目标推断另一台电脑；此能力不依赖 Harness 或 Codex Desktop。
- 首版只取主屏，不引入显示器管理、窗口选择、录像、标注、自动刷新或原图/缩略图双份传输。
- 原生平台层负责采集，Web 负责访问校验与传输；优先复用维护中的跨平台采集实现，不自行扩展为远控系统。
- 截图依赖仅在 Windows、macOS 构建中启用，直接通过现有 Launcher 一次性取图，不增加独立程序或常驻服务。分别记录实际验证环境，未验证不能写成已通过。

## Capabilities

### New Capabilities

- `desktop-screenshot`: 用户主动获取连接电脑主屏的单张截图、查看时间、放大与替换，以及权限、图形会话、隐私和临时资源边界。

### Modified Capabilities

无。

## Impact

- `crates/platform`、`crates/launcher`：一次性系统截图能力及原生命令入口。
- `packages/web-server`：已认证、同源的取图入口和受限原生命令调用；复用打包 Launcher 的资源解析。
- `apps/web-ui/packages/client/ui-codexhost`：截图按钮和临时预览，复用已有输入框扩展点及图片查看组件。
- 采集库及其平台依赖、对应原生发行与 CI 构建条件；既有 Harness、Host 客户端通道和官方流量路径不变。
- `docs/product/standalone-web.md`：说明操作、三平台前提及不支持的环境。
