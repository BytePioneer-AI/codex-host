# Design

## Context

WebAssets 当前从固定内置清单或发行目录生成启动图。客户端使用真实 DSH 模块加载器，但任意插件激活失败会拒绝整个页面启动。此次仅实施方案中的安装、加载和恢复闭环。

## Decisions

- 在 Web 数据目录下保存独立扩展安装树和版本化记录；每个包使用隔离的安装目录，npm 安装明确关闭脚本、工作区和 peer 自动安装。记录文件损坏时禁止写入覆盖，恢复入口报告错误。
- 读取原包客户端元数据及产物；客户端依赖必须由内置平台、现有插件或显式安装的客户端插件提供，不导入 Host 入口自动补齐。
- WebAssets 合并外置记录，原生格式保持不变。正常启动装配失败时返回内置图并保留错误；`--safe-mode` 或 `?extensions=off` 仅加载内置插件。独立 `/extensions` 管理页不执行插件脚本。
- 安装默认关闭，启用与卸载变更在重启 Web 后生效。管理结果显示已装配 ID 而非假定浏览器执行成功。卸载先移除记录，运行中的旧页面需重启/刷新完成清理。
- 管理 RPC 使用现有本机认证判定和同源保护。浏览器安全 schema 仅定义界面扩展信息，不复用 Harness 执行 manifest。
- 适配 DSH 原有来源解析及安装弹窗，安装请求增加可选 registry URL。界面提供 npm 官方源、中国大陆镜像源和自定义源；只使用所选源，不自动将私有包名提交到其他源。
- npm 包名可省略版本，登记实际安装版本；GitHub 仓库只获取其归档，不执行 Git 包准备脚本。本机目录安装为独立快照，不使用指向用户目录的活动链接。来源扩展仍要求包包含可用的预构建客户端产物。

## Risks / Trade-offs

- 客户端包可能调用未声明服务 → 使用真实样本与浏览器验证，保留不执行第三方代码的恢复入口，不承诺脚本沙箱。
- 跳过 npm peers 不证明兼容 → 在启动图中检查可解析模块，禁止覆盖共享实例，记录包与宿主基线。
- GitHub 和目录来源可能只含源码 → 缺少预构建客户端产物时拒绝安装并说明原因，不通过运行构建脚本补齐。

## Migration

缺少扩展记录时等同无用户插件，不改变现有启动行为。启用状态按 Web 数据目录保存；回退旧产品版本会忽略这些新记录。故障时可通过独立管理页禁用，或以仅内置模式运行，不删除会话或配置。
