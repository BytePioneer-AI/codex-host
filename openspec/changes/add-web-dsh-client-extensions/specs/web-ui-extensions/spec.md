## Purpose

允许用户在独立 Web 中安装并启用经过兼容检查的原生 DSH 客户端发布包，通过独立管理和恢复入口处理插件故障，同时保持 Harness 执行、现有页面与用户数据的所有权。

## ADDED Requirements

### Requirement: 独立安装纯客户端插件

系统 SHALL 允许本机管理用户从 npm 包名（可带版本）、GitHub 仓库地址、本机绝对目录或本地预构建安装包安装界面扩展，保存实际包名、版本、格式和 Web 支持范围；获取和安装包及依赖时 MUST NOT 执行生命周期脚本或默认服务端入口。安装与启用 SHALL 分开，失败不改变已有可用记录。系统 SHALL 提供添加扩展弹窗和 npm 官方源、镜像源、自定义源选择，默认使用官方源。

#### Scenario: 安装本地原包
- **WHEN** 用户安装满足支持范围的客户端原包
- **THEN** 包保持未启用状态，显示实际身份和版本，且不需要修改源码或重建产品

#### Scenario: 安装不兼容包
- **WHEN** 包缺少支持的客户端入口或要求未提供的模块
- **THEN** 系统报告明确错误，不启用该包或破坏既有插件

#### Scenario: 直接输入包名和选择源
- **WHEN** 用户输入不带版本的 npm 包名并选择一个安装源
- **THEN** 系统通过该源获取包，保存实际安装版本，不要求用户手工查找版本号，不自动切换到其他源

#### Scenario: 安装 GitHub 或本机目录
- **WHEN** 用户提供包含预构建客户端产物的 GitHub 仓库地址或本机绝对目录
- **THEN** 系统保存独立安装副本，不执行准备或构建脚本，原目录后续变化不直接改变已安装客户端

### Requirement: 按持久启用配置装配 Web

系统 SHALL 持久保存每个插件的 Web 启用选择，重启 Web 后在源码与发行运行中加载启用的客户端原包，并提供其支持的资源。用户插件 MUST NOT 覆盖内置平台模块。启用选择和当前进程装配结果 SHALL 分别显示。

#### Scenario: 重启加载
- **WHEN** 已安装插件被启用且 Web 服务重启
- **THEN** 新页面展示其界面贡献，安装记录和选择仍保留

#### Scenario: 禁用恢复
- **WHEN** 用户禁用插件后重启 Web 并重新打开页面
- **THEN** 该插件不加载，内置界面可用且不保留该插件样式

### Requirement: 插件故障可恢复

系统 SHALL 提供不依赖第三方客户端运行的本机管理入口，以及只加载内置插件的页面或启动方式。静态装配失败 SHALL 保留启用选择并显示错误，不阻止内置界面启动；客户端运行异常 SHALL 提供到恢复入口的路径。

#### Scenario: 外部包损坏
- **WHEN** 启用插件的资源缺失或启动失败
- **THEN** 用户可进入独立恢复入口禁用该插件，并重新打开内置界面

### Requirement: 管理范围与执行边界

系统 MUST 在服务端限制扩展管理为本机管理访问；远程访问令牌不得执行管理操作。界面插件安装及启停 MUST NOT 改写 Harness 插件目录、DSH profile 或启动额外 Agent Runtime。当前支持目标 SHALL 仅为 Web，不宣称 GUI 兼容。

#### Scenario: 远程请求管理
- **WHEN** 已登录的远程浏览器请求安装或启停扩展
- **THEN** 服务端拒绝操作且保留原状态
