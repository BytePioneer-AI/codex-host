# Claude Code Adapter语义调查结论

## 1. 结论摘要

本次调查支持把官方`@anthropic-ai/claude-agent-sdk`作为后续最小`ClaudeCodeAdapter`的唯一首选结构化边界，并通过`pathToClaudeCodeExecutable`使用用户安装的Claude Code。当前实测配对是Agent SDK `0.3.220`与Claude Code `2.1.220`；SDK包清单也声明`claudeCodeVersion: 2.1.220`。

技术结论是**有条件进入最小契约实现**，不是宣布Claude Code产品支持。条件如下：

1. 等并行的HarnessAdapter Tool/Cancel公共契约落地后，先rebase并逐项对照本记录。
2. 后续Change只实现`create/text/tool/cancel/fault/close`及其必要Interaction桥接，不接Renderer路由、Mapping Store、一级Thread、发布打包或公开MVP。
3. 在正式发布前单独完成Anthropic法律条款、第三方OAuth资格、程序化使用计费和二进制重新分发决策。
4. 全量Live Gate已经在恢复OAuth认证后复跑通过；仍不得从SDK类型或Paseo推断其他平台及未覆盖边界。

## 3. 场景结果

| 场景 | 结果 | 已确认事实 |
| --- | --- | --- |
| SDK/CLI安装与版本 | PASS | SDK `0.3.220`与CLI `2.1.220`配对；用户安装命令来自PATH；未把绝对路径写入报告 |
| 无Prompt预热 | PASS | `startup()`前、预热中、关闭后均无可恢复空Session；拥有1个直系Claude进程且有界退出 |
| 设置源与认证 | PASS | `[]`失去OAuth并产生认证异常，`["user"]`通过同一用户安装的Claude完成真实Turn；认证异常会被分类为环境BLOCKED而非安装或协议失败 |
| 单Query双Turn | PASS（初始本地Capture） | Session ID稳定；每Turn各有一个Result；调用方User UUID进入原生历史且顺序稳定 |
| Result终态冲突 | PASS（初始本地Capture与Hermetic测试） | 观察到`subtype=success`同时`is_error=true`、`terminal_reason=api_error`；不得只看`subtype` |
| 未知原生事件 | PASS（初始本地Capture与Hermetic测试） | 当前CLI曾发出SDK导出`SDKMessage`联合未声明的`command_lifecycle`；未知事件必须开放处理 |
| 跨进程Resume | PASS（初始本地Capture） | 新SDK进程继续同一Session；已有消息UUID不变；历史追加而非重写 |
| 精确Fork | PASS（初始本地Capture） | `forkSession(upToMessageId)`创建新Session、在选定Assistant上下文截止、来源不变、派生消息UUID全部重映射 |
| Read/Edit与Approval | PASS（初始本地Capture） | Tool Use ID关联Tool Result；`canUseTool`提供Tool Use ID、独立Request ID、AbortSignal和建议结构 |
| Edit File Change | PASS（初始本地Capture与Hermetic测试） | Edit结果提供`originalFile`和`structuredPatch`；非Git目录不保证`gitDiff.patch`；原生hunk可确定性序列化并重放到LF/CRLF文本 |
| AskUserQuestion | PASS（初始本地Capture） | 同样经过`canUseTool`，但语义是Question；答案对象必须用完整问题文本作为键 |
| 运行中Bash Interrupt | PASS（初始本地Capture） | `interrupt()`后约数十毫秒得到`error_during_execution/aborted_tools`；子进程退出、完成副作用未发生；同一Query/Session可继续下一Turn |
| Tool Progress | NOT OBSERVED | 多次长Bash均未收到`tool_progress`；只能作为可选更新，不能作为Tool开始或完成依据 |
| Streaming Interrupt | PASS | 首个partial streaming event后调用`interrupt()`，native Result收敛为`aborted_streaming`，Session匹配且只有一个Result |
| Pending Interaction Cancel | PASS | `canUseTool`只触发一次；Interrupt使回调AbortSignal触发并收敛，native Result为`aborted_tools`且没有重复终态 |
| 跨平台进程树关闭 | BLOCKED | 仅在当前darwin-arm64验证直系进程和受控Bash子进程；Windows、MCP及更深后代进程未验证 |

所有真实运行时Prompt/模型正文、Tool输入/输出、完整Session/Message/Tool/Request UUID、本地绝对路径、账号字段与原始Transcript只存在于Git忽略目录；版本控制中只有Gate源代码所需的固定合成指令和固定隐私反例。表中结论来自人工检查后的布尔值、计数、枚举和版本，不由工具自动复制Raw Capture生成。

## 4. 对HarnessAdapter公共语义的反馈

这些反馈应在Tool/Cancel变更合入后做对照，不在本Change中编辑公共契约。

### 4.1 Session与Turn身份

- 可以由Host预分配Session UUID并传给首个Query，但只有收到native init/消息并在官方历史API中可见后才发布为Native Session Ref。
- SDK接受调用方User Message UUID，且当前历史/Resume保留它，可作为Native Turn Ref候选。
- 一个长期Query可承载多个顺序Turn；不要为每个Turn创建Session。
- Fork会重映射派生Session的全部消息UUID，因此来源Checkpoint不能直接成为派生Session的Native Turn Ref。

### 4.2 Turn终态

- Turn成功必须联合`subtype`、`is_error`、`terminal_reason`、Assistant error与本地cancel状态。
- `subtype=success`不是充分条件。
- `interrupt()`返回只表示控制请求已处理，不是Host Turn终态；必须继续等待native Result。
- Adapter必须保证每个已接受Turn只产生一个Host终态，并在此之前关闭所有Tool和Interaction。

### 4.3 Tool与File Change

- Tool主关联键是native Tool Use ID；Permission control Request ID是另一条控制面身份，不能混用。
- `tool_progress`可缺失，Tool Result或取消/Turn终态才是收敛依据。
- Edit/Write只在成功native Tool Result提供可靠Patch/structuredPatch时产生File Change。
- 若Codex投影需要Unified Patch，可确定性序列化SDK原生hunk；不得从`old_string/new_string`、Git、文件监听或前后快照推断。
- 缺少可靠变更数据时保持Generic Tool，不伪造File Change。

### 4.4 Interaction

- 普通Tool Permission Callback是Approval候选；`AskUserQuestion`是Question，即使两者都通过`canUseTool`。
- Host Interaction ID、native Tool Use ID和native control Request ID必须分别保存和关联。
- `PermissionUpdate.destination`只能作为能力事实；除非产品能忠实执行对应作用域，否则不能直接转成“始终允许”等Host动作。
- Pending Interaction取消已确认通过回调AbortSignal收敛，并且每个Turn只产生一个native Result。

### 4.5 Process与Close

- 产品Adapter应使用`spawnClaudeCodeProcess`接管进程创建，并复用平台层的有界进程树监督。
- `Query.close()`是Session关闭动作；运行中Turn取消使用`Query.interrupt()`并等待Result。
- 仅验证直系进程退出不足以证明Windows、MCP Server或任意Tool后代全部清理。

## 5. 后续最小ClaudeCodeAdapter建议

1. 新建独立`packages/adapters/claude-code`所有者，不把SDK放入HarnessAdapter或Host Runtime。
2. 依赖官方Agent SDK，显式传用户安装的Claude可执行文件；Raw CLI stream-json仅保留诊断用途。
3. `createSession()`只创建惰性Host对象或无副作用WarmQuery，不持久化空Native Session。
4. 每个Host Session维护一个顺序消费的SDK Query、Session UUID、User UUID到Native Ref映射、Tool/Interaction关联表和受监督进程句柄。
5. SDK消息先经过运行时结构校验与开放的unknown分支，再投影为UI无关HarnessAdapter Event。
6. Result分类、structuredPatch序列化、Question/Approval分流和cancel收敛复用本Gate的Hermetic规则，但生产代码应归属具体Adapter包而非`tools/`。
7. Resume/Fork只调用官方Session API；不扫描用户其他Session，不修改native JSONL，不建立第二份标准Transcript，不调用文件rewind。
8. 第一阶段不注册Renderer、Host Agent目录、Mapping Store或发布包；用Fake contract tests和受控Claude Adapter测试验证公共契约。

## 6. 未验证与明确不支持

- 未验证稳定的Session idle事件；当前以Result作为Turn终态输入。
- 未验证重试、多Assistant消息、Compaction或无模型Turn时最合适的Assistant Checkpoint选择。
- 未验证所有Assistant error枚举和`success + is_error`组合。
- 未验证persistent Permission更新的每个destination及其跨进程效果。
- 未验证多文件Patch、二进制文件、重命名和所有CRLF边界；Hermetic测试只证明确定性文本hunk转换。
- 未验证Windows/macOS完整进程树、MCP进程和强制关闭升级路径。
- 不支持把SDK file checkpoint/`rewindFiles()`当作codexhost会话Fork。
- 不支持把Claude Code加入当前公开Pi MVP。

## 7. 法律、分发与计费

官方Agent SDK `LICENSE.md`写明“Use is subject to the Legal Agreements”，并指向Claude Code法律与合规页面；`README.md`还引用Commercial Terms、Privacy Policy和数据使用说明。包中包含按平台分发的可选Claude二进制，但“技术上可安装”不等于codexhost已获得重新分发结论。

Paseo公开文档中的第三方SDK、OAuth和计费提醒只能作为风险线索，不能作为Anthropic政策事实源。本Change不判断下列问题：

- codexhost是否可让第三方产品使用用户Claude订阅/OAuth；
- 程序化Agent SDK使用采用订阅、API或其他计费来源；
- 是否可在codexhost安装包中重新分发SDK或Claude Code二进制；
- 应展示哪些数据使用、隐私和用户同意文案。

这些问题必须在产品宣称支持、发布打包或用户测试前由最新官方条款和必要的法律/商务确认单独关闭。
