# 已运行Desktop附加验证结论

- 验证平台：Windows x64
- Codex Desktop：`26.727.6591.0`
- Change：`attach-running-codex-desktop`
- 当前结论：受控实例复用已实现；独立官方实例不进入动态附加，要求完全退出后重试

## 受控实例事实

当前本机受控进程链确认包含一个Desktop根、随机loopback Node Inspector、Desktop Controller、Shim、Host Runtime和官方app-server。拥有Launcher只在完整链ready后发布最小Controller端点；第二个Launcher依靠实例锁和一次nonce握手请求现有Controller恢复Renderer并激活窗口，不重复验证Desktop PID、Inspector或Shim/Host后代，也不创建第二套Desktop、Controller或Host。

## 真实用户行为矩阵

本轮直接使用最新构建的`codexhost.exe`和官方开始菜单App Activation操作真实Codex Desktop，不调用Rust、TypeScript或Mock测试入口。

| 用户行为 | 结果 | 进程事实 |
| --- | --- | --- |
| 先启动纯官方Codex，再启动codexhost | 当前生产路径约0.86秒返回完全退出提示；旧bootstrap约12秒`BLOCKED`的证据促成删除 | 原Desktop根保持；未留下Launcher、Controller、Shim或Host |
| 没有Codex时启动codexhost | `PASS` | 一个Desktop根、一套Launcher/Controller/Shim/Host；最小描述符发布 |
| 受控Codex运行时再次启动codexhost | `PASS`，约29毫秒返回 | Desktop根不变；所有运行时进程计数不变 |
| 受控Codex运行时再次点击官方Codex | `PASS` | Windows激活同一Desktop根；sidecar不变 |
| 快速并发启动两个codexhost | `PASS`，两个Launcher均返回0 | 仍只有一个Desktop根和一套运行时 |
| Launcher与Desktop异常终止后再次启动codexhost | `PASS` | 真实残留描述符被替换，新受控实例ready |
| 用户激活Codex并按`Ctrl+Q` | `PASS` | Desktop、Launcher和Controller退出；描述符删除 |

首次clean launch实测曾发现Host链已实际存在，但Windows进程路径一边带`\\?\`verbatim前缀、另一边不带，导致Launcher误判Node后代不存在。平台路径身份比较统一移除verbatim前缀并按Windows大小写规则比较后，同一真实场景重跑为`PASS`。

`Ctrl+Q`实测确认Desktop、Launcher、Controller和描述符均完成清理，同时暴露Controller可能先于Desktop被观察到退出、导致Launcher将正常退出记录为code 1的竞态。Launcher现对该顺序保留1秒Desktop退出观察窗口；若Desktop正常退出则返回成功，只有Desktop仍运行才报告Controller故障。该分类修复已通过真实退出事实和聚焦进程测试，完整二次实测因工作区另一个Renderer Binding Gate占用唯一Desktop实例而未强制争用。

## 未受控实例Probe

Probe只对已运行Desktop执行二次激活，不终止Desktop、app-server或Controller，不发送Prompt，也不记录PID、端口、命令行、环境、Thread ID或用户数据。

| 方式 | 同一Desktop根保持 | 新调试端点 | 结论 |
| --- | --- | --- | --- |
| `ApplicationActivationManager` +随机`--inspect` | 是 | 否 | `BLOCKED` |
| `ApplicationActivationManager` +随机`--remote-debugging-port` | 是 | 否 | `BLOCKED` |
| 直接执行Desktop +随机`--inspect` | 是 | 否 | `BLOCKED` |

App Activation返回瞬时激活进程而不是现有Desktop根PID，但没有创建第二个持久Desktop根。三种方式等待10秒后均没有得到新端点，原Desktop根始终存活。

## 影响

当前Windows Codex build不能通过CodexPlusPlus式二次启动参数为已运行实例补开Node Inspector或Chromium CDP。因此未受控实例无法进入后续主进程环境设置、app-server重建和生产Renderer安装步骤；本Change不得声明完整未受控附加已实现。

生产Launcher已删除App Activation、临时Inspector/CDP和附加Controller路径。检测到独立官方实例时立即提示用户完全退出后重试，保留原Desktop，不安装外部Agent控件，也不启动第二套Controller或Host。由codexhost正常启动且发布了有效运行描述符的实例继续通过nonce握手恢复Renderer readiness并激活窗口。

## 解除条件

以下任一事实可解除阻塞：

1. Codex Desktop提供受支持的运行期Inspector/CDP启用入口；
2. Codex Desktop提供受支持的Extension或主进程控制接口，可在不重启Desktop的情况下重建app-server；
3. 后续Desktop build真实证明二次App Activation参数会应用到现有根进程。

不采用DLL/远程线程注入、UI自动化DevTools Console、修改`app.asar`或全局环境作为解除方案。
