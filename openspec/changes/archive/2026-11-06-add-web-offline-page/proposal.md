# Proposal

## Why

经中转访问时，电脑离线后 Relay 拿不到证书，只能断开连接，手机浏览器显示自己的“无法连接”错误页，用户分不清是网络问题、地址错了，还是电脑没开。Tailscale Funnel 和自备隧道在电脑离线时也是同样的情况。已打开的页面有“电脑离线”提示；新打开或刷新页面时还没有。

## What Changes

- 现有的 `sw.js` 增加对页面导航的处理：先走网络；网络失败、10 秒内没有响应，或网关返回 502/503/504 时，返回 `sw.js` 内置的离线页。
- 离线页说明无法连接电脑（手机没网时说明网络已断开），提供重试，并在电脑恢复后自动重新加载。
- Service Worker 已在每次打开界面时注册，不需要改注册方式。

## Decisions

- **内置离线页，不缓存前端。** 浏览器本地只保存草稿和偏好，会话列表和历史都在内存中，没有可以离线浏览的内容；启动完整界面后能显示的仍只是“电脑离线”。另外，前端壳由插件在运行时组合，资源地址带版本号，缓存它要处理版本更新和插件变化。内置一个离线页能达到同样的效果，而且不需要 Cache Storage，与版本更新无关。
- **只处理页面导航。** 接口、WebSocket 和静态资源的请求照常走网络，不经过离线页。已打开页面的离线提示仍由现有的连接状态处理。
- **离线页不加载任何外部资源。** 样式和文案都写在 `sw.js` 里，浅色和深色主题都适配，中文或英文按浏览器语言选择。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `web-remote-access`：新增“电脑离线时打开页面”的要求。

## Impact

- `apps/web-ui/apps/web/public/sw.js`
- 浏览器测试：`packages/web-server/test/browser/`
- 文档：`docs/product/web-remote-access.md` 中关于离线页的说明
- 局域网 HTTP 入口不是安全上下文，没有 Service Worker，所以不受影响。首次访问时电脑必须在线。
