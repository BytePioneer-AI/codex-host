# Proposal

## Why

电脑为自己的 `<id>.<中转域名>` 自动申请和续期证书，让手机可以经 Relay 建立 TLS 连接。没有可用证书时，电脑只应答本轮证书验证，关闭普通手机连接。

## What Changes

- 注册成功后，电脑在没有可用证书时向 Let's Encrypt 申请，用 TLS-ALPN-01 验证：验证连接经 Relay 转发到电脑，电脑用挑战证书应答。证书私钥和 ACME 账户私钥都在本机生成和保存。
- 证书在实际有效期过去 2/3 后续期，沿用原证书私钥；Web 运行期间每小时检查一次，启动和重新注册时也检查。新证书装好后立即生效，不重启 Web。
- 失败后按递增间隔重试，基准间隔最长 24 小时，抖动只向后推迟，并且不早于证书机构要求的等待时间；重试时间保存到磁盘，重启不清零。验证连续失败两次或被 CAA 拒绝时，停止申请并显示原因。
- 证书机构的请求和控制连接一样经 `HTTPS_PROXY`。
- 连接设备页按手机能否访问显示状态：准备中、已开启、暂时无法使用（附重试时间）、需要处理（申请暂停）。证书本身不作为单独状态展示。
- 没有正式证书时，电脑仍应答证书验证连接（ALPN 为 `acme-tls/1`），其他连接照旧关闭。

## Decisions

- **使用 `acme-client`（MIT）。** 通过账户、下单、挑战和下载证书接口实现 RFC 8555 与 TLS-ALPN-01 流程。
- **不实现 ARI（RFC 9773）。** 不用 ARI 时，同一主机名的续期本来就不占“新订单数”和“同域名每周新证书数”这两项限额，只受“同一组名字每周 5 张”和失败次数限制。每台电脑约两个月续期一次，碰不到这些限额。Let's Encrypt 认可按有效期 2/3 续期。
- **续期时机按证书实际有效期计算，不写死天数。** Let's Encrypt 默认有效期将从 90 天缩短到 64 天（2027-02）和 45 天（2028-02）。
- **每台电脑一个 ACME 账户，账户私钥只在本机，持久复用。** 账户私钥放在 Relay 上，Relay 就能以这个账户申请证书；所有电脑共用一个账户，一台电脑泄露就会波及全部。
- **续期沿用证书私钥，只替换证书文件。** 这样更新只涉及一个文件，可以原子替换，不需要设计两个文件同时切换的机制。
- **不加跨进程文件锁。** 只有当前注册的进程申请证书，注册失效就作废进行中的一轮。被替换时同一数据目录上的两个进程可能短暂重叠：私钥排他创建，证书是同一主机名、同一私钥，原子替换；失败记录的等待时间合并取较晚者，最坏只丢一次失败计数、提前一档重试一次。
- **不解析错误文字。** 失败分类只看结构化字段：authorization 终态、problem 类型、`Retry-After`。`acme-client` 会把错误响应转成只有文字的 `Error`，所以关闭它的库内重试，用它公开的 axios 实例记录响应。
- **不做备用证书机构的自动切换。**
- **不做 CAA `accounturi`。** 每台电脑账户不同，要给每个子域写 DNS 记录，而且挡不住控制 Relay 的一方。
- **证书机构地址可用环境变量 `CODEXHOST_RELAY_ACME_DIRECTORY` 覆盖。** 默认是 Let's Encrypt 生产环境。真实环境验收要先用 Let's Encrypt staging，自动化测试要用本地 Pebble，所以这个覆盖确实需要。

## Capabilities

### New Capabilities

- `web-relay-certificates`：电脑端为中转地址自动申请、续期、保存证书，失败处理和状态显示。

### Modified Capabilities

- `web-relay-access`：没有正式证书时仍应答证书验证连接；连接设备页显示证书状态。

## Impact

- `packages/web-server`：新增证书管理模块（`src/remote-relay/` 下），扩展进程内 TLS 以应答 `acme-tls/1`；新增依赖 `acme-client`。
- `packages/remote-relay`：增加 ClientHello 解析的公开导出，电脑端复用它读取 ALPN。
- `packages/shared-contracts`、`apps/web-ui`（`ui-codexhost`）：证书状态。
- 新电脑首次申请受证书机构对同一注册域名的新证书限额约束，部署者需参考 [Let's Encrypt 速率限制](https://letsencrypt.org/docs/rate-limits/)。
- 证书会进入公开的证书透明日志，中转地址因此是公开的；访问安全依赖 token，不依赖地址保密。
