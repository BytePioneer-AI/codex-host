# Design

## Context

范围见 proposal。当前 Web 启动时把可选 `relayHost` 传给 `RemoteRelay`，该对象不支持动态地址；未配置时不返回中转状态。`RelayControl.tsx` 不区分官方和自建。证书文件路径固定，加载时校验域名，签发记录按域名与 ACME directory 区分；仅校验域名无法保证更换控制地址后绝不沿用旧证书。

## Decisions

- Web 服务端定义官方地址常量。官方与自建是两种平级页面方式，共享一个中转连接实例；访问状态提供官方地址、保存的自建地址、当前选择类型与启用开关，前端按类型呈现状态与扫码，避免另一张卡片误显示当前地址；访问状态不包含身份密钥的本机绝对路径。
- 保留 `relayHost` 为自建地址，增加 `relayKind` 记录当前类型；旧配置缺少 relayKind 时，地址为 relay.chost.dev 或未配置地址均按官方读取，其余地址按自建读取；识别旧官方文件不改写配置、不清除分配地址或证书，不要求用户重新注册。`--relay` 仅预填或覆盖自建地址，不改变官方地址或显式选择的类型；空值清除自建地址。扩展 `codexhost/relaySet` 接受类型与控制地址，地址只允许自建类型。页面只接受 DNS 主机名，不接受协议、端口、路径、IP；前后端同语义校验，CLI 保留带端口开发地址支持。
- 配置修改继续走本机鉴权。保存地址时必须已关闭中转，即使请求同时传关闭也不隐式切换；开启状态由持久化开关判断，包含连接中与已停止但仍开启的状态。相同有效地址不触发清理。自建关闭时填写主机名，启用请求同时保存地址，不设单独保存按钮；开启后只读展示控制地址，切换到另一卡片时才提示先关闭当前中转。
- 地址改变时清除 `relayHostname`、旧注册字段、旧额度提示、证书文件和证书签发记录，清空内存证书状态。保留身份密钥、ACME 账户和证书私钥；证书私钥不等于证书，可继续用于新申请。CLI 改址采用同一清理语义，防止重新启动后加载旧证书。
- 官方且未分配地址时才显示和提交名字、邀请码；自建使用通用说明并显示控制地址，不向自建服务器发送官方邀请码。切回官方时重新填写注册字段。
- 两张卡片与现有方式共用摘要和选择交互；自建详情复用中转状态与扫码组件，状态与开关之后紧跟访问地址和复制链接，末尾以 details 展示双语教程：未配置时展开、有控制地址后折叠；先准备域名与装有 Docker Compose、certbot 的 Linux 服务器，再 git clone 公开仓库，之后配置两条 DNS（Cloudflare 仅 DNS）、443/80、申请控制证书、Docker 构建与 Compose 启动、回页面填地址并启用。身份说明只写数据目录中的 remote-relay/identity.pem，不展示本机绝对路径。链接到公开仓库 main 分支的完整自建文档；不新增向导或额外确认流程。
- 保持单一中转实例和现有启停路径，修改运行中的目标地址后下一次启用直接连接新目标，不重启 Web 或 Host。

## Risks / Trade-offs

- [换址后即使切回旧服务也需要重新准备证书] → 选择明确隔离而非多套缓存，不新增中转列表或复杂缓存管理。
- [保留 CLI 开发端口与页面校验不同] → 文档明确页面只接收主机名，CLI 仅为兼容性补充；分别测试。
- [官方测试可能访问正式服务] → 官方注册使用受控替身，自建注册使用现有本地 Relay 与 ACME fixture，所有测试隔离数据目录和端口。

## Migration

既有 `relayHost` 与开启状态沿用；未显式保存类型且地址为官方域名时按官方读取，分配地址、证书、名字及邀请码保持不变。未保存地址时默认官方但保持关闭。`--relay ""` 清除自建地址，不改变官方卡片；若当前自建开启则拒绝清除，需先在页面关闭。文档明确 CLI 仅覆盖自建地址。增量规格在实施时同步到主规格，保留未修改需求和场景。回滚代码前须关闭中转；清除的分配地址与证书不恢复，身份密钥保留。
