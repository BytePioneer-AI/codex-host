# Spec Delta

## MODIFIED Requirements

### Requirement: 中转设置

本机连接设备页 SHALL 始终列出平级的“codexhost 中转”与“自建中转”方式，官方地址固定 `relay.chost.dev`，默认关闭。自建卡片 SHALL 在关闭时输入控制主机名，点击启用同时保存并连接，不设独立保存按钮；前后端拒绝非法主机名。开启后 SHALL 只读显示控制地址，不显示编辑框或改址提示，访问地址和复制链接紧跟状态与开关。保存与启停即时生效，不重启 Web 或 Host。同一时间 MUST 只开启一个中转，切换类型或地址前须关闭。选择卡片不启用；可单独关闭，“停止设备访问”也关闭它。设置只允许本机修改且重启沿用。`--no-auth` MUST 拒绝开启。`--relay` SHALL 仅预填或覆盖自建地址，空值清除自建地址，不改变官方卡片。

#### Scenario: 未配置控制地址

- **WHEN** Web 启动时没有保存过控制地址
- **THEN** 本机连接设备页显示官方与自建两种方式，官方使用 `relay.chost.dev`，自建尚未配置，Web 不连接任何 Relay

#### Scenario: 开启中转

- **WHEN** 用户在本机选择 codexhost 中转并点击启用
- **THEN** Web 开始连接当前 Relay，运行中的任务和已连接的浏览器不受影响

#### Scenario: 未启用认证

- **WHEN** Web 以 `--no-auth` 运行，且保存的设置是开启中转
- **THEN** Web 不连接 Relay，开启中转的接口返回明确的错误

#### Scenario: 手机尝试开启或关闭中转

- **WHEN** 经中转或局域网访问的页面调用开启、关闭或修改控制地址的接口
- **THEN** 接口拒绝，设置不变

#### Scenario: 页面保存自建地址

- **WHEN** 中转关闭，用户展开独立的“自建中转”卡片，填写 `relay.example.com` 并点击启用
- **THEN** 同一请求保存并按该地址注册，Web 和 Host 不重启；开启后控制地址只读，关闭后恢复编辑

#### Scenario: 非法控制地址

- **WHEN** 页面输入或设置接口收到带协议、端口、路径、用户信息、空白、IP 或不合法 DNS 标签的控制地址
- **THEN** 页面提示主机名格式错误，服务端拒绝保存，原设置不变

#### Scenario: 开启时更换地址

- **WHEN** 任一中转仍处于开启状态，用户试图更换控制地址或启用另一个类型
- **THEN** 页面要求先关闭中转，接口拒绝直接更换且不改变现有连接与设置

#### Scenario: 关闭后更换地址

- **WHEN** 用户关闭中转后保存不同的控制地址
- **THEN** 旧分配主机名和证书不再沿用，电脑身份密钥不变，旧额度提示不出现在新中转上

#### Scenario: 切回官方中转

- **WHEN** 用户选择官方卡片，而自建中转仍开启
- **THEN** 官方卡片要求先关闭自建中转，当前使用标识仍在自建卡片；关闭后才可启用固定地址 `relay.chost.dev` 的官方中转

#### Scenario: 命令行覆盖

- **WHEN** 开发者通过 `--relay localhost:4498` 启动或通过 `--relay ""` 清除覆盖
- **THEN** 分别覆盖或清除自建控制地址，官方卡片仍固定 `relay.chost.dev`，显式保存的当前类型不变

#### Scenario: 旧官方配置无损识别

- **WHEN** 旧配置未保存中转类型、控制地址为 `relay.chost.dev`，且中转已经启用
- **THEN** 按官方类型展示为当前使用，保留已分配地址、证书和注册字段；用户无需重新启用或重新提供注册信息，正常启动连接继续提交原名字与邀请码

### Requirement: 身份密钥

首次开启中转时，Web SHALL 生成身份密钥，保存在数据目录中只有当前用户可读的文件里，之后的重启和更新 MUST 沿用同一密钥。私钥 MUST NOT 离开这台电脑。访问状态 MUST NOT 返回身份密钥的本机绝对路径。连接设备页 SHALL 简述身份密钥用于保持地址不变、不可删除或分享，位置以本机数据目录中的 `remote-relay/identity.pem` 表示，MUST NOT 显示完整本机绝对路径；密钥丢失或删除后地址会改变且无法找回。

#### Scenario: 更新后地址不变

- **WHEN** 升级 codexhost 后重新开启中转
- **THEN** 注册得到的地址与升级前相同

#### Scenario: 删除密钥

- **WHEN** 用户删除密钥文件后重新开启中转
- **THEN** Web 生成新密钥，得到新的地址，旧地址不再可用

### Requirement: 地址名与邀请码

官方中转尚未分配地址时，连接设备页 SHALL 在启用按钮前提供地址名（可选）与邀请码。地址名只接受 4–20 位小写字母和数字，留空由中转分配；启用时保存两项并在注册时提交。取得地址后 MUST 隐藏输入框，同一身份沿用原地址、不能改名。自建中转 MUST 不显示或提交名字和邀请码。中英文说明 SHALL 区分官方与自建，自建显示当前控制地址且不得称为官方；隐私文案 SHALL 限定为正常转发时不解密内容，不承诺中转方绝对无法读取。

#### Scenario: 填写名字和邀请码启用

- **WHEN** 用户在官方中转填写地址名 `alice` 和有效邀请码后点击启用
- **THEN** 注册成功后连接设备页显示 `https://alice.<域名>`，输入框不再出现

#### Scenario: 名字留空

- **WHEN** 用户在官方中转只填写邀请码就点击启用
- **THEN** 中转分配地址名，页面显示分配到的地址

#### Scenario: 关闭后再启用

- **WHEN** 已取得地址的用户关闭中转后再次选择同一个 codexhost 中转
- **THEN** 页面不显示输入框，启用后沿用原地址

#### Scenario: 自建中转展示

- **WHEN** 展开控制地址为 `relay.example.com` 的自建卡片
- **THEN** 中英文界面显示自建中转与该地址，不出现官方说明、地址名或邀请码输入框，注册不携带官方注册字段；开启后展示当前使用标识、状态与扫码入口

## ADDED Requirements

### Requirement: 自建中转教程

自建卡片 SHALL 展示简短中英文教程及公开仓库默认分支的完整自建文档链接，教程未配置时 SHALL 展开，有控制地址后 SHALL 收起为可展开的“如何搭建自己的中转”，排在访问地址之后。内容与文档一致：先准备自己的域名及装有 Docker Compose 和 certbot 的 Linux 服务器，再用一行 git clone 命令获取公开仓库源码，然后配置控制与电脑通配两条 DNS、Cloudflare 仅 DNS、服务器放行 443 与申请控制证书所需 80、先申请控制证书再按仓库 Dockerfile 构建与 Compose 启动、回页面填写地址。没有域名时 SHALL 建议官方中转或 Tailscale。

#### Scenario: 尚未配置自建中转

- **WHEN** 用户展开未配置的自建卡片
- **THEN** 页面同时显示主机名输入框与展开的简短部署教程，不要求命令行配置电脑端，不显示名字和邀请码

#### Scenario: 已配置自建中转

- **WHEN** 用户展开有控制地址的自建卡片
- **THEN** 教程默认折叠为一行，可手动展开；已开启时访问地址和复制链接在状态与开关之后、教程之前
