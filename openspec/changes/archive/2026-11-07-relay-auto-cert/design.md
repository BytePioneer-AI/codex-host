# Design

## Context

控制地址的 SNI 在中转终止 TLS，电脑地址仍按原协议转发。Web 包已有 acme-client 使用方式及本地 ACME 测试替身，但中转必须可独立构建。

## Decisions

- 中转增加精简证书管理模块，直接依赖 acme-client，不从 web-server 引入实现或新增共享包。边界检查仅增加该依赖白名单。
- 控制地址的 `acme-tls/1` 连接使用临时验证证书，普通连接使用正式证书；首次签发前拒绝普通连接。电脑地址验证流量仍转发。
- 数据目录默认 `./data`，可用 `--data-dir` 指定；容器使用 `/data`。保存账户私钥、证书私钥和证书，私钥权限 0600，证书原子替换。
- 每 15 分钟检查，在实际有效期的 2/3 处续期；失败保留可用证书，下一次检查重试。不保存失败状态，重启后需要签发时立即重试。
- Compose 以仓库根目录为构建上下文，命令只有域名，持久卷由镜像初始化为非 root 用户可写。容器与公网均使用 443，通过容器网络设置允许非 root 监听。

## Risks / Trade-offs

- DNS、CAA 或公网 443 不通会导致签发失败 → stderr 提示，后台重试；不回退到 HTTP 验证。
- Let's Encrypt 频率限制 → 复用密钥和有效证书，保留数据卷，提醒不要反复删除数据。

## Migration

已有部署保留显式控制地址和 `--cert/--key`，继续通过 SIGHUP 加载。自建 Compose 改用自动证书时移除外部证书挂载，保留数据卷。回滚自动证书部署时需显式提供已有证书路径。
