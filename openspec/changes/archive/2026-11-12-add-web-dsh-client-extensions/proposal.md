# Proposal

## Why

Web 已保留 DSH 客户端运行机制，但用户无法安装外部发布包。先用一个真实纯前端插件跑通安装、加载、禁用和故障恢复，为界面扩展方案建立可验证的起点。

## What Changes

- 增加独立的 Web 界面扩展安装记录，支持 npm 包名、GitHub 仓库、本机目录和预构建安装包，可选择官方、镜像或自定义 npm 源；保存实际安装版本，安装不执行脚本。
- 加载已启用的 DSH 客户端原包，支持源码和发行运行；缺依赖和资源错误不覆盖内置插件。
- 提供本机管理入口和独立恢复入口，保存启用状态并显示重启后的实际装配情况。
- 复用 DSH 安装来源解析与添加插件弹窗的独立代码，接入 Web 自有安装与兼容校验，不引入 DSH 后端插件运行时。
- 用真实发布包验证安装、重启加载和禁用恢复，并补回归测试与使用文档。

## Decisions

- 此变更是第一期的最小闭环：先支持不需新增后台服务、配置或主题选择器的客户端包，完整第一期能力继续以界面扩展方案为准。
- DSH 原包不改写；保留格式、支持目标与启用目标信息，当前仅支持 Web。Harness 与 GUI 扩展运行时保持现有边界。
- 重启 Web 后应用启用配置；恢复入口在仅加载内置插件的页面之外也可用，不依赖第三方插件成功启动。

## Capabilities

### New Capabilities

- `web-ui-extensions`: Web 客户端插件的安装、装配、启停与恢复。

### Modified Capabilities

无。

## Impact

影响 Web 服务端、DSH 客户端启动和 codexhost 设置入口、浏览器安全的管理契约及 Web 发行验证。插件状态存储于 Web 数据目录，不修改 Harness 插件或用户 DSH profile。
