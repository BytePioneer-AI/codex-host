# Spec Delta

## Purpose

升级 codexhost 后，在 Desktop 和 Web 中各弹一次当前运行版本的更新公告。公告按主题展示本版变化和贡献者，内容取自该版本的 GitHub Release 正文。

## ADDED Requirements

### Requirement: 公告内容来自当前运行版本的正式 Release
Host SHALL 只为当前运行版本提供公告，来源是 Tag 为 `v<当前版本>` 的 GitHub Release。该 Release MUST 已正式发布：不是草稿，也不是预发布。读取失败、Release 不存在、是草稿或预发布、正文中解析不出主题时，Host SHALL 报告“无公告”，不得退而显示其他版本的说明。同一进程内，Host SHALL 对每个版本只成功读取一次，之后复用结果。

#### Scenario: 当前版本有正式 Release
- **WHEN** Host 运行 0.24.1，且 GitHub 上 `v0.24.1` 是正式 Release，正文含主题
- **THEN** 公告的版本为 0.24.1，并带有该 Release 的发布日期和链接

#### Scenario: 不用最新版说明冒充当前版本
- **WHEN** Host 运行 0.24.1，GitHub 最新正式版是 0.25.0
- **THEN** 公告内容来自 `v0.24.1`，不来自 0.25.0

#### Scenario: 预发布或缺失
- **WHEN** 当前版本的 Release 是预发布、草稿，或者不存在
- **THEN** Host 报告无公告

#### Scenario: 网络失败
- **WHEN** 读取 GitHub 超时或失败
- **THEN** Host 报告无公告，且不缓存这次失败，下次请求时重新读取

### Requirement: 从 Release 正文解析中英文公告
Host SHALL 按 `codexhost-release` 模板解析正文，得到中文和英文两份公告。

- 正文以第一条单独的 `---` 为界：之前是中文，之后是英文。
- 每种语言取第一个二级标题（`## `）之前的部分：第一段是总结；每个 `### <图标> <标题>` 开始一个主题，其后的文字是说明；以 `— ` 开头的行列出贡献者（`@用户名`，以 ` · ` 分隔）。

图标和贡献者都可以没有。某种语言解析不出主题时，该语言 SHALL 视为没有公告；两种语言都没有时，SHALL 视为无公告。

#### Scenario: 解析模板正文
- **WHEN** 中文部分是一句总结，后跟两个 `###` 主题，每个主题有说明和 `— @a · @b` 行
- **THEN** 中文公告包含该总结，以及两个主题，每个主题有图标、标题、说明和贡献者 `a`、`b`

#### Scenario: 旧格式正文
- **WHEN** 正文只有 `## ✨ 本版重点` 列表，没有 `###` 主题
- **THEN** 视为无公告

#### Scenario: 只有一种语言
- **WHEN** 正文没有 `---` 分隔，且只有中文主题
- **THEN** 只有中文公告；界面语言为英文时也显示中文公告

### Requirement: 已读记录由 Host 统一保存
Host SHALL 持久化最后一个已读公告的版本号，Desktop 和 Web 共用这一记录，重启后仍然保留。确认已读时，客户端 SHALL 提交公告的版本号；版本号不等于当前运行版本时，Host SHALL 拒绝。当前版本已确认过时，Host SHALL 不再要求显示公告。

#### Scenario: 一端确认后另一端不再弹
- **WHEN** 用户在 Desktop 上确认了 0.24.1 的公告，之后打开 Web
- **THEN** Web 不再弹出 0.24.1 的公告

#### Scenario: 没有已读记录
- **WHEN** 首次安装或首次使用此功能，当前版本有公告
- **THEN** Host 要求显示公告

### Requirement: Desktop 和 Web 启动后弹出更新公告
Desktop 的注入界面和 Web 在连上 Host 后，SHALL 各查询一次公告。当前版本有公告且未读时，SHALL 弹出“更新公告”对话框，内容依次为：

- 版本号和本地化的发布日期；
- 总结；
- 每个主题：图标、标题、贡献者和说明。

对话框按界面语言选择中文或英文公告，缺失时使用另一种语言。对话框 SHALL 提供“我知道了”按钮和完整更新说明的链接。点“我知道了”或按 `Esc` 关闭，关闭时确认已读；点击遮罩不关闭。没有公告或查询失败时，SHALL 不显示任何提示，也不影响正常使用。对话框在手机宽度下 SHALL 可完整滚动阅读。

#### Scenario: 升级后首次打开
- **WHEN** 用户升级到 0.24.1 后首次打开 Desktop，公告未读
- **THEN** 弹出 0.24.1 的更新公告；用户点“我知道了”后，Host 记录 0.24.1 已读，之后启动不再弹出

#### Scenario: 离线启动
- **WHEN** 启动时无法访问 GitHub
- **THEN** 不弹窗，也不记录已读；下次联网启动时再弹

#### Scenario: 多个标签页
- **WHEN** 同一个 Web 在两个标签页中打开，用户在其中一个确认了公告
- **THEN** 另一个标签页再次查询时不会弹出

### Requirement: 在设置中重新查看本版公告
设置的“更新”页 SHALL 提供“查看本版公告”入口，打开与启动时相同的对话框。从这里打开和关闭对话框 SHALL 不改变已读记录。没有公告时，该入口 SHALL 不显示。

#### Scenario: 手动查看
- **WHEN** 用户已确认过当前公告，从设置“更新”页点“查看本版公告”
- **THEN** 对话框再次显示当前版本公告；关闭后已读记录不变
