## 实现边界

- 构建基础设施统一位于`scripts/release/`，测试位于`tests/release/`，不再是npm Runtime Package；
- `packages/release-staging`、Project Reference和lockfile Workspace条目已删除；
- 固定九文件Payload保留Node官方归档校验、Pi-only Host Bundle审计和第三方许可证；
- Payload不再生成`release-manifest.json`、`SHA256SUMS.txt`或目录备份事务；
- macOS由系统`codesign`和`hdiutil`生成ad-hoc签名App及DMG，Release不再输出App ZIP；
- Windows由固定WiX Toolset 4.0.6和声明式WXS生成per-user MSI；
- GitHub Release Workflow覆盖四目标，只上传最终DMG/MSI与SHA旁车。

## 未关闭边界

本机没有`.NET`、PowerShell、WiX和Windows Installer环境，不能把WXS静态检查表述为MSI构建通过。需要在真实Windows宿主分别运行：

```text
npm run release:package -- --target windows-x64
npm run release:package -- --target windows-arm64
```

还需安装并启动生成的MSI，验证开始菜单无参数入口、卸载、私有Node、Launcher资源解析和真实Codex Desktop Gate。Release Workflow已承载这两个构建目标，但在它实际成功前不得宣称Windows安装包支持已经通过。
