## Purpose

让用户在运行中的 codexhost Web 启停已安装的界面插件，无需重启服务或刷新普通插件所在页面，同时保留原包配套资源、核心功能和故障恢复入口。

## ADDED Requirements

### Requirement: 运行中应用插件选择

系统 SHALL 在普通运行模式下直接应用已安装插件的启用、禁用和卸载，更新其客户端贡献及服务端配套功能，不重启 Web 或共享 Host。安装 SHALL 仍默认禁用且不执行插件入口；启用选择持久保存，后续启动按选择恢复。卸载 SHALL 在相关实例释放后清理安装文件。

#### Scenario: 启用与禁用
- **WHEN** 本机管理用户启用一个兼容插件，再禁用它
- **THEN** 插件在已打开的普通页面出现后消失，其配套路由随之启停，无需重启或手动刷新

#### Scenario: 卸载运行中的插件
- **WHEN** 用户卸载已启用插件
- **THEN** 插件被停用并移除登记，运行实例释放前不删除其仍需使用的安装文件

#### Scenario: 安装与后续启动
- **WHEN** 用户只安装插件，或之后重新启动 Web
- **THEN** 仅安装不执行插件；重新启动仍只加载已保存为启用的插件

### Requirement: 页面同步与刷新边界

系统 SHALL 将最新插件集合同步到连接中的普通页面，并在断线重连后恢复一致；源码及发行运行 SHALL 行为一致。仅能通过首页初始化应用的贡献 SHALL 提示刷新页面，不要求重启服务；服务端加载成功 MUST NOT 被描述为所有浏览器已应用成功。

#### Scenario: 多页面与重连
- **WHEN** 一个页面修改插件选择，另一个页面在线或稍后重连
- **THEN** 两个页面最终采用最新插件集合，不要求分别启停

#### Scenario: 首页初始化贡献
- **WHEN** 插件贡献无法在现有页面中动态应用
- **THEN** 用户获得需要刷新页面的提示，不被告知已无刷新生效

### Requirement: 失败隔离与现有边界

热加载 SHALL 保持现有本机管理权限、路由认证和恢复入口。可捕获的加载失败 SHALL 显示原因并清理失败实例，不将其标为已加载；未受影响插件和内置服务 SHALL 保持运行。热加载 MUST NOT 重启终端、改变 Harness 执行或 Thread 持久化，也不得绕过安全模式及仅内置页面选择。

#### Scenario: 插件加载失败
- **WHEN** 新启用插件缺少依赖或初始化抛出可捕获异常
- **THEN** 界面显示失败与已保存选择，其他未受影响插件、内置文件和终端服务不被重启

#### Scenario: 安全模式和恢复页面
- **WHEN** 用户在安全模式保存启用选择，或在普通模式打开 `/extensions`、`/?extensions=off`
- **THEN** 安全模式不执行用户插件；恢复页面不因热加载通知而载入第三方客户端或首页注入

#### Scenario: 原包与核心功能
- **WHEN** 用户在已有终端和会话运行时启停带图片路由的兼容主题
- **THEN** 主题资源沿用原包及现有认证，终端和会话不因插件切换中断，聊天、文件与设置保持原有功能
