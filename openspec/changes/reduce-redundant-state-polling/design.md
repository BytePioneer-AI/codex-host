## Context

当前基线：`agent-group-sync.ts` 每 3 秒读排序；`ch-sessions.ts` 即使启用事件通道仍每 10 秒扫描活动/归档列表、所有权与项目；`shared-thread-bridge.ts` 在线时每 3 秒唤醒，但直接复用连接。远程连接页与 Console 概览每 5 秒查询。具体目标见 [proposal.md](proposal.md)。

## Goals / Non-Goals

目标是减少无状态变化时的请求与唤醒，并保持失败恢复。范围限上述五处；GUI 原生 Codex 执行路径、共享 Thread 所有权、已有持久化文件及旧 CDP 回退路径保持各自契约。

## Decisions

### 1. 先补事件，再删除排序轮询

沿用现有偏好同步的数据流：`Host 保存成功 → 通知状态失效 → 各端读取最新快照`。通过方法专属的公共通知契约接入 Desktop 和 Host client channel，Web 再转成浏览器事件；不增加通用事件总线或浏览器文件访问。

排序文件继续由 Host 管理。订阅先于初读建立，写入失败不发布成功变更，重连与恢复可见时补读。显式缺少事件支持的旧入口保留兼容刷新，不能直接删定时器后丢失跨端同步。

### 2. 分开会话事实与项目归属

事件模式下，会话目录由首次读取、Thread 变更、重连及显式用户刷新触发。项目归属尚无完整事件覆盖，保留 10 秒项目查询并使用缓存的已确认会话 ID；定时查询不再分页获取全部会话或重复查询所有权。旧 CDP 保持现有目录/历史查询。相比直接关闭整个定时器，这样仍能发现 GUI 的项目调整。

### 3. 断线期间重试，在线期间停止

共享连接初次连接失败或断开后，按 1、2、4、8、15 秒上限退避，最多一个在途连接请求。成功后取消重试；用户请求可以提前触发连接并复用在途工作。沿用原有连接关闭与代次校验，迟到连接和响应不能覆盖新连接。

### 4. 页面可见性约束必要查询

远程连接页、Console 在打开/恢复可见、用户刷新及操作结束时读取一次。稳定状态 30 秒检查，远程操作或 Console 启动中 5 秒检查；隐藏、离开页面或 dispose 时取消计划中的查询。状态来源没有完整事件覆盖，先降低频率，不为减少轮询额外搭建后台推送框架。

同一数据源的通知与用户刷新合并在途读取；读取期间到达的新事件标记为待刷新并在当前读取结束后再次核对。取消后迟到结果不能修改已退役页面。

## Risks / Trade-offs

- 事件缺失导致状态停滞 → 增加保存、订阅、断线恢复与焦点恢复的定向测试后删除轮询。
- 稳定健康状态最多延迟约 30 秒 → 操作期间保留 5 秒检查，提供立即刷新入口。
- 拆分项目查询误删会话或改变执行 cwd → 失败保留确认状态，项目调整只改变显示归组。

## Migration Plan

五项依次交付，每项包含自身测试和对应文档；最后做跨端组合验收。无数据迁移。回滚刷新调度时保留已有公共通知与数据文件兼容性。
