## Purpose

使安装在 codexhost Web 数据目录的可信 DSH Web 扩展能够以原包完成客户端展示及其配套服务端功能，在源码和发行运行中保持一致，并保留 codexhost 核心功能归属、明确的依赖诊断和禁用恢复能力。

## ADDED Requirements

### Requirement: 按启用配置运行原包

系统 SHALL 在普通 Web 启动时按已保存的启用配置运行扩展的原生服务端入口及客户端贡献，遵循原包的 bundle、配置和依赖声明，不要求修改原包或编写逐插件资源映射。安装及保存启用选择 MUST NOT 执行扩展入口；未启用包不得因已安装而执行。仅含受支持客户端产物的包 SHALL 保持可用。

#### Scenario: 前后端协同扩展
- **WHEN** 用户启用包含预构建服务端、客户端及资源的 Web 扩展并重启 Web
- **THEN** 原包的服务端功能与客户端贡献均可用，包内代码和资源布局保持不变

#### Scenario: 已安装但未启用
- **WHEN** 用户只安装扩展或保存启用选择而未重启 Web
- **THEN** 操作本身不执行该扩展入口，界面仍区分保存的选择与当前运行结果

#### Scenario: 纯客户端包
- **WHEN** 已有受支持扩展仅包含客户端入口
- **THEN** 重启后的客户端贡献继续可用，不将浏览器代码当作服务端入口执行

### Requirement: 真实依赖与加载诊断

系统 SHALL 根据实际可用的宿主模块、版本及服务装配扩展；缺失必需依赖、版本冲突或入口加载失败时，报告相关扩展和原因，不伪造服务、替换内置模块或隐式启动 Agent Runtime。加载失败与用户保存的启用选择 SHALL 分别显示，服务端装配状态 MUST NOT 被描述为浏览器功能验收结果。

#### Scenario: 缺少必需服务
- **WHEN** 扩展要求当前 Web 未提供的必需服务
- **THEN** 系统显示依赖诊断，不将其标为成功运行，不修改 Harness 配置以补齐依赖

#### Scenario: 可捕获的加载失败
- **WHEN** 用户扩展的加载抛出可捕获异常
- **THEN** 系统报告失败并清理该次失败装配的资源，保留启用选择和内置界面的恢复路径，不因清理而释放既有文件或终端服务

### Requirement: 原生资源响应与入口归属

系统 SHALL 在既有 Web 地址上提供扩展自行注册的路由，保持插件处理方法、状态码、响应头及响应体的语义；插件路由 SHALL 经过现有认证，写请求及连接升级沿用适用的同源约束。扩展装配 MUST NOT 抢占内置 API、认证、恢复入口、核心资源或连接通道；路由冲突须明确报告，不以加载顺序静默覆盖。

#### Scenario: 自带资源服务
- **WHEN** 扩展注册并处理自身的图片、HTML、JavaScript、CSS 或字体请求
- **THEN** 已认证浏览器从现有 Web 地址收到原包定义的响应，无需额外端口或改写资源 URL

#### Scenario: 方法与缓存语义
- **WHEN** 扩展对 GET、HEAD、条件请求或不支持的方法提供不同响应
- **THEN** 系统保留原包定义的响应语义，不统一转换成静态文件响应

#### Scenario: 内置入口冲突
- **WHEN** 扩展注册会覆盖内置入口的路径或替换内置服务与模块身份
- **THEN** 系统报告冲突，原有入口和内置依赖继续由原所有者处理

#### Scenario: 未认证访问与远程管理
- **WHEN** 未认证请求访问扩展路由，或远程访问令牌请求安装和启停扩展
- **THEN** 服务端按既有认证与本机管理规则拒绝请求，不因启用扩展而放宽权限

### Requirement: 重启生效与资源释放

启用、禁用和卸载 SHALL 继续在重启 Web 后应用于运行中的扩展。停用生效、装配失败或正常退出时，系统 SHALL 释放相关插件注册的路由、订阅和生命周期资源；卸载 MUST NOT 提前删除仍被当前运行实例使用的安装文件。系统不得为应用扩展选择自动重启共享 Host，也不承诺撤销插件已产生的外部副作用。

#### Scenario: 禁用后重启
- **WHEN** 用户禁用扩展并重启 Web、刷新页面
- **THEN** 该扩展的客户端贡献与服务端路由均不再加载，用户会话和配置仍保留

#### Scenario: 卸载当前运行的扩展
- **WHEN** 用户卸载正在运行的扩展但尚未重启 Web
- **THEN** 管理结果说明待重启生效，当前实例需要的包内文件在其释放前保持可用，重启后不再装配该扩展并清理不再使用的安装文件

### Requirement: 区分页面恢复与整服务恢复

系统 SHALL 保留不加载第三方客户端的独立管理页和仅内置页面。`--safe-mode` SHALL 在启动时跳过用户扩展的服务端入口和客户端贡献，保留安装记录及启用选择；`?extensions=off` 只影响当前页面，不得声称能停止已运行的服务端扩展。恢复页面不得应用用户扩展的首页注入。

#### Scenario: 整服务安全模式
- **WHEN** 用户使用原数据目录以 `--safe-mode` 启动 Web
- **THEN** 用户扩展的服务端代码不执行，页面只加载内置贡献，用户仍可管理已保存的启用选择

#### Scenario: 页面级恢复
- **WHEN** 用户打开 `/extensions` 或 `/?extensions=off`
- **THEN** 页面不执行第三方客户端或使用其首页注入，但不会因此停止其他页面共享的服务端扩展

### Requirement: 源码与发行运行一致

系统 SHALL 在源码运行和移出仓库的发行目录中提供同等的 Web 扩展加载与依赖语义。扩展使用宿主提供的共享运行依赖时 SHALL 使用宿主实例，不依赖开发工作树、用户另装的 DSH 或安装过程中下载的另一套宿主来获得兼容性。

#### Scenario: 仓库外发行目录
- **WHEN** 用户在仓库外启动发行包并启用与源码模式相同的扩展
- **THEN** 该扩展的服务端、客户端和包内资源可用，共享依赖可解析，缺失依赖仍得到明确诊断

### Requirement: 保留 codexhost 核心功能

Web 扩展装配 MUST NOT 改变 Harness 执行、Thread 存储、现有认证与核心接口的所有权，不得修改用户的原生 DSH profile。启用已验收扩展后，聊天、Harness 选择、会话管理、文件访问、终端及设置 SHALL 保持原有功能；兼容声明须区分原包已验证行为与未验证能力。

#### Scenario: 核心功能回归
- **WHEN** 用户启用通过验收的 Web 扩展并使用聊天、Harness 选择、会话、文件、终端和设置
- **THEN** 这些操作继续使用原有执行与持久化路径，结果符合未启用扩展时的功能契约

#### Scenario: 原包兼容声明
- **WHEN** 产品声明某版本扩展已兼容
- **THEN** 声明基于该未修改原包的实际浏览器运行、资源响应和禁用恢复结果，而非仅安装成功或服务端装配状态
