## Why

Claude Code writes control-plane transcript records such as `/model` envelopes and `<local-command-stdout>` alongside human conversation messages. The current Claude history mapper treats any text-bearing `user` record as a Host Turn, and the Host then appends newly discovered mappings even when they occur in the middle of the Native Snapshot; after one recovery this can persist an order that causes every later recovery to fail.

## What Changes

- Classify Claude Code local-command protocol records at the Adapter boundary and omit non-conversation control output from Host history Turns, following the proven Paseo transcript-noise approach without copying its persistent Timeline model.
- Preserve genuine human prompts and supported slash-command prompts while excluding model-selection control records generated by the native control path.
- Reconcile persisted Turn identities against the complete Native Snapshot order and atomically persist the complete ordered mapping set when legitimate Native Turns are discovered between existing mappings.
- Keep conflict, missing-turn, cross-Session, Fork, and rollback consistency checks fail-closed.
- Add regression coverage for Claude model-switch records and two consecutive cold recoveries after middle-inserted Native history.

## Capabilities

### New Capabilities

None.

### Modified Capabilities

- `claude-code-text-session`: Clarify that Claude local-command metadata and control output are not human User Turns in a Native history Snapshot.
- `external-thread-mapping-store`: Require complete ordered Turn mapping replacement during Snapshot reconciliation while preserving atomicity and identity-conflict rejection.

## Impact

- `packages/adapters/claude-code`: Claude history classification and focused mapper tests.
- `packages/host-runtime`: Snapshot alignment and repeated-recovery regression coverage.
- `packages/mapping-store`: Atomic ordered mapping replacement API and persistence tests.
- No public HarnessAdapter schema change, no persisted Transcript, no Native Session mutation, and no automatic migration of an already inconsistent live Mapping Store record.
