# Spec Delta

## Purpose

将桌面端交互收拢到单一安装包：正常启动不再自动弹出诊断控制台浏览器页，按本机安装探测与用户偏好进入自有原生桌面窗口或 Codex Desktop 增强模式，并通过系统托盘与简洁的连接设备引导完成跨模式切换和手机配对。

## ADDED Requirements

### Requirement: 正常启动静默控制台与故障救援

通过图形入口或桌面启动命令启动 codexhost 时，系统 MUST NOT 在启动正常流程中自动打开本地 Console 浏览器页面；仅当启动失败或检测到持续的界面注入失败时，系统 SHALL 自动打开 Console 总览用于排障和更新。用户显式执行 `codexhost console`、通过托盘选择诊断入口或在终端模式下查看启动输出时，原有访问与输出行为 SHALL 保留。

#### Scenario: 正常桌面启动不弹窗
- **WHEN** 用户从开始菜单、应用图标或命令行正常启动桌面模式且未发生启动或注入错误
- **THEN** 目标桌面窗口正常打开，系统不自动在浏览器打开 Console 页面

#### Scenario: 启动或注入持续失败时自动救援
- **WHEN** 启动阶段失败，或桌面界面注入报告持续不可用
- **THEN** 系统自动打开本地 Console 总览页面展示失败阶段、原因与更新恢复入口

#### Scenario: 显式打开或终端模式
- **WHEN** 用户执行 `codexhost console` 或在终端直接执行 `codexhost launch`
- **THEN** `codexhost console` 正常打开本地 Console 页面；终端启动继续打印本机控制台与 Web 访问地址

### Requirement: 默认桌面模式探测与偏好持久化

系统 SHALL 在数据目录持久化用户的默认桌面启动模式与首次引导完成状态（Unix 下为仅当前用户可读写权限）。未在本机检测到官方 Codex Desktop 时，系统 MUST 直接打开自有桌面窗口而不打扰用户；检测到官方 Codex Desktop 且尚未完成首次引导时，系统 SHALL 展示一次性选择界面供用户选定默认打开自有桌面窗口或官方 Codex Desktop 增强模式，随后记住选择并在后续启动直接生效。用户 SHALL 可通过命令行或系统托盘随时查询与修改该默认模式。

#### Scenario: 未安装官方 Codex Desktop
- **WHEN** 本机不存在可用的官方 Codex Desktop，用户启动 `codexhost`
- **THEN** 不显示模式选择引导，直接启动后台服务并打开自有桌面窗口（无桌面壳二进制时回落为打开本机 Web）

#### Scenario: 首次检测到官方 Codex Desktop
- **WHEN** 本机存在官方 Codex Desktop 且尚未保存过默认启动模式，用户启动 `codexhost`
- **THEN** 展示首次模式选择界面；用户选择「自有桌面窗口」或「官方 Codex Desktop」后持久化偏好并立即打开对应界面

#### Scenario: 已保存偏好但官方客户端已卸载
- **WHEN** 已保存默认模式为官方 Codex Desktop，但启动时未找到官方安装
- **THEN** 系统退回自有桌面窗口或明确提示切回自有模式，不静默卡死

#### Scenario: 命令行查询与切换偏好
- **WHEN** 用户查询或更新启动偏好命令
- **THEN** 查询返回包含本机官方安装状态与当前默认模式的结果；更新合法模式值后立即原子写入并在下次启动生效，非法值返回错误

### Requirement: 自有原生桌面壳与系统托盘

自有桌面壳 SHALL 确保共享 Host 与本地 `web-server` 运行后，使用本机回环一次性登录凭证加载会话界面，不要求用户手动粘贴令牌；非本机来源的外部链接 SHALL 交给系统默认浏览器打开。桌面壳 SHALL 维护运行状态记录并保证单实例聚焦：关闭主窗口时隐藏到系统托盘而非中止后台服务；系统托盘 SHALL 提供打开自有窗口、打开官方 Codex Desktop、查看手机连接、切换默认启动方式、打开诊断控制台、检查更新与完全退出服务的入口。两个桌面窗口同时开启时 SHALL 共用同一后台状态。

#### Scenario: 零登录打开自有桌面窗口
- **WHEN** 用户执行 `codexhost app` 或以自有模式启动桌面壳
- **THEN** 后台 Host 与本地 `web-server` 自动就绪，桌面窗口免手工输入令牌直接展示会话主界面

#### Scenario: 关闭窗口保留托盘与后台
- **WHEN** 用户关闭自有桌面窗口的关闭按钮
- **THEN** 窗口隐藏而托盘图标继续保留，共享后台与进行中的 Turn 不中断，点击托盘入口可重新前置窗口

#### Scenario: 托盘完全退出服务
- **WHEN** 用户在系统托盘点击「完全退出 CodexHost」
- **THEN** 桌面壳退出并停止本机托管的后台服务

#### Scenario: Web 服务监听配置变更重启
- **WHEN** 用户在界面修改连接配置导致本机 `web-server` 重启切换监听端口或网卡
- **THEN** 桌面壳展示平滑重连过渡状态并在服务重新就绪后自动恢复页面，不展示浏览器网络错误页

### Requirement: 连接设备与移动端获取引导收口

会话 Web 的「连接设备」页面 SHALL 优先突出推荐远程连接方式与一键扫码登录区，将进阶网络配置与说明收纳至展开区；同时提供移动端分平台引导：为 Android 用户提供独立 APK 下载入口与扫码指引，为 iOS 用户说明通过 Safari 扫码后「添加到主屏幕」以独立窗口获取完整输入贴合与推送能力。在自有原生桌面壳中运行会话界面时，系统 SHALL 隐藏浏览器「安装应用」提示行。

#### Scenario: 在自有桌面壳中查看通用设置
- **WHEN** 用户在自有原生桌面壳窗口内打开「设置 → 通用」
- **THEN** 不显示「安装为浏览器应用」条目，避免对已处于桌面端内的用户造成困惑

#### Scenario: 查看连接设备页移动端引导
- **WHEN** 本机用户打开「设置 → 连接设备」
- **THEN** 页面首屏聚焦主连接卡片与二维码，下方提供 Android 安装包获取与 iOS 添加到主屏幕指引，进阶自建/隧道选项默认收起
