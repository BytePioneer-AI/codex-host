# Design

## Context

- 拖动放置已实现：落点判定在 `rows/thread-drop.ts`，拖动状态在 `rows/ThreadPlacementDrag.tsx`；手动顺序存于 `stores.ts` 的 `sessionOrderByAccount`（浏览器本地，现仅顶层）。
- 子 Thread 当前被禁止排序拖动（`Rows.tsx` 中 `depth > 0` 不接 `drag`），顶层排序线与挂靠区共用 25/50/25 的行内划分。

## Decisions

### 1. 落点按“意图”分层，而不是按行内固定比例

- 默认：行内上下各 50%，决定插入线位置（目标行之前或之后），语义为“成为目标行的同级，位于其间”。
- 在目标行中间区域（约 40%，上下各留 30% 给插入线）稳定停留 500ms（抖动 ≤ 6px）后切换为“成为子 Thread”：隐藏插入线，显示整行框与提示；离开该区域立即取消。
- 按更新时间排序时不显示插入线：默认整行表示“同级”，停留表示“子 Thread”。
- 移到顶层沿用现有的分组标题/空白处落点，并保留“移入其他工作区分组”的原有行为。
- 纯函数：落点判定与停留状态机放在 `thread-drop.ts`，用 node:test 覆盖；组件只接线。

### 2. 每一层独立的手动顺序

- `sessionOrderByAccount` 的键扩展为容器：顶层沿用现有键，子 Thread 使用 `thread:<parentId>`。读取时与当前成员做 reconcile（新成员排在最前，失效项忽略），复用现有 `reconcileManualOrder`。
- 放置到新父 Thread 的同时写入目标层的顺序；Host 的显示父 Thread 与浏览器本地顺序分别持久化，顺序丢失时退化为按更新时间排序，不影响树关系。

### 3. 菜单仅用于触屏

沿用已有的触屏判断（`(hover: none), (pointer: coarse)`），桌面和窄桌面窗口都不显示“移到…下”“移到顶层”。

## Risks

- 停留状态机与既有的拖入聊天引用、拖到工作区分组并存：同一时刻只激活一个落点，拖入聊天区域不预览任何放置。
- 子 Thread 手动顺序只在当前浏览器有效，换浏览器后按更新时间排序。
