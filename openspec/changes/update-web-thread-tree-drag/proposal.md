# Proposal

## Why

会话树上线后，手动拖动存在两个问题：子 Thread 不能参与拖动排序，一旦被放到某个父 Thread 下，就无法用拖动把它移回平级或顶层的指定位置；同时手动排序下行上下边缘的命中区过窄，想排序时常常误挂靠为子 Thread。

## What Changes

- 手动排序下，所有 Thread（包括子 Thread）都可以拖动：拖到两行之间时出现插入线，松手后成为这两行的同级并插在它们之间，可以移出到任意层级和位置。
- 每一层的手动顺序独立保存，顶层顺序沿用现有设置，子 Thread 的顺序按父 Thread 保存；按更新时间排序时各层仍自动排序。
- 默认的拖动落点是“成为目标行的同级”；在目标行中间稳定停留约 500ms 并看到提示后，才成为目标行的子 Thread。
- 桌面使用拖动，手机和触屏设备使用行菜单（“移到…下”“移到顶层”）；桌面不再显示这两个菜单项。
- 拖到自己所在分组的标题或空白处移到顶层；拖到其他工作区分组仍是原有的移入文件夹，拖入聊天区域仍是会话引用。

## Decisions

- **手动顺序只保存在当前浏览器**：沿用顶层手动顺序的存储位置（浏览器本地视图设置），按“顶层或父 Thread ID”分别记录；显示父 Thread 仍由 Host 持久化。不新增 Host 数据、不改后端接口。
- **同级优先，子项需要停留确认**：每一行都能成为父项，行高只有 32px，同一次松手承担排序与挂靠容易误操作；以停留加提示作为“放入”的显式意图，参考主流树形拖动实现（Chrome 书签、Notion、VS Code、Headless Tree）。
- **按更新时间排序时无位置概念**：该模式下拖动只改变显示父 Thread，不显示插入线，整行高亮表示“成为它的同级”，停留后表示“成为它的子项”。
