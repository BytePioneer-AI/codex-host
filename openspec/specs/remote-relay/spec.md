# remote-relay Specification

## Purpose
Relay 让没有公网地址的电脑通过 `<id>.<域名>` 被手机浏览器访问。它只按 SNI 转发加密字节，不解开用户 TLS，官方中转和自托管中转使用同一份程序。

## Requirements

### Requirement: 子域 ID 由公钥决定

每台电脑的子域 ID MUST 只由其身份公钥确定：同一公钥总得到同一 ID，不同公钥得到不同 ID 的概率可以忽略。ID MUST 是合法的 DNS 标签，只含小写字母和数字。Relay MUST 自己从公钥计算 ID，不接受电脑声明的 ID 或主机名。没有注册检查时，用户访问地址为 `<id>.<域名>`；有检查时使用检查返回的地址名。

#### Scenario: 换网络后地址不变

- **WHEN** 电脑更换 IP 后用同一身份密钥重新注册
- **THEN** Relay 计算出相同的 ID，手机仍用原地址访问

#### Scenario: 不能注册别人的子域

- **WHEN** 一个客户端不持有某 ID 对应的私钥，尝试注册该 ID
- **THEN** 注册失败，该 ID 的现有注册不受影响

### Requirement: 电脑注册

电脑 MUST 通过 WSS 连接 Relay 控制地址上带协议版本的路径来注册。Relay 发出随机挑战，电脑用身份私钥签名，签名内容 MUST 绑定挑战和控制地址；电脑 MAY 同时提交想要的地址名和邀请码。验证和注册检查通过后，Relay 告知电脑其完整主机名，之后该主机名的手机连接才会被转发。不支持的协议版本、超时或签名无效时，Relay MUST 关闭连接，并让电脑能区分原因。

#### Scenario: 注册成功

- **WHEN** 电脑完成 WSS 连接并返回有效签名
- **THEN** Relay 返回 `<地址名>.<域名>`，此后发往该主机名的手机连接被转发到这台电脑

#### Scenario: 签名转发到其他 Relay 无效

- **WHEN** 恶意 Relay 把电脑对它的签名拿到另一个控制地址注册
- **THEN** 另一个 Relay 验证失败，拒绝注册

#### Scenario: 协议版本不支持

- **WHEN** 电脑请求 Relay 不支持的协议版本路径
- **THEN** Relay 拒绝升级为 WebSocket，电脑可据此提示升级，不必反复重试

#### Scenario: 注册超时

- **WHEN** 连接建立后 10 秒内没有完成注册
- **THEN** Relay 关闭该连接

### Requirement: 新注册替换旧注册

同一地址名在任何时刻 MUST 只有一条生效的控制连接。同一地址名的新注册成功后，Relay MUST 关闭旧控制连接以及经它转发的手机连接，并告知旧连接被替换。

#### Scenario: 断线后旧连接尚未超时

- **WHEN** 电脑网络切换后重新注册，而 Relay 还没发现旧连接已断
- **THEN** 新连接立即生效，旧连接被关闭，新的手机连接都走新连接

### Requirement: 控制连接心跳

Relay MUST 每 25 秒在每条控制连接上发送一次心跳。上一次心跳在下一次发送时仍未收到回应，Relay MUST 关闭该控制连接并注销该 ID，最迟约 50 秒内发现静默断开的电脑。

#### Scenario: 电脑休眠

- **WHEN** 电脑休眠，控制连接没有收到 FIN
- **THEN** Relay 在两个心跳周期内注销该 ID，之后到该地址的手机连接被关闭

### Requirement: 按 SNI 转发且不解开 TLS

Relay MUST 在 443 端口接受手机 TCP 连接，读取 TLS ClientHello 的 SNI 后，把包括 ClientHello 在内的全部字节原样交给对应电脑，不解开 TLS，不修改内容。ClientHello 可能跨多个 TCP 分段或 TLS 记录；超过 16 KiB 或 10 秒仍未读完、没有 SNI、SNI 不是控制地址也不属于在线地址名时，Relay MUST 直接关闭连接。

#### Scenario: 电脑在线

- **WHEN** 手机访问 `https://<地址名>.<域名>`，该地址名已注册
- **THEN** 手机与电脑完成 TLS 握手，证书由电脑提供，Relay 看不到 HTTP 内容

#### Scenario: 电脑离线或地址未知

- **WHEN** SNI 对应的地址名未注册，或 SNI 不属于该 Relay 的域名
- **THEN** Relay 关闭连接，不返回任何内容

#### Scenario: 慢速发送 ClientHello

- **WHEN** 客户端连接后 10 秒内没有发完 ClientHello
- **THEN** Relay 关闭连接

### Requirement: Relay 不保存内容

Relay MUST NOT 把转发的字节写入磁盘或日志。日志只能包含元数据：ID、电脑和手机的 IP、连接时间、字节数和关闭原因。

#### Scenario: 检查日志

- **WHEN** 手机经 Relay 完成登录和日常操作
- **THEN** Relay 的输出和磁盘上找不到请求或响应内容

### Requirement: 每条手机连接一个流

Relay MUST 为每条手机连接在对应控制连接上打开一个独立的流，并随流告知电脑手机的 IP 和端口。两个方向的结束 MUST 独立传递：一方发送完毕不影响另一方继续发送；任一方异常中断时，另一方也被中断。每个 ID 同时转发的手机连接 MUST 不超过 32 条，超出的新连接被关闭。

#### Scenario: 传递客户端地址

- **WHEN** 手机从某 IP 建立连接
- **THEN** 电脑在该流上拿到这个 IP 和端口，可用于登录限速

#### Scenario: 半关闭

- **WHEN** 手机发送完请求并关闭写方向，电脑还在发送响应
- **THEN** 电脑的响应完整送达手机

### Requirement: 流控与背压

Relay MUST 让每个流的接收窗口为 2 MiB、每条控制连接的接收窗口为 8 MiB。手机接收慢时，Relay MUST 停止读取对应流，而不是无限缓存，每台电脑每个方向的缓存因此不超过约 64 MiB。一条手机连接传输大文件时，同一电脑的其他手机连接 MUST 继续得到转发。

#### Scenario: 手机网络慢

- **WHEN** 电脑向一台网络很慢的手机发送大文件
- **THEN** Relay 为这条连接缓存的未发送数据不超过 2 MiB，电脑在这条连接上的发送被阻塞

#### Scenario: 多台手机同时很慢

- **WHEN** 同一电脑的多条手机连接同时接收很慢，另有一条连接在正常交互
- **THEN** 每条慢连接的缓存不超过 2 MiB，正常交互的连接继续得到转发

#### Scenario: 大传输期间审批

- **WHEN** 一条手机连接正在下载大文件，同一电脑上另一条连接发起审批请求
- **THEN** 审批请求被及时转发，不等大文件传完

### Requirement: 按子域限速和每日额度

Relay MUST 支持按地址名限制每个方向的带宽和每日总字节额度，未配置时不限制；注册检查返回的值优先于启动参数。每日额度按 UTC 日计算，同一地址重连不清零。超出当日额度后，Relay MUST 关闭该地址的现有手机连接并拒绝新连接，直到次日。超额期间 ALPN 只含 `acme-tls/1` 的连接仍被转发，但每条不超过 64 KiB、10 秒，且每个地址每小时合计不超过 1 MiB。

#### Scenario: 超过每日额度

- **WHEN** 某地址当日转发字节数达到额度
- **THEN** 该地址的手机连接被关闭，新连接被拒绝，其他地址不受影响

#### Scenario: 超额时续期证书

- **WHEN** 某地址已超额，证书机构发起 TLS-ALPN-01 验证
- **THEN** 验证连接被转发，电脑可以完成续期

#### Scenario: 冒充验证连接

- **WHEN** 超额期间客户端只声明 `acme-tls/1`，反复建立小连接传输数据
- **THEN** 单条连接在 64 KiB 或 10 秒处被关闭，该地址一小时内累计达到 1 MiB 后新的验证连接被拒绝

#### Scenario: 检查返回的额度

- **WHEN** 启动参数未设额度，注册检查为某地址返回每日额度
- **THEN** 该地址按检查返回的额度限制，其他地址仍不限制

### Requirement: 部署配置

Relay MUST 由部署者提供域名，控制地址默认 `relay.<域名>`，也可显式指定。Relay 只为控制地址终止 TLS。未提供证书和私钥时，Relay MUST 通过公网 443 自动申请证书并在到期前续期，无需 80 端口；证书及账户密钥 MUST 持久化，重启复用仍有效且未到续期时间的证书。自动续期 MUST 不重启进程或中断已有连接。部署者 MAY 成对提供证书和私钥，此时 MUST 不自动申请；收到重新加载信号时 MUST 重新读取提供的证书，不中断已有连接。

#### Scenario: 控制地址证书续期

- **WHEN** 部署者更新证书文件并发送重新加载信号
- **THEN** 新的控制连接使用新证书，已注册的电脑和转发中的连接不受影响

#### Scenario: 只提供域名

- **WHEN** 部署者只提供 `example.com`，公网 443 可达
- **THEN** Relay 为 `relay.example.com` 自动申请证书，验证握手只在控制地址终止，不影响电脑证书验证的原样转发

#### Scenario: 重启与自动续期

- **WHEN** Relay 重启或证书已到续期时间
- **THEN** 重启复用持久化密钥及未到续期时间的有效证书；到续期时间后自动申请并替换证书，已有连接保持

#### Scenario: 使用已有证书

- **WHEN** 部署者成对提供证书和私钥，并显式指定控制地址
- **THEN** Relay 使用该地址和证书，不向证书机构申请；只提供证书或私钥之一时启动报错

### Requirement: 可选连接总数上限

Relay MUST 支持可选正整数参数 `--max-connections`，限制监听端口的 TCP 连接总数；未配置时 MUST 不限制。无效值 MUST 在启动监听前报错。

#### Scenario: 总连接边界

- **WHEN** 已接受的 TCP 连接数达到配置值，又有新连接到达
- **THEN** 新连接直接关闭；计数包含电脑、手机及尚未完成 ClientHello 的连接，已有连接不受影响；名额释放后可再次接入，电脑端自动退避重连而不永久停止

#### Scenario: 未配置或参数无效

- **WHEN** 部署者未配置上限，或传入零、负数、非整数及非数值
- **THEN** 未配置时保留现有行为；无效参数导致启动报错

### Requirement: 用量记录保留与清理

Relay MUST 定期清理早于 UTC 当天且对应地址名当前未注册的用量记录，MUST 保留当天记录和当前已注册地址的记录。同一地址当天断开后重连 MUST 不清零额度。核心只在内存保存用量，重启后从注册检查返回的当天已用字节数起算；没有检查时重启清零，依次更换身份可获得新地址的额度，这不构成准入控制。

#### Scenario: 清理过期离线身份

- **WHEN** 清理时存在前一天的离线地址、前一天仍注册的地址和当天已离线地址
- **THEN** 只删除前一天的离线地址记录，其余记录保留；当天重连继续使用原额度

### Requirement: 注册检查

部署者 MAY 提供注册检查。签名验证通过后，Relay MUST 把 ID、电脑 IP、电脑填写的地址名和邀请码交给检查，由检查返回允许或拒绝。允许时返回地址名，可附带该地址的带宽上限、每日额度和当天已用字节数。之后电脑使用 `<地址名>.<域名>` 访问，额度从已用字节数起算。没有提供检查时，地址名就是 ID，行为与现在相同。

#### Scenario: 自建中转不提供检查

- **WHEN** 部署者没有提供注册检查，电脑填写了地址名和邀请码
- **THEN** Relay 忽略这两项，电脑仍注册为 `<id>.<域名>`

#### Scenario: 检查分配地址名

- **WHEN** 检查允许注册并返回地址名 `alice`
- **THEN** Relay 告知电脑 `alice.<域名>`，此后发往该主机名的手机连接被转发到这台电脑

#### Scenario: 重启后沿用当天用量

- **WHEN** Relay 重启后电脑重新注册，检查返回当天已用字节数
- **THEN** 该地址的当日额度从这个值继续计算，不因重启清零

### Requirement: 拒绝注册的原因

检查拒绝注册时，Relay MUST 告知电脑原因后关闭控制连接。原因只有四种：邀请码无效、地址名已被占用、已被停用、容量已满。电脑 MUST 能区分这四种原因与签名无效、注册超时、被替换。

#### Scenario: 名字已被占用

- **WHEN** 电脑填写的地址名已属于另一个身份
- **THEN** Relay 告知名字已被占用并关闭连接，原地址名的注册不受影响

#### Scenario: 容量已满

- **WHEN** 检查因容量已满拒绝
- **THEN** Relay 告知容量已满并关闭连接，电脑可以稍后重试

### Requirement: 用量报告与断开

Relay MUST 把每个地址名转发的字节数及时报告给部署者，计数口径与每日额度相同。部署者 MUST 能立即断开某个地址名：Relay 关闭它的控制连接和手机连接，电脑重连时重新经过检查。

#### Scenario: 修改限额

- **WHEN** 部署者修改某地址的额度后断开它
- **THEN** 电脑自动重连，检查返回新额度，新额度对之后的手机连接生效

#### Scenario: 停用地址

- **WHEN** 部署者停用某身份并断开它
- **THEN** 电脑重连时检查拒绝，电脑收到已被停用的原因

### Requirement: 额度用完通知电脑

某地址达到当日额度时，Relay MUST 通知对应电脑，并说明额度在下一个 UTC 日恢复。

#### Scenario: 当日额度用完

- **WHEN** 某地址当天转发的字节数达到额度
- **THEN** 电脑收到额度用完的通知，控制连接保持，次日手机可以再次访问

### Requirement: 控制地址上的其他请求

部署者 MAY 提供一个 HTTP 请求处理函数。控制地址上不属于 Relay 协议的 HTTPS 请求（不是升级到注册路径的 WebSocket 请求）MUST 交给它处理；没有提供时，Relay 对这些请求返回 404，与现在相同。手机发往地址名的连接不受影响，仍按 SNI 原样转发。

#### Scenario: 部署者处理自定义路径

- **WHEN** 部署者提供了处理函数，浏览器访问控制地址上由部署者自定的路径
- **THEN** 请求交给该处理函数，由它返回页面

#### Scenario: 没有提供处理函数

- **WHEN** 部署者没有提供处理函数，浏览器访问控制地址上的任意路径
- **THEN** Relay 返回 404

### Requirement: 可选连接事件与方向用量

部署者 MAY 订阅连接事件。Relay MUST 在成功注册及注销时报告电脑的地址名、IP、时间和已有的下线原因，无论是否提供注册检查；MUST 报告获准转发的手机连接开始和结束，包含连接标识、地址名、IP、开始及结束时间和各方向字节数。连接和用量报告 MUST 标明 ACME 验证连接，用量报告 MUST 区分手机到电脑与电脑到手机，并标明首次触达日额度。未订阅时转发和注册行为 MUST 不变，原双参数用量回调 MUST 继续可用。

#### Scenario: 电脑被替换或断开

- **WHEN** 已成功注册的控制连接被替换、断开或心跳超时
- **THEN** 部署者收到一次对应地址名、电脑 IP、时间和原因的下线事件；新连接注册成功后收到上线事件

#### Scenario: 手机双向转发

- **WHEN** 手机连接获准转发后关闭
- **THEN** 部署者收到匹配的开始和结束事件，结束包含开始/结束时间及两个方向分别的字节数，与增量用量报告一致

#### Scenario: 证书验证与未订阅

- **WHEN** ALPN 只含 `acme-tls/1` 的连接被转发
- **THEN** 连接及用量事件标记为 ACME；未提供回调时仍按原有规则转发
