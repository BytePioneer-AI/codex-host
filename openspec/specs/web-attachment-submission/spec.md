# web-attachment-submission Specification

## Purpose
定义 Web 中图片和普通文件从选择、上传到消息提交的完整用户体验与安全约束，使手机用户可以即时发送、查看每个附件的真实进度，并在失败后保留文字与附件重试。

## Requirements

### Requirement: 图片预上传保留图片语义

Web SHALL 在选择图片时上传二进制，JPEG 与 WebP 按大照片压缩规则准备，其他图片保持原始字节，提交消息仅引用会话凭证。上传 MUST 显式声明实际图片类型，按图片格式、大小、尺寸限制校验，并保留原有存储位置、转录区预览、队列缩略图与 Harness 图片清单语义。原有编码图片入口 SHALL 保持兼容。

#### Scenario: 图片凭证与隔离

- **WHEN** 当前会话引用图片上传凭证
- **THEN** Harness 收到按附件顺序排列的图片路径及图片标记，队列和转录区显示图片；其他会话不能使用该凭证

#### Scenario: 上传拒绝不合规图片

- **WHEN** 声明图片的上传包含非图片、无效尺寸或超过 20 MiB 的数据
- **THEN** 上传被拒绝，超过大小限制时不等待整个请求接收完成

#### Scenario: 消息级限制

- **WHEN** 消息中的编码图片与凭证图片合计超过 20 张或 32 MiB
- **THEN** 整条消息被拒绝，不提交部分附件

### Requirement: 上传中发送立即反馈并等待完整附件

Web SHALL 允许上传中发送，立即清空已提交草稿并显示待发送消息，全部附件成功后才执行原有 queue 或 steer 提交。已就绪附件 MUST NOT 引入上传等待。命令附件同样等待上传。已有失败附件 SHALL 阻止提交并提示重试或移除。切换会话 MUST NOT 取消等待消息。

#### Scenario: 上传中发送
- **WHEN** 用户发送带有上传中附件的消息
- **THEN** 待发送消息立即出现，所有附件就绪前没有 Host 提交，就绪后按原模式提交

#### Scenario: 图片和文件进度
- **WHEN** 输入框或待发送消息中的附件正在上传
- **THEN** 每个附件显示自己的进度，有总大小时显示“上传中 {percent}%”或“Uploading {percent}%”，否则显示现有上传中文案；完成后进度消失，沿用现有 Agent 状态

### Requirement: 失败恢复及有限自动重试

上传等待失败 SHALL 撤回待发送消息并恢复所有附件及文字，显示现有错误提示，不部分发送。已有新草稿文字时 MUST 将失败文字以空行追加其后。页面回到前台 SHALL 对传输失败附件自动重试一次；明确服务端拒绝 MUST NOT 自动重试。离开会话后的失败沿用页面内既有生命周期，不新增持久化。

#### Scenario: 空草稿恢复
- **WHEN** 上传失败且输入框为空
- **THEN** 文字与全部附件原样恢复，失败项可重试或移除

#### Scenario: 保留新输入
- **WHEN** 上传或普通提交失败且输入框已有新文字
- **THEN** 新文字保留在前，失败文字用空行追加在后，全部附件恢复

#### Scenario: 回到前台
- **WHEN** 页面从后台返回，附件因网络或非成功 HTTP 状态失败
- **THEN** 每个失败附件自动重试一次，重复前台事件不无限重试，服务端明确拒绝项不重试

### Requirement: 浏览器自动压缩大照片

Web SHALL 仅对 JPEG 或 WebP 且长边大于 2048 像素或文件大于 1 MiB 的图片在上传前尝试压缩：按 EXIF 方向转正，等比缩到长边不超过 2048、不放大，输出质量 0.85 的 JPEG。仅当结果严格更小时 SHALL 采用，保留文件名主体、扩展名改为 `.jpg`，声明 `image/jpeg`。PNG、GIF 与普通文件 MUST 保持原字节。压缩丢弃 EXIF 可接受，不提供原图开关。

#### Scenario: 大横拍与竖拍照片

- **WHEN** 用户选择 4000×3000 的 JPEG 或 EXIF 方向为 6 的同尺寸照片且压缩结果更小
- **THEN** 上传分别为 2048×1536 或 1536×2048 的 JPEG，保持方向正确

#### Scenario: 小图与尺寸阈值

- **WHEN** 用户选择不超过 1 MiB 且长边不超过 2048 的 JPEG，或任意大小 PNG、GIF、普通文件
- **THEN** 上传原文件；尺寸小于上限但超过 1 MiB 的 JPEG 或 WebP 尝试重新编码且不放大

### Requirement: 照片准备复用及失败回退

Web SHALL 把压缩作为现有上传流程的一部分，期间沿用上传中状态、进度与上传中发送语义；手动重试、前台自动重试或切换会话后的继续上传 MUST 复用同一准备结果，不重复压缩。解码、编码失败或结果未严格变小时 SHALL 静默上传原文件，不新增错误或阻止发送。

#### Scenario: 无法压缩或结果更大

- **WHEN** 浏览器无法解码或编码照片，或输出大小大于等于原文件
- **THEN** 按原文件名、原 MIME 与原始字节继续上传

#### Scenario: 压缩后上传失败重试

- **WHEN** 已准备的照片上传失败后手动或返回前台重试
- **THEN** 继续上传同一准备结果，不重复压缩，保留既有失败恢复与有限自动重试规则
