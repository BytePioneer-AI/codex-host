# web-relay-access Specification

## Purpose
让 Web 通过出站连接注册到 Relay，用固定的 `https://<id>.<域名>` 被手机访问，TLS 在这台电脑上解开，Relay 看不到内容。

## Requirements

### Requirement: 中转设置

本机连接设备页 SHALL 始终列出平级的“codexhost 中转”与“自建中转”方式，官方地址固定 `relay.chost.dev`，默认关闭。自建卡片 SHALL 在关闭时输入控制主机名，点击启用同时保存并连接，不设独立保存按钮；前后端拒绝非法主机名。开启后 SHALL 只读显示控制地址，不显示编辑框或改址提示，访问地址和复制链接紧跟状态与开关。保存与启停即时生效，不重启 Web 或 Host。同一时间 MUST 只开启一个中转，切换类型或地址前须关闭。选择卡片不启用；可单独关闭，“停止设备访问”也关闭它。设置只允许本机修改且重启沿用。`--no-auth` MUST 拒绝开启。`--relay` SHALL 仅预填或覆盖自建地址，空值清除自建地址，不改变官方卡片。

#### Scenario: 未配置控制地址

- **WHEN** Web 启动时没有保存过控制地址
- **THEN** 本机连接设备页显示官方与自建两种方式，官方使用 `relay.chost.dev`，自建尚未配置，Web 不连接任何 Relay

#### Scenario: 开启中转

- **WHEN** 用户在本机选择 codexhost 中转并点击启用
- **THEN** Web 开始连接当前 Relay，运行中的任务和已连接的浏览器不受影响

#### Scenario: 未启用认证

- **WHEN** Web 以 `--no-auth` 运行，且保存的设置是开启中转
- **THEN** Web 不连接 Relay，开启中转的接口返回明确的错误

#### Scenario: 手机尝试开启或关闭中转

- **WHEN** 经中转或局域网访问的页面调用开启、关闭或修改控制地址的接口
- **THEN** 接口拒绝，设置不变

#### Scenario: 页面保存自建地址

- **WHEN** 中转关闭，用户展开独立的“自建中转”卡片，填写 `relay.example.com` 并点击启用
- **THEN** 同一请求保存并按该地址注册，Web 和 Host 不重启；开启后控制地址只读，关闭后恢复编辑

#### Scenario: 非法控制地址

- **WHEN** 页面输入或设置接口收到带协议、端口、路径、用户信息、空白、IP 或不合法 DNS 标签的控制地址
- **THEN** 页面提示主机名格式错误，服务端拒绝保存，原设置不变

#### Scenario: 开启时更换地址

- **WHEN** 任一中转仍处于开启状态，用户试图更换控制地址或启用另一个类型
- **THEN** 页面要求先关闭中转，接口拒绝直接更换且不改变现有连接与设置

#### Scenario: 关闭后更换地址

- **WHEN** 用户关闭中转后保存不同的控制地址
- **THEN** 按控制地址分别保留分配主机名和证书，切回原控制地址时复用；不同控制地址不共用，即使域名后缀相同；电脑身份密钥不变，旧额度提示不出现在新中转上

#### Scenario: 切回官方中转

- **WHEN** 用户选择官方卡片，而自建中转仍开启
- **THEN** 官方卡片要求先关闭自建中转，当前使用标识仍在自建卡片；关闭后才可启用固定地址 `relay.chost.dev` 的官方中转

#### Scenario: 命令行覆盖

- **WHEN** 开发者通过 `--relay localhost:4498` 启动或通过 `--relay ""` 清除覆盖
- **THEN** 分别覆盖或清除自建控制地址，官方卡片仍固定 `relay.chost.dev`，显式保存的当前类型不变

#### Scenario: 旧官方配置无损识别

- **WHEN** 旧配置未保存中转类型、控制地址为 `relay.chost.dev`，且中转已经启用
- **THEN** 按官方类型展示为当前使用，保留已分配地址、证书和注册字段；用户无需重新启用或重新提供注册信息，正常启动连接继续提交原名字与邀请码

### Requirement: 身份密钥

首次开启中转时，Web SHALL 生成身份密钥，保存在数据目录中只有当前用户可读的文件里，之后的重启和更新 MUST 沿用同一密钥。私钥 MUST NOT 离开这台电脑。访问状态 MUST NOT 返回身份密钥的本机绝对路径。连接设备页 SHALL 简述身份密钥用于保持地址不变、不可删除或分享，位置以本机数据目录中的 `remote-relay/identity.pem` 表示，MUST NOT 显示完整本机绝对路径；密钥丢失或删除后地址会改变且无法找回。

#### Scenario: 更新后地址不变

- **WHEN** 升级 codexhost 后重新开启中转
- **THEN** 注册得到的地址与升级前相同

#### Scenario: 删除密钥

- **WHEN** 用户删除密钥文件后重新开启中转
- **THEN** Web 生成新密钥，得到新的地址，旧地址不再可用

### Requirement: 连接与注册

开启后 Web SHALL 通过 443 端口的出站 WSS 连接控制地址，按 Relay 协议完成注册并记录 Relay 返回的地址。一次连接尝试超过 30 秒未完成注册即放弃并按重连规则重试。环境变量 `HTTPS_PROXY` 指向 HTTP 代理时 MUST 经该代理连接。连接设备页 SHALL 按手机能否访问显示状态：关闭；准备中（连接、注册和首次申请证书）；已开启（附地址）；暂时无法使用（附自动重试时间）；需要处理（证书申请暂停，附证书机构的说明）；已停止（附原因）。准备中时页面 SHALL 自动刷新直到状态稳定。证书有效期、续期和申请过程 MUST NOT 作为单独状态显示。

#### Scenario: 注册成功

- **WHEN** 电脑能访问 Relay，注册通过，证书有效
- **THEN** 连接设备页显示已开启和 `https://<地址名>.<域名>`，不显示证书有效期

#### Scenario: 经代理连接

- **WHEN** 电脑只能通过 HTTP 代理访问外网，`HTTPS_PROXY` 已设置
- **THEN** Web 经代理连上 Relay 并完成注册

#### Scenario: 证书申请失败

- **WHEN** 已注册但证书申请失败
- **THEN** 连接设备页显示暂时无法使用和下次重试时间；申请已暂停时显示需要处理和证书机构的说明

### Requirement: 断线重连

连接断开或连续 60 秒没有收到 Relay 心跳时，Web SHALL 自动重连，间隔带随机抖动并逐次增加，最长 60 秒；连接稳定一段时间后间隔重新计算。重连 MUST NOT 重启 Host 或 Web，地址和 token 不变。Relay 告知被同一身份替换、协议版本不被支持或签名被拒时，Web MUST 停止重连并显示原因。

#### Scenario: Relay 重启

- **WHEN** Relay 重启后恢复
- **THEN** Web 自动重新注册，运行中的任务继续，手机用原地址重新连接

#### Scenario: 电脑静默断网

- **WHEN** 网络中断但没有收到断开通知
- **THEN** Web 在约 60 秒内发现并开始重连

#### Scenario: 同一密钥在两台电脑上

- **WHEN** 另一台电脑用同一身份密钥注册，这台电脑被替换
- **THEN** 这台电脑停止重连，连接设备页说明地址正被另一台电脑使用

#### Scenario: Relay 不支持当前协议版本

- **WHEN** Relay 拒绝当前协议版本
- **THEN** Web 停止重连，提示更新 codexhost

### Requirement: 在电脑上解开 TLS

每条经 Relay 到达的手机连接 SHALL 在 Web 进程内用数据目录中的证书完成 TLS，优先协商 HTTP/2 并兼容 HTTP/1.1，共用现有请求处理；10 秒内未完成握手的连接 MUST 被关闭。Web MUST NOT 新开监听端口。ALPN 只含 `acme-tls/1` 且 SNI 与申请主机名相同（不区分大小写）时，Web SHALL 用挑战证书应答，最低 TLS 1.2，握手后关闭，申请期间每次验证均有效。其他验证连接直接关闭。没有可用证书时 SHALL 保持注册并关闭普通手机连接。Web MUST NOT 宣告 HTTP/3 或 ECH。

#### Scenario: 手机经中转打开页面

- **WHEN** 证书有效，手机访问 `https://<id>.<域名>`
- **THEN** 手机看到的证书由这台电脑提供，页面、登录、RPC 和 WebSocket 都与其他入口一致

#### Scenario: 握手停滞

- **WHEN** 客户端发完 ClientHello 后不再发送
- **THEN** 10 秒后该连接被关闭

#### Scenario: 还没有证书

- **WHEN** 已注册但数据目录中没有证书
- **THEN** 手机连接被关闭，连接设备页显示准备中或暂时无法使用

#### Scenario: 证书机构验证

- **WHEN** 申请进行中，证书机构经 Relay 发起 ALPN 为 `acme-tls/1` 的连接
- **THEN** Web 用该主机名的挑战证书完成握手，即使还没有正式证书；多地点同时连接时每次都能完成

#### Scenario: 没有申请时的验证连接

- **WHEN** 没有进行中的申请，收到 ALPN 为 `acme-tls/1` 的连接
- **THEN** Web 直接关闭该连接

#### Scenario: HTTP/2 多路复用

- **WHEN** 手机支持 HTTP/2 并发起多个 HTTP 请求
- **THEN** 经中转协商 h2，在同一 TLS 连接上并发处理，认证和中转归属不变

#### Scenario: WebSocket 和旧客户端

- **WHEN** 浏览器打开 WebSocket，或客户端只支持 HTTP/1.1
- **THEN** 经独立 HTTP/1.1 连接使用现有认证与升级处理，不要求 HTTP/2 扩展 CONNECT

#### Scenario: 其他入口不变

- **WHEN** 通过 localhost、局域网、Tailscale 或反向代理连接 Web 的 HTTP 端口
- **THEN** Web 仍使用 HTTP/1.1

### Requirement: 经中转请求的归属

经中转到达的请求 MUST 视为非本机访问和 HTTPS 访问：不能查看或修改 token，登录 Cookie 带 Secure，响应带 HSTS（不含子域），同源校验要求 Origin 完整等于 `https://<注册得到的主机名>`。登录失败限速 SHALL 按 Relay 告知的手机 IP 计数。这类请求携带的 `x-forwarded-*` 头 MUST 被忽略。

#### Scenario: 两台手机经中转输错 token

- **WHEN** 一台手机经中转连续输错 token 被限速
- **THEN** 另一台从不同 IP 经中转访问的手机不受影响

#### Scenario: 兄弟子域发起请求

- **WHEN** 同一中转域名下另一台电脑的页面向这台电脑发起带 Cookie 的写请求
- **THEN** Origin 不匹配，请求被拒绝

#### Scenario: 伪造转发头

- **WHEN** 经中转的请求带有 `x-forwarded-for: 127.0.0.1`
- **THEN** 该请求仍按非本机处理，限速按 Relay 告知的 IP 计数

### Requirement: 大传输不阻塞其他请求

Web 端每条中转流的接收窗口 SHALL 为 2 MiB，整条控制连接的接收窗口为 8 MiB。一台手机下载大文件时，经同一控制连接的其他手机连接 MUST 继续得到响应。

#### Scenario: 下载期间审批

- **WHEN** 一台手机正在经中转下载大文件，另一台手机发起审批
- **THEN** 审批请求及时得到处理

### Requirement: 界面不可被其他来源嵌入

所有入口返回的 HTML 页面 SHALL 带 `Content-Security-Policy: frame-ancestors 'self'`，使页面只能被同源页面嵌入。

#### Scenario: 兄弟子域嵌入界面

- **WHEN** 同一中转域名下另一台电脑的页面用 iframe 嵌入这台电脑的 Web
- **THEN** 浏览器拒绝显示，用户的登录状态不能被借用来诱导点击

### Requirement: 地址名与邀请码

官方中转尚未分配地址时，连接设备页 SHALL 在启用按钮前提供地址名（可选）与邀请码。地址名只接受 4–20 位小写字母和数字，留空由中转分配；启用时保存两项并在注册时提交。取得地址后 MUST 隐藏输入框，同一身份沿用原地址、不能改名。自建中转 MUST 不显示或提交邀请码；关闭时 SHALL 依次提供中转域名和可选的设备名称，并预览手机访问地址；设备名称在启用时保存、注册时提交，由自建中转绑定到电脑身份，留空使用电脑 ID。中英文说明 SHALL 区分官方与自建，自建显示当前控制地址且不得称为官方；隐私文案 SHALL 限定为正常转发时不解密内容，不承诺中转方绝对无法读取。

#### Scenario: 填写名字和邀请码启用

- **WHEN** 用户在官方中转填写地址名 `alice` 和有效邀请码后点击启用
- **THEN** 注册成功后连接设备页显示 `https://alice.<域名>`，输入框不再出现

#### Scenario: 名字留空

- **WHEN** 用户在官方中转只填写邀请码就点击启用
- **THEN** 中转分配地址名，页面显示分配到的地址

#### Scenario: 关闭后再启用

- **WHEN** 已取得地址的用户关闭中转后再次选择同一个 codexhost 中转
- **THEN** 页面不显示输入框，启用后沿用原地址

#### Scenario: 自建中转展示

- **WHEN** 展开中转域名为 `example.com` 的自建卡片
- **THEN** 中英文界面显示自建中转、中转服务器地址 `relay.example.com`、设备名称输入框和手机访问地址预览，不出现官方说明或邀请码输入框，注册不携带邀请码；开启后展示当前使用标识、状态与扫码入口

### Requirement: 注册被拒的处理

中转拒绝注册时，Web SHALL 按原因处理：名字已被占用、邀请码无效、已被停用时 MUST 停止重连并关闭中转，连接设备页在输入框上方显示原因，用户修改后可再次启用；容量已满时 MUST 按重连规则自动重试，页面显示中转已满、正在重试。

#### Scenario: 名字已被占用

- **WHEN** 用户填写的地址名已被其他电脑使用
- **THEN** 中转关闭，页面提示"这个名字已被占用，请换一个"，用户换名字后可以再次启用

#### Scenario: 邀请码无效

- **WHEN** 邀请码不存在或已被其他电脑使用
- **THEN** 中转关闭，页面提示邀请码无效或已被使用

#### Scenario: 容量已满

- **WHEN** 中转因容量已满拒绝注册
- **THEN** 中转保持开启并自动重试，页面显示中转已满、正在重试

### Requirement: 额度用完提示

中转通知当日额度用完时，连接设备页 SHALL 显示今日流量已用完以及恢复时间（下一个 UTC 日），在额度恢复前保持该提示。电脑上的任务和其他连接方式 MUST 不受影响。

#### Scenario: 额度用完

- **WHEN** 中转通知这台电脑的当日额度已用完
- **THEN** 连接设备页显示今日流量已用完和恢复时间，局域网和 Tailscale 访问照常可用

### Requirement: 自建中转教程

自建卡片 SHALL 展示简短中英文教程及公开仓库默认分支的完整自建文档链接，教程未配置时 SHALL 展开，有控制地址后 SHALL 收起为可展开的“如何搭建自己的中转”，排在访问地址之后。内容与文档一致：先准备自己的域名及装有 Docker Compose 和 certbot 的 Linux 服务器，再用一行 git clone 命令获取公开仓库源码，然后配置控制与电脑通配两条 DNS、Cloudflare 仅 DNS、服务器放行 443 与申请控制证书所需 80、先申请控制证书再按仓库 Dockerfile 构建与 Compose 启动、回页面填写地址。没有域名时 SHALL 建议官方中转或 Tailscale。

#### Scenario: 尚未配置自建中转

- **WHEN** 用户展开未配置的自建卡片
- **THEN** 页面同时显示主机名输入框与展开的简短部署教程，不要求命令行配置电脑端，不显示名字和邀请码

#### Scenario: 已配置自建中转

- **WHEN** 用户展开有控制地址的自建卡片
- **THEN** 教程默认折叠为一行，可手动展开；已开启时访问地址和复制链接在状态与开关之后、教程之前
