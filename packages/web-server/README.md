# Web Server

A separate Node server for the responsive DSH-derived UI. By default it starts or connects to one independent local CodexHost service: canonical Threads, history and mutations remain owned by CH, whether or not Desktop is open. It neither starts/stops Desktop nor opens a second Adapter or Mapping Store. Rendering journals are in memory; existing Web workspace records group CH Threads by their actual GUI project membership, not execution cwd alone. Unselected/generated directories stay out of the project list; assigned worktrees share their parent project while retaining their real cwd. Native project metadata is read-only, with no mkdir or GUI project creation. `--session-source standalone` explicitly selects the previous independent plugin Host.

Build from the repository root with `npm run build:web`. The default plugin input is the same checkout's `packages/host-runtime/dist/plugins`, built by the existing CH release plugin builder; the installed CodexHost.app is not consulted. Usage-only plugins are excluded from conversations. The standalone Codex Adapter lives in `packages/adapters/codex`; no Harness implementation is duplicated here.

`npm run start:web` uses the isolated, authenticated preview. Either Web or Desktop can start/connect to the same background owner; closing either UI does not stop the other or its running tasks. The native Launcher owns detachment, concurrent-start admission and old-process-tree cleanup, while the service owns the sole writable store and Harness registry. The current-platform packed distribution includes this Launcher and the same Host bundle, not Node or Harness CLIs. Updated local Hosts provide an authenticated event channel in `~/.codexhost/client-hosts`; use `-- --ch-data <host-data>` for another owner data directory, separate from Web's `--data`. Optional paths are `--ch-launcher`, `--ch-host-runtime`, `--ch-plugins` and `--ch-codex-home`. Projects come from read-only native persisted metadata without Desktop; pin writes still require Desktop's native service. An old Desktop-owned endpoint may be used but is never taken over or killed: transition requires a user-arranged Desktop update/restart. Supplying only `-- --ch-cdp http://127.0.0.1:<port>` explicitly selects the legacy path; combine it with a control directory for events and GUI-dependent pin access. Building Web does not replace a running Host. Neither disconnect nor recovery falls back to standalone or resends uncertain mutations. For the independent plugin mode, use `-- --session-source standalone`, with Claude Code enabled by default. Add `-- --harness all` to enable every bundled session plugin except Codex/Pi, or `-- --harness <id,...>` to select specific plugins. Codex/Pi, missing plugins and usage-only plugins are rejected before starting; selection does not install/authenticate CLIs or imply full capability verification. The packed entry is `dist/codexhost-web/preview.mjs`; it strips inherited Desktop routing and Node injection variables, preserves CLI credentials/PATH, and stores preview data separately. `server.mjs` is the configurable full entry and must not be launched with inherited Desktop routing state.

The root `test:shared-host` script tests real Launcher/Node lifecycle with isolated homes and fake native protocols. Node test-runner suites are owned by this package's `test`, `test:distribution` and `test:browser` scripts; the root TypeScript test command invokes the unit suites separately from Vitest. The browser and distribution suites require built frontend artifacts. They use temporary data, fake Harnesses and a fake CH/CDP peer, never real model submissions. The generic authenticated App gateway is `/api/ch/v1/{events,rpc,snapshot,respond}`. It uses the same Host owner and never exposes its private discovery token. See [the client protocol](../../docs/architecture/host-client-channel.md) for invalidation/snapshot recovery, arbitration and bounded receipts. Event-mode Web shares approvals/questions; legacy CDP mode still handles them in GUI. Project metadata retains periodic checks; generic file preview/download, shared Web Steering and complete background/subagent projections remain limited.

Local shared mode accepts PNG/JPEG/WebP/GIF clipboard, picker and drop images. Sending saves exact uploaded bytes under `<data>/attachments/images` and passes native Desktop-style attachment path context to the Host; it does not change the Harness input protocol or Codex configuration. Authenticated previews are reconstructed from the native Thread's own path references, including Desktop clipboard/original images and structured local/inline image input. Presentation separates the user's request from execution context and shows ordinary native files as read-only reference cards. Image reads require both the current Thread's loaded canonical input and its display reference; guessed IDs or browser-supplied paths cannot authorize reads. Native bytes stay at their original paths, HTTP/remote image URLs are not fetched, and unavailable images remain placeholders beside the user's request. Limits: 20 MiB/image, 20 images/32 MiB per message, 8192 pixels per side, 64 million pixels; HTTP RPC bodies are capped at 48 MiB. Files are retained after ambiguous submissions and across restarts. The Harness must be able to read the same local filesystem; remote/WSL path translation and standalone attachments are not enabled. `image-size` performs header checks and its MIT notice is included in packaged licenses.

Local shared mode also streams arbitrary file types through the existing background upload UI and authenticated `/api/session/uploadFileBinary` route. Exact bytes are saved under `<data>/attachments/files/<sha256>/<safe filename>` and only Session-scoped opaque receipts are accepted by prompts; selecting files never allocates a native Thread. Limits are 64 MiB/file, 20 files/128 MiB per message, separate from image limits. Pending receipts expire after one hour or a Web restart; accepted receipts retire, while refused/ambiguous sends retain their bytes. Native history restores file cards without a second Thread index. No auto-execution, archive extraction, universal preview or file download endpoint is added.

The initial Web implementation is imported from the MIT-licensed `codexhost-web` fork; its upstream license is retained in `LICENSE.upstream`. Current behavior, limitations and ownership are documented in [standalone-web.md](../../docs/product/standalone-web.md).
