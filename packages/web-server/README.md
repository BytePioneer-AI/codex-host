# Web Server

A separate Node server for the responsive DSH-derived UI. By default it starts or connects to one independent local CodexHost service: canonical Threads, history and mutations remain owned by CH, whether or not Desktop is open. It neither starts/stops Desktop nor opens a second external Adapter or Mapping Store. External rendering buffers are in memory; existing Web workspace records group CH Threads by their actual GUI project membership, not execution cwd alone. Unselected/generated directories stay out of the project list; assigned worktrees share their parent project while retaining their real cwd. Native project metadata is read-only, with no mkdir or GUI project creation.

Build from the repository root with `npm run build:web`. The default plugin input is the same checkout's `packages/host-runtime/dist/plugins`, built by the existing CH release plugin builder; the installed CodexHost.app is not consulted. Usage-only plugins are excluded from conversations. Official Codex uses the shared Host's native app-server and Thread IDs, not a Harness plugin; external Harness implementations remain in their Adapter packages.

`npm start web` runs `build:web`, stops the matching Web development process in this checkout on the selected port, restarts the shared Host, then starts the environment-isolated, authenticated preview. It does not close Desktop, but restarting Host interrupts its running tasks. A failed build prevents launch; use `npm start web -- --no-build` to reuse existing artifacts while still restarting Host and Web. `npm run start:web` uses the same build-and-start path and accepts `-- --no-build` too. It listens on `0.0.0.0:4400` by default for LAN/Tailscale access and prints token-free network URLs; authentication and same-origin checks remain enabled. Use `npm start web -- --host 127.0.0.1` for loopback-only access. Startup output is left-aligned and omits the data directory. Interactive builds update the actual phase, completed frontend-plugin count and elapsed time on one line, with a blank line before access URLs. Firewall/network reachability is still required; use a trusted network, Tailscale, or HTTPS rather than exposing plain HTTP to the public Internet. `npm start` without `web` still launches Desktop, and `npm run start:web` remains a compatible alias. Either Web or Desktop can start/connect to the same background owner; closing either UI does not stop the other or its running tasks. The native Launcher owns detachment, readiness and normal process-tree cleanup, while the service owns its writable store and Harness registry. Native ensure, stop and restart serialize lifecycle operations per Host data directory. Restart retains the operation lock through shutdown and readiness, so reconnecting clients reuse the requested replacement. Older clients without this lock must be updated or closed first. The current-platform packed distribution includes this Launcher and the same Host bundle, not Node or Harness CLIs. Runtime bundles use the standard `app/` layout (`app/server.mjs` and `app/host-runtime.mjs`), so the packaged native CLI resolves the same Host runtime without a Web-specific fallback. Updated local Hosts provide an authenticated event channel in `~/.codexhost/client-hosts`; use `-- --ch-data <host-data>` for another owner data directory, separate from Web's `--data`. Optional paths are `--ch-launcher`, `--ch-host-runtime`, `--ch-plugins` and `--ch-codex-home`. Projects come from read-only native persisted metadata without Desktop; pin writes still require Desktop's native service. An old Desktop-owned endpoint may be used but is never taken over or killed: transition requires a user-arranged Desktop update/restart. Supplying only `-- --ch-cdp http://127.0.0.1:<port>` explicitly selects the legacy path; combine it with a control directory for events and GUI-dependent pin access. Building Web does not replace a running Host. Packed Web snapshots its bundled Host, native Launcher and plugin files under `<ch-data>/host-builds/<content-hash>/` before connecting; running Hosts and reconnects use those retained files independently of repackaging. Explicit external path overrides remain caller-managed. Snapshots are deduplicated and not automatically deleted; clean unused builds only after stopping their Web clients and Host. Host processes use the Host data directory as cwd. Both `npm start` and `npm start web` restart the backend before starting their respective interface; no separate Host development command is needed. Development restart requires a local shared Host; use the direct preview entry for legacy CDP connections. Neither disconnect nor recovery opens a local executor or resends uncertain mutations. `npm start web` enables every bundled session Harness, including official Codex and Pi, by default; only `-- --port <port>` is needed to change the listener. Advanced `--harness <id,...>` optionally selects official Codex and/or a subset of bundled Harness plugins, while `--adapters` and `--ch-plugins` select the plugin directory. Official Codex prefers Desktop's bundled program, then a local `codex` version 0.161.0 or newer; an unavailable program hides its selector entry without blocking Web startup or other Harnesses. Selection does not install/authenticate CLIs or change Adapter, model catalog or session behavior. Explicitly selecting missing or usage-only plugins remains an error. The packed entry is `dist/codexhost-web/preview.mjs`; it strips inherited Desktop routing and Node injection variables, preserves CLI credentials/PATH, and stores preview data separately. `app/server.mjs` is the configurable full entry and must not be launched with inherited Desktop routing state.

Web-owned data defaults to `~/.codexhost/web/` for both the direct server and preview. Custom `--ch-data <root>` defaults Web storage to `<root>/web`; explicit `--data` remains independent. This consolidates configuration, authentication, Push state and attachments without changing the Host's sole session ownership or moving user projects/native Harness homes. Startup does not inspect or migrate old profiles, read root-migration markers, or resolve attachment compatibility links. Existing directories stay untouched; owned images still require content-hash validation, and arbitrary symlink reads remain prohibited. See the [data directory constraints](../../docs/product/standalone-web.md#web-数据目录).

Access is token-based. `npm start web` listens on `0.0.0.0` by default; other devices sign in with the access token, whose QR code and sign-in link are shown in Web settings on this computer. See [Access authentication](../../docs/product/standalone-web.md#访问认证).

Remote access accepts `--public-url` or `CODEXHOST_WEB_PUBLIC_URL` (CLI wins), including through `npm start web` and `preview.mjs`. Only HTTP(S) site roots without user information, paths, queries or fragments are accepted. This is the preferred link/QR address, not a trusted proxy or origin allowlist. Startup retains its first local-link line, then reads Tailscale with a three-second deadline and prints public, Funnel and Serve URLs before interface addresses. Funnel is explicitly marked public; HTTP URLs warn about unencrypted content.

The connection page diagnoses Tailscale through `tailscale status --json` and `tailscale serve status --json` only. It offers a copyable Serve command when the HTTPS 443 root is free, but never executes it or replaces existing forwarding. A detected root pointing to this Web makes loopback forwarding headers trusted; startup, page reads and a 30-second Serve check refresh this trust. No detection runs with `--no-auth` or a specific non-loopback listener. Serve configuration remains after Web exits, and another program on that port would be forwarded. Other proxies require explicit `--trusted-proxy`; preserve Host or supply trusted forwarding headers, enable WebSockets and disable event-stream buffering. Two failed five-second authentication-probe windows show “computer offline”; HTTP 200 or carrier recovery clears it without losing drafts. See [remote access](../../docs/product/web-remote-access.md) for Serve, Funnel, nginx, frp and Cloudflare Tunnel examples, TLS ownership and unexecuted real-device checks.

The root `test:shared-host` script tests real Launcher/Node lifecycle with isolated homes and fake native protocols. Node test-runner suites are owned by this package's `test`, `test:distribution` and `test:browser` scripts; the root TypeScript test command invokes the unit suites separately from Vitest. The backend suite includes real HTTP entry-point tests; its `pretest` builds frontend artifacts so a clean checkout has the same startup prerequisites as the real server. Browser and distribution suites also require built frontend artifacts. They use temporary data, fake Harnesses and a fake CH/CDP peer, never real model submissions. The generic authenticated App gateway is `/api/ch/v1/{events,rpc,snapshot,respond}`. It uses the same Host owner and never exposes its private discovery token. See [the client protocol](../../docs/architecture/host-client-channel.md) for invalidation/snapshot recovery, arbitration and bounded receipts. Event-mode Web shares approvals/questions; legacy CDP mode still handles them in GUI. Project metadata retains periodic checks; generic file preview/download, shared Web Steering and complete background/subagent projections remain limited.

Local shared mode accepts PNG/JPEG/WebP/GIF clipboard, picker and drop images. Sending saves exact uploaded bytes under `<data>/attachments/images` and passes native Desktop-style attachment path context to the Host; it does not change the Harness input protocol or Codex configuration. Authenticated previews are reconstructed from the native Thread's own path references, including Desktop clipboard/original images and structured local/inline image input. Presentation separates the user's request from execution context and shows ordinary native files as read-only reference cards. Image reads require both the current Thread's loaded canonical input and its display reference; guessed IDs or browser-supplied paths cannot authorize reads. Native bytes stay at their original paths, HTTP/remote image URLs are not fetched, and unavailable images remain placeholders beside the user's request. Limits: 20 MiB/image, 20 images/32 MiB per message, 8192 pixels per side, 64 million pixels; HTTP RPC bodies are capped at 48 MiB. Files are retained after ambiguous submissions and across restarts. The Harness must be able to read the same local filesystem; remote/WSL path translation is not enabled. `image-size` performs header checks and its MIT notice is included in packaged licenses.

Local shared mode also streams arbitrary file types through the existing background upload UI and authenticated `/api/session/uploadFileBinary` route. Exact bytes are saved under `<data>/attachments/files/<sha256>/<safe filename>` and only Session-scoped opaque receipts are accepted by prompts; selecting files never allocates a native Thread. Local ordinary files have no application-level size, count, total-byte or pending-receipt count quotas. Browser Blob/Uint8Array/stream carriers all use raw-byte intake rather than bounded JSON RPC; storage remains streamed. System/filesystem/network constraints still apply, and image limits remain separate. Pending receipts expire after one hour or a Web restart; accepted receipts retire, while refused/ambiguous sends retain their bytes. Native history restores file cards without a second Thread index. No auto-execution, archive extraction, universal preview or file download endpoint is added.

The initial Web implementation is imported from the MIT-licensed `codexhost-web` fork; its upstream license is retained in `LICENSE.upstream`. Current behavior, limitations and ownership are documented in [standalone-web.md](../../docs/product/standalone-web.md).

The interface extension installer reuses the fork's `packages/boot/plugin-manager/src/install-spec.ts` parser at commit `a28f8758b4579787e8511a2a45401e2c29ba2199`, retained as `src/dsh-install-spec.ts` with its MIT notice. Web policy accepts prebuilt Web packages from npm, public GitHub archives and absolute local directories/archives, keeps an isolated installed copy, and disables package scripts. It does not import the upstream plugin-manager Host. See [Web interface extensions](../../docs/product/web-ui-extensions.md) for supported sources, registry selection and recovery.

Enabled Web extensions execute their original Host entries through the embedded DSH Cordis Loader/Include and contribute browser modules through native ClientModules. The embedded `webServer` registers exact/prefix routes, upgrades and index injections behind this server's existing listener and authentication. Writes and upgrades retain same-origin checks. Core `/api`, `/plugins`, `/assets`, Harness icons, shell files and recovery routes cannot be replaced; duplicate registrations fail rather than override. Plugins are trusted same-process code, not sandboxed. Missing services fail activation without disposing the core file/terminal backend; no DSH Agent Runtime is started. `--safe-mode` skips user Host and client execution. `/extensions` and `?extensions=off` suppress user browser code and index injections only, not the shared running Host entries. Enable/disable/remove applies on restart; removed installation files survive until the running plugin is disposed.

Packing emits shared Web framework modules into distribution `node_modules/` and redirects installed plugins' framework imports to those same instances. Keep that directory with `app/` and `web/` when relocating the package. Node must satisfy the repository's supported engines (22.19+ in the 22.x line, or 24.x); another DSH installation is neither used nor required. The separate shared Host's Cordis version is unchanged.

Official Codex Threads appear directly from the active `CODEX_HOME` (default `~/.codex`), without import or Mapping Store records. Web and Desktop use the same official runtime and Thread IDs. Models, Thinking and permissions use official catalogs and confirmed settings; queues, `/compact`, `/review`, Skills, pins and usage follow the official path. A writer conflict permits read-only history and returns the official error on send; the Host does not bypass locks or automatically Fork. Web does not offer official Fork or rollback. Other Harnesses retain generic session import.

Web may stop while the owner continues; Push requires the gateway. No profile/home ownership lock is used. There are no standalone migration, rollback or handoff entry points. Old `<ch-data>/web-codex/` data is not read, migrated or deleted. A draft without a selected workspace uses the Host projectless allocator on first submission; generated directories are not registered as projects. File/image uploads, receipt validation and native path-context input use the shared gateway flow.
